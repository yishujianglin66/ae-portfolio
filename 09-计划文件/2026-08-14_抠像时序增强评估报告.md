## 5. 结论与下一步建议（基于真实结果）

1. **L2 时序稳定（方案 4A 光流 warp）仍是正确且优先级最高的方向**：基线病根是 SAM2 传播崩塌 + 帧间边缘抖动（J500=26@500帧、FR 随段长恶化），不是缺新分割模型。`scripts/stabilize_temporal.py`（M2-A1）已存在，应尽快并入 `infer_segment_video_enhanced.py` 跑通 A/B（`_dbg7_ab_run.py` 框架现成），直接对治 J500。
2. **基线口径必须先修正**：把方案 §6 表格的 8.5%/19 更新为 500 帧实测 0.252/26，并注明段长依赖，否则 M1-C（FR<2%）与 M2-A3（J500<8）的验收无法公平判定（500 帧口径下差距更大，也更能体现 L2 价值）。
3. **rvm 值得作为 L2 增强的候选接入**（真实依据：pip 不可装但源码 clone + CUDA 前向通过）：
   - 方式：vendoring 到 `external/rvm`（与 RIFE warplayer 同模式），下载 `rvm_mobilenetv3.pth` 权重（本次未下载）
   - 定位：RVM 是**自带时序一致**的 matting，对"人物边缘抖动"直接对症，可作为 warp 融合之外的第二候选，A/B 对比 J500
4. **cutie 不优先**（真实依据：MSVC 编译器缺失导致 pip 安装失败、依赖链重含 GUI）；若仍要试，只 vendoring `cutie/model` 核心，并需先装 MSVC C++ Build Tools
5. **短期路线**：M1 路由（log 已显示 55 次模式切换可行）→ benchmark_qc_matting A/B → M2-A warp 融合 → J500 仍高再评估 rvm。
