## 0. 总体实验设计（全局适用）

### 0.1 核心假设（Hypotheses）

| 编号 | 假设 | 验证方式 |
|------|------|---------|
| H1 | 参考视频的风格可被量化为一份 JSON 规格书（切点分布/转场频次/速度曲线/色调），且该规格书能驱动现有编排层复刻出特征距离更近的成片 | 方向A实验 |
| H2 | 变速 + xfade 真转场可在纯 ffmpeg 链路实现，使成片"踩拍误差"和"观感评分"显著优于硬切基线 | 方向B实验 |
| H3 | 木偶风格化存在一条"纯开源最小路径"（SAM2抠像 + 降帧 + 色调量化），无需商业软件即可产出可辨识的木偶感 | 方向C实验 |

### 0.2 基准评测集（Benchmark，先建后测）

所有方向共用一套评测集，避免"感觉变好了"式的主观结论：

| 组成 | 内容 | 来源 | 成本 |
|------|------|------|------|
| 参考视频集 R | 10 条外网风格样本（漫剪×4、静止系×3、木偶×3），每条 30-60s | B站/YouTube 手动下载（yt-dlp 已装） | ¥0 |
| 素材集 M | 现有 D:\AE-Work\resources\video（4.96GB，9个IP） | 已有 | ¥0 |
| BGM 集 | 现有 D:\AE-Work\resources 音频 | 已有 | ¥0 |
| 人工评分组 | 自己 + 1 位朋友双盲打分（1-5 分制） | — | ¥0 |

### 0.3 量化指标体系（所有实验统一）

| 指标 | 定义 | 计算方式 | 基线值(T39) |
|------|------|---------|------------|
| **踩拍误差** CBE | 每个切点到最近节拍点的时间差中位数 | `median(|cut_t - nearest_beat_t|)` | 待测 |
| **风格特征距离** SFD | 成片 vs 参考片的 24 维风格特征余弦距离 | `1 - cos(f_out, f_ref)`，复用 `core.style_feature_extractor` | 待测 |
| **转场多样性** TD | 成片中实际生效的非硬切转场数 | ffprobe + 剧本审计 | 0 |
| **人工观感分** HMS | 双盲 A/B 打分均值 | (新片分 - 旧片分) | 基线=旧片 |
| **成本消耗** COST | llm_gateway 内置 token 追踪读数 | `llm_gateway` 成本监控 | — |

> 注：`style_pipeline.py` 已提供 `analyze_video_style()`，可直接对"成片"和"参考片"各跑一次得到 24 维特征，SFD 指标零额外开发成本。

### 0.4 全局成本控制原则

1. 一切能在本地 ffmpeg/GPU（RTX 4060 Laptop）完成的，不上云
2. 一切需要 GPU 训练的，优先 Kaggle 免费额度（每周 30h T4/P100），其次 AutoDL 按量（4090 ≈ ¥2.1/h）
3. VLM 调用全部走 `core/llm_gateway.py`（内置降级与 token 追踪），单次实验预算上限 ¥30，超限自动中止

## 方向 A：风格识别 → 剧本生成闭环

### A.1 目标定义

把"风格"从**标签**升级为**可执行规格书**：输入一条参考视频，输出 `StyleSpec JSON`，编排层消费该规格书生成剧本，使成片的 SFD 特征距离比硬编码预设基线下降 ≥40%。

**明确不做什么**：不做风格迁移（逐像素重绘），只做"剪辑语法复刻"（切点/转场/速度/色调/文字规律）。这是成本与效果的最优平衡点。

### A.2 现状分析（基于真实代码）

| 组件 | 文件 | 现状 |
|------|------|------|
| 风格特征提取 | `core/style_feature_extractor.py` → 24维 | ✅ 可用 |
| 风格分类器 | `models/output/style-classifier/model.json`（23类） | ✅ 可用，但只出标签 |
| VRS 视频分析 | `vrs/video_effect_analyzer_v2.py` | ⚠️ 可用但有 mock 降级（已 fail-closed） |
| 标签→参数映射 | `core/style_preset_adapter.py::style_to_atomic_params` | ❌ 硬编码查表，非参考片反推 |
| 编排层 | `production_director.py::_plan()` | ⚠️ 只消费情绪曲线，不消费风格规格 |
| LLM 网关 | `core/llm_gateway.py::chat_with_routing` | ✅ 有 EFFECT_PLANNING/STYLE_TRANSFER 任务类型、成本追踪、自动降级 |

**断链点**（上轮评估结论）：`classify_style()` 输出标签 → 查硬编码表 → 与参考片实际风格无关。

### A.3 技术路线

```
参考视频
  ├─ ffmpeg scdet → 切点时间序列 → 切点间隔分布/均值/方差
  ├─ librosa(参考片音轨) → 参考片节拍 → 切点-节拍对齐率
  ├─ 抽帧(每镜头首尾帧) → VLM 批量分析(llm_gateway) → 转场类型标注 + 速度感知
  ├─ VRS color_grading → 色调统计(亮度/饱和/对比)
  └─ 汇总 → StyleSpec JSON
              ↓
production_director._plan(spec=StyleSpec) → 剧本 → 渲染
```

**Why 选这条路**：
- vs 端到端风格迁移模型（如视频 diffusion）：成本数百倍（需 A100 级 GPU），且输出不可控、无法驱动现有剧本层 → 否决
- vs 纯 VLM 一次性描述风格：不可量化、无法精确到切点时间戳 → 否决
- 选"信号处理量化 + VLM 只补语义缺口"：切点/节拍/色调全部本地免费算，VLM 只负责"转场类型判断"这类必须语义理解的部分，成本最低

### A.4 实施步骤（代码级）

**Step A-1：新建 `core/style_spec_extractor.py`**（约 300 行，2-3 天）

```python
@dataclass
class StyleSpec:
    cut_times: List[float]          # 参考片切点
    cut_interval_stats: Dict        # {mean, std, min, max}
    beat_sync_ratio: float          # 切点落在节拍±80ms内的比例
    transition_dist: Dict[str, int] # {cut: 12, flash: 5, zoom: 3}
    speed_segments: List[Dict]      # [{start, end, speed}]
    color_profile: Dict             # {brightness, saturation, contrast}
    avg_shot_duration: float
    source_video: str
```

核心函数：
- `extract_spec(video_path) -> StyleSpec`
- 切点检测：`ffmpeg -vf "scdet=threshold=10" -f null -` 解析 stderr 时间戳（本地，¥0；备选 PySceneDetect `pip install scenedetect`）
- 节拍：复用 `ae.beat_detector.BeatDetector`（参考片若有人声音轨则先 `ffmpeg -af vocalremover` 简化处理，失败则直接用原音轨）
- 转场标注：每对相邻镜头取尾帧+首帧，批量调 `chat_with_routing(task_type=TaskType.EFFECT_PLANNING)`，提示词要求只输出枚举 `{cut, fade, flash, zoom, glitch, wipe}`；10 条参考片 ≈ 80-150 次调用 ≈ **¥5-15**
- 速度感知：对镜头内做光流幅度估计（OpenCV `cv2.calcOpticalFlowFarneback`，已有依赖）幅度异常大→慢放嫌疑，VLM 复核

**Step A-2：扩展剧本数据结构**（`ai/production_director.py`，半天）

`DirectorSegment` 增加字段：
```python
speed: float = 1.0                    # 段落播放速度
transition_params: Optional[Dict] = None  # {type, duration}
```

**Step A-3：`_plan()` 接受 spec 参数**（1 天）

- 新签名 `_plan(..., style_spec: Optional[StyleSpec] = None)`
- 有 spec 时：段落时长采样自 `spec.cut_interval_stats` 分布（`random.gauss(mean, std)` 截断），转场类型按 `spec.transition_dist` 加权抽样，色调用 `spec.color_profile` 替代 `COLOR_PRESETS` 硬编码
- 无 spec 时：行为完全不变（**对照组即现状**，保证可回退）

**Step A-4：实验与度量**（2-3 天）

| 组 | 配置 | 样本 |
|----|------|------|
| 控制组 C | 现有管线（无 spec，硬编码预设） | 同素材×同BGM ×5 条 |
| 实验组 E | 管线 + StyleSpec（取自对应风格参考片） | 同上 ×5 条 |
| 阳性对照 P | 参考片本身 | SFD=0 基准 |

测量：SFD（E 组目标 ≤ 0.6 × C 组）、HMS 双盲打分、COST 读数。

### A.5 成本估算

| 项 | 金额 |
|----|------|
| VLM 转场标注（150 次调用上限） | ¥15 |
| scenedetect pip 包 | ¥0 |
| 本地计算（ffmpeg/OpenCV/librosa） | ¥0 |
| 双盲评分 | ¥0 |
| **小计** | **≈¥15** |

### A.6 时间估算

8-10 个工作日（单人）。关键路径在 Step A-1 的 VLM 提示词调优。

### A.7 验收指标

| 指标 | 及格 | 优秀 |
|------|------|------|
| SFD 下降幅度（vs 控制组） | ≥25% | ≥40% |
| 踩拍误差 CBE | ≤120ms | ≤80ms |
| HMS 双盲胜出率 | ≥60% | ≥80% |
| 单参考片 spec 提取耗时 | ≤5min | ≤2min |
| 单参考片 API 成本 | ≤¥2 | ≤¥0.8 |

### A.8 风险与降级（What-if）

| 风险 | 概率 | 降级方案 |

| 规格书复刻后"形似神不似" | 高 | 预期之内——本方向只承诺剪辑语法复刻；"神似"（特效质感）由方向B/C 承担 |

## 方向 B：漫剪 / 静止系 AMV 能力补齐

### B.1 目标定义

在不引入任何新付费软件的前提下，把执行层从"硬切+eq调色"升级为"变速+真转场+静止图运镜"，使漫剪成片 TD（转场多样性）从 0 → ≥6 种，静止系 AMV 从不可做 → 可出片。

### B.2 现状分析

| 能力 | 现状 | 证据 |
|------|------|------|
| 变速 | ❌ 全原速 | `_extract_clip()` 无 setpts |
| 真转场 | ❌ transition 字段只是字符串标签 | `_execute()` 用 concat 硬拼 |
| 静止图运镜 | ❌ 无图片输入分支 | `_analyze()` 只接受视频 |
| ffmpeg 滤镜支持 | ✅ **已实测**：xfade / zoompan / tinterlace 全部存在（ffmpeg 8.1.1） | 本机 `-filters` 验证 |

### B.3 技术路线与 Why

**Why 纯 ffmpeg 而非 AE**：AE 链路（Bridge/JSX）历史上稳定性问题多（命令丢失/冻结），且渲染慢；xfade 内置 20+ 转场已覆盖外网漫剪 60-70% 的常用转场。AE 留给方向 C 的高阶效果。
**Why 不装新库**：zoompan/xfade/setpts 全在现有 ffmpeg 8.1.1 里，零依赖变更 = 零回归风险。

### B.4 实施步骤（代码级）

**Step B-1：变速支持**（1-2 天）

修改 `production_director.py::_extract_clip()`，在 vf 链中插入：
```python
if speed != 1.0:
    vf_speed = f"setpts={1.0/speed}*PTS"   # 注意在 -ss/-t 语义下同步调整 duration
# 慢放需补帧防卡顿：追加 minterpolate 或 直接 -r 保持（先不加插帧，控制成本）
```
剧本侧：drop/climax 段落 `speed=0.7`（慢放蓄力）→ 下一段 `speed=1.4`（加速释放），参数写进 `COLOR_PRESETS` 同级的 `SPEED_PRESETS` 常量表。
**陷阱预警**：`-t duration` 指素材原时长，变速后实际输出时长 = duration/speed，须换算后再裁。

**Step B-2：xfade 转场链**（2-3 天）

改造 `_execute()`：从"concat 硬拼"改为"xfade 链式合成"。
```
[a][b]xfade=transition=fadeblack:duration=0.25:offset={a时长-0.25}[ab];
[ab][c]xfade=transition=slideleft:...
```
转场映射表（剧本标签 → xfade 名，均已实测存在）：

| 剧本标签 | xfade | 场景 |
|---------|-------|------|
| fade | fadeblack/fadewhite | intro/outro |
| flash | fadewhite(dur=0.12) | drop 卡点 |
| zoom | smoothup + scale 前置 | 高潮进点 |
| slide | slideleft/slideright | 常规过渡 |
| glitch | pixelize 或 hblur 短闪 | 高能段 |

**实现约束**：xfade 链超过 ~10 段时滤镜图过大易崩，采用**分段合成再拼接**策略（每 8-10 段一个 xfade 链，链间硬切——这恰好符合"段落边界用硬切"的漫剪惯例）。

**Step B-3：静止系 AMV 分支**（3-4 天）

新增 `ai/still_amv_director.py`（复用 ProductionDirector 的感知层实例）：
- 输入：图片目录（可从现有视频 `ffmpeg fps=1` 批量抽帧获得，¥0）+ BGM
- 每张图 → `zoompan=z='min(zoom+0.0015,1.2)':d={beat_interval*fps}:s=1920x1080`（Ken Burns 缓推）
- 交替使用 push-in / pull-out / pan-left 三种运镜模板（zoompan 参数表）
- 卡点闪白：相邻图间 `xfade=fadewhite:duration=0.1`
- 微抖动：`crop` + `overlay` 随机 ±3px 偏移（模拟手持感）

**Step B-4：对照实验**（2 天）

| 组 | 配置 |
|----|------|
| B0 | 现有管线（硬切、原速） |
| B1 | +变速 |
| B2 | +变速 +xfade |
| B3 | 静止系分支成片 |

指标：CBE、TD、HMS。消融分析得出变速与转场各自贡献。

### B.5 成本估算

**¥0**（全部本地 ffmpeg）。唯一隐性成本是调试时间。

### B.6 时间估算

7-9 个工作日。B-1 与 B-2 可并行设计。

### B.7 验收指标

| 指标 | 及格 | 优秀 |
|------|------|------|
| TD 转场多样性 | ≥4 种生效 | ≥6 种生效 |
| CBE 踩拍误差 | ≤100ms | ≤60ms |
| HMS：B2 vs B0 双盲胜出率 | ≥70% | ≥90% |
| 静止系出片成功率 | 10 张图出 30s 片不崩 | 50 张图出 2min 片不崩 |
| 渲染耗时回归 | ≤ 基线 ×1.5 | ≤ 基线 ×1.2 |

### B.8 风险与降级

| 风险 | 概率 | 降级方案 |
|------|------|---------|
| xfade 滤镜链 OOM/崩溃（滤镜图过深） | 中 | 分段合成策略（已内置于设计）；再崩则回退 concat + 转场帧预烘焙（单独生成 0.25s 转场小片段再拼接） |
| 变速后音画不同步（素材原声） | 低 | 现有管线 `-an` 丢弃原声只用 BGM，天然规避 |
| zoompan 输出抖动/闪烁（d 参数陷阱，历史踩坑） | 高 | zoompan 的 d 必须 = 输出帧数整数且每图固定；先单图探测再批量（遵循已有的 ffmpeg 最佳实践记忆） |
| 慢放卡顿（无插帧） | 中 | 接受（0.7x 以内肉眼可接受）；若不可接受再上 `minterpolate`（渲染慢 3-5 倍，作为可选开关） |

## 方向 C：木偶风格化关键路径（最小可行实现）

### C.1 目标定义

用纯开源链路做出**可被普通人一眼认出"木偶感"**的 10-15s 样片：抠像换背景 + 定格动画降帧 + 材质化色调。不追求商业级关节化/3D 舞台（那是 12 个月蓝图的事）。

### C.2 现状分析

| 组件 | 现状 | 证据 |
|------|------|------|
| SAM2 抠像 | ✅ **真实可运行** | `puppet-automation/src/engines/sam2/engine.py`：auto_mask / extract_foreground，独立 venv（D:\AE-Work\venv-sam2），昨晚实际在跑推理 |
| 定格降帧 | ✅ ffmpeg tinterlace/fps 实测存在 | ffmpeg 8.1.1 |
| 材质色调化 | ⚠️ 可用基础滤镜近似 | posterize/curves/eq |
| 关节化/提线 | ❌ 无 | 属于 AE 高阶，本期不做 |
| 3D 舞台 | ❌ Blender 适配器是骨架 | 本期不做 |
| 商业文档蓝图 | 仅是规划 | 《落地总计划》12 个月方案，不纳入本期 |

### C.3 技术路线（三级递进，每级独立可交付）

```
L1 定格感滤镜（纯ffmpeg, ¥0, 2天）
   原片 → fps=8（降帧）→ 每帧随机±2px微位移 → posterize=5（色阶量化）
        → 暖色调curves + 暗角vignette → "廉价木偶感"
        ↓ 若 L1 观感达标，继续
L2 抠像换舞台（SAM2, ¥0, 4-6天）
   原片 → SAM2Engine.extract_foreground → 前景透明视频
        → 叠加木纹背景（Stable Diffusion 生成或现成素材）
        → L1 滤镜链 → "舞台上的木偶"
        ↓ 若需要更强关节感
L3 AE 关节接缝（可选, ¥0但时间贵, 1-2周）
   前景 → AE 导入 → 预置关节线遮罩模板（手动建一次，参数化复用）
```

**Why L1 先行**：定格动画的"木偶感" 70% 来自**降帧+微抖动**而非抠像（实验假设 H3 的核心）。先花 2 天验证最便宜的假设，成立再投入抠像。
**Why 用现有 SAM2Engine 而非重写**：它已解决 venv 隔离、子进程调用、国内模型路径（D:\AE-Work\models\sam2）三个坑。

### C.4 实施步骤（代码级）

**Step C-1：L1 定格滤镜链**（2 天）
新建 `ai/puppet_mvp.py`：
```python
FILTER_CHAIN = (
    "fps=8,"                                  # 定格降帧
    "crop=iw-4:ih-4:2+random(1)*2:2+random(1)*2,pad=iw+4:ih+4,"  # 微抖动
    "posterize=5,"                            # 色阶量化(手工感)
    "curves=r='0/0.02 1/0.95':g='0/0.01 1/0.9':b='0/0 1/0.8',"    # 暖木调
    "vignette=PI/5"                           # 舞台暗角
)
```
> random() 表达式在 crop 里需逐帧种子，若 ffmpeg 表达式不支持稳定随机，降级为预生成 8 组固定偏移循环。
