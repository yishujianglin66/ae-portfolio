# 文字视觉观感编排设计与实证（2026-09-12）

> 触发：Boss 反馈「太乱了视觉上的观感，应该局部或者某些时间段应用；请分析并深度思考怎么设计编排视觉观感好，学习他人」。
> 方法：**先量化"他人"再定规则**（参照集实测）→ 定编排原则 → 实现 → **同帧 A/B 校验**。

## 一、学习他人：参照作品 vs 本片的节律实测

指标：逐秒帧间运动量（降采样灰度帧差）→ 归一化后判定"静段(<25%)/强段(>60%)"，并统计最长连续强段与峰均比。

| 作品 | 静段占比 | 强段占比 | 最长连续强段 | 峰/均比 |
|---|---|---|---|---|
| [AMV 4K] 5 Years by Donya | 31% | 17% | 2s | 2.50 |
| [AMV] exhausted by Donya | 48% | 21% | 2s | 3.04 |
| [一拳超人超燃AMV] JUST ONE PUNCH! | 38% | 19% | 2s | 2.91 |
| [前方高燃预警] 全员恶人 | 38% | 19% | 3s | 2.77 |
| [综漫AMV] 平凡的世界 | 41% | 16% | 3s | 2.81 |
| AKross2016 NanaMi 孤独者的荣光 | **78%** | 5% | 1s | 8.43 |
| AMV AGAINST FATE (AKROSS 2015) | **89%** | 3% | 1s | 5.95 |
| AMV FATE'S END (AKROSS 2015) | **70%** | 3% | 1s | 4.70 |
| **本片 v32e（编排前）** | **0%** | **100%** | **29s** | **1.15** |

**结论（数据化）**：一流作品的共同点是**大量留白 + 短促强峰**（静段 31-89%、强段仅 3-21%、
连续强段 ≤3s、峰均比 2.5-8.4）。本片则是**全程强、无收放、无峰**（峰均比 1.15）——
"乱"的本质不是某个效果丑，而是**没有对比**。

## 二、诊断：乱从何来

1. **效果密度过高**：12 个爆点每拍都挂冲击特效（约 1 次/秒），且叠加常驻发光/模糊/湍流。
2. **颗粒（v32）雪上加霜**：粗颗粒在画面上形成大块明暗斑（整帧均值可被抬高 60+），
   视觉上就是"脏"。
3. **缺少"平静段"**：intro/build/outro 与爆点用同一套强度，没有呼吸。

## 三、编排原则（本片采用）

| # | 原则 | 依据 |
|---|---|---|
| P1 | **留白优先**：特效只给一部分节拍（本次 6/22 = 27%），其余保持干净 | 参照静段 31-89% |
| P2 | **短峰**：单次特效作用 ≤0.6s（爆发后回落），不跨拍持续 | 参照连续强段 ≤3s |
| P3 | **对比而非堆叠**：同一拍最多一个主特效 | 参照峰均比高（说明峰与常态差距大） |
| P4 | **情绪映射**：颗粒/胶片感只属于"余韵/怀旧"段落；冲击特效只属于 drop 区 | 静止系 MAD 常识 + 本节实测 |
| P5 | **安静拍更干净**：没有主特效的拍子，把常驻效果（方向/径向模糊、湍流）再压轻 | 制造 P3 的对比 |

## 四、实现与证据

- **P1/P3**：`impact_recipe` 改为"隔拍"（drop 内 `i%2==0` 才给配方）→ 6 个特效事件 / 16 个安静事件；
  六种配方（抖动/射线/色散/回授/边缘射线/胶片闪）仍轮换且**同配方两次出现参数不同**。
- **P5**：安静拍的方向/径向模糊与湍流量统一 ×0.65。
- **P4（颗粒）**：**已停用**（默认关闭，`TEXT_OVERLAY_GRAIN=1` 可重开）。三条实证：
  ① 细颗粒（Freq 100）无损可见（局部 std ×1.86）但 **H.264@15Mbps 完全压掉**；
  ② 粗颗粒（Freq 12）形成大块明暗斑并把整帧提亮（4.5s 均值 57→127，采样点趋同≈恒定偏移）；
  ③ 关键帧化 Color Amplitude 在该版本未按预期生效（不做无依据补救）。
  → 结论：**在当前交付编码（H.264 15Mbps）下，颗粒收益为负**；若将来要颗粒，需先确认
  编码码率与颗粒尺度匹配（或改用无损/高码率母版）。
- **校验**：v34（编排版，无颗粒）与无颗粒基线 v31d **同帧均值完全一致**（Δ 0.0~−0.5）→
  编排没有引入亮度副作用。

## 五、后续可做（按性价比）

1. **build/intro 也做"轻变化"**：目前只有入场变款轮换；可让光晕颜色（青/金/白）随段落轮换，
   保持"有变化但不吵"。
2. **按音乐结构分段定强度**（而非按时长）：用 `production_report.json` 的段落/能量曲线驱动
   P1 的密度（副歌密、主歌疏），比固定"隔拍"更贴音乐。
3. **颗粒若要回归**：先提高母版码率或输出无损母版，再按"频率-编码"匹配实测。

## 六、方法沉淀（可复用）

- **判定"效果是否有效"必须同帧 A/B**：跨帧比较会被内容差异淹没（本次区域均值比较即失效）。
- **区分"效果没生效"与"被编码压掉"**：用无损输出模板（OM="无损"）做对照。
- **颗粒感用局部块 std（64×64 多块均值）**；但**粒度超过块尺寸时，局部 std 会低估"斑块感"**
  ——此时必须看同帧区域均值是否漂移。

## 附录：v35 音乐结构驱动强度（替代固定"隔拍"）

**动机**：固定"隔拍"只是机械均匀留白；更好的做法是**让留白跟着音乐呼吸**（副歌密、主歌疏）。

**实现**：
1. 用 `music_envelope`（31s / 1335 点 RMS）计算**局部强度** `local_i(t)`：取 t±0.4s 五点均值，
   再按 p10-p95 归一化到 0-1（消除整体响度差异）。
2. 阈值取 **drop 区事件 local_i 的中位数**（若取全体事件分位会被 intro/build 的安静值拉偏 ——
   实测特效只剩 1 个）。
3. **强度优先贪心**选取：按 local_i 降序，逐个选入并保证与已选事件间隔 ≥1.0s。
   （时间序"先到先得"会让最响的拍因间隔规则被漏掉 —— 实测安静拍里出现过 local_i 0.948）
4. 特效强度随音乐缩放：`ik = 0.75 + 0.6 × local_i`（0.75-1.35），作用于抖动幅度/射线亮度/
   色散强度/回授强度/胶片曝光等全部配方参数。

**实测（v35）**：
- 特效事件 **4/22（18%）**，全部为 drop 区最响的拍（local_i 0.601-0.748），间隔 1.85-4.62s；
- 18% 落在参照作品的强段区间（3-21%）内；
- 亮度同帧校验：除特效瞬间自身的局部提亮（+1.3 / +5.7）外，无整体偏移（Δ 0.0）。

**设计要点回顾**：留白不是"均匀地少"，而是**跟着音乐起伏**——安静段落给文字留出呼吸，
把视觉预算集中到音乐最响的时刻。

## 附录：v36-v38 —— 从"特效编排"转向"文字本身的收放"

### 诊断链（为什么会"感觉没啥变化"）

v34/v35 改了**结构**（隔拍 → 音乐驱动），但观感几乎没动。用逐帧"成片 vs 原始素材"差异
曲线查原因，得到一个反直觉结论：

- 差异曲线在各区**几乎平坦**（v34/v35/v36 均值 8.89 / 8.92 / 8.89），
- 而且**安静段（9.69）竟然强于 drop 段（8.00）**。

→ 说明：之前所有改动只动**短暂特效**（占全片时长极小），真正主导观感的是
**"文字本身从头到尾一直很重"**（大字号 + 厚描边 + 常驻光晕，22 个事件铺满 0-30s）。
特效只是瞬间，观感的"乱"来自**常态**。

> 方法教训：**先确认"你改的那一项是不是观感的主因"**，再动手。差异曲线的形状会直接告诉你
> 主因在哪；只看局部特效帧的 A/B 会一直在无头苍蝇式地微调。

### v37 时段处理分级（ZONE_TREAT）

按事件所属时段（intro/build/drop/outro）对**文字处理强度**做整体缩放：

| 时段 | glow | stroke 上限 | shadow | bevel | shimmer(通道分离) |
|---|---|---|---|---|---|
| intro | 0.0（关） | 2.5px | 0.5 | 0.4 | 否 |
| build | 0.45 | 5.5px | 0.8 | 0.7 | 否 |
| drop | 1.0 | 12px | 1.0 | 1.0 | 是 |
| outro | 0.6 | 4.5px | 0.9 | 0.8 | 否 |

同时：`glow<0.7` 时强制关掉第二层发光；非 drop 时段强制 `chroma=False`。

**实测（基线无关指标 = 事件位置 560×340 窗口内 luma≥232 像素占比 "ink"）**：
intro 明显变轻（0.0765 → 0.0113），但 **build 几乎没变（0.1239 → 0.1236）**。

→ 原因：build 段的视觉重量主要来自**白色字身本身**（字号），光晕/描边的加减在窗口里被字身淹没。
**要拉开时段差异，主杠杆是字号，不是光晕。**

### v38 分段字号倍率（主杠杆）

```
ZONE_TREAT[zone]["size"]:  intro 0.78 / build 0.70 / drop 1.10 / outro 0.95
size = max(60, round(size * 倍率))     # 仍受字号下限门禁 ≥60px 约束
```

**v37 → v38 同法实测**（同帧、同窗口、同事件）：

| 时段 | 代表词 | 字号 v37→v38 | ink v37→v38 |
|---|---|---|---|
| intro | 五条悟 | 108 → 84 | 0.0191 → 0.0097 |
| build | 無限 | 109 → 76 | 0.0736 → 0.0553 |
| drop | 最強 | 188 → 207 | 0.2351 → 0.2150 |
| outro | THE END | 114 → 108 | 0.2460 → 0.2276 |

- **drop/build 体量比 = 3.89×**（字号真值比 207/76 = **2.72×**）。
- 1:1 原尺寸目视：build "LIMIT"（76px/描边 5.5/无光晕）干净克制；
  drop "最強"（207px/描边 12/冷青双色光晕/通道分离）压倒性 → **收放成立**。

> ⚠ 指标口径提醒：`ink` 的窗口是固定的 560×340。当字形大到接近窗口尺寸时，
> **光晕外沿被裁到窗外**，ink 反而会下降 —— drop 段 −9% 就是这个窗口伪影，不是真的变轻。
> 跨字号比较时以**字号真值**为准，ink 只用于同字号下的明暗比较。

### 操作事故与修复（必须记住）

本轮一次注入漏了**注入前的基底重置**，`build: saved layers=60`（正常应为 32）——
即 v37 的 32 层与 v38 的 28 层叠在了一起，存出的 `.aep` 含重复文字层。

- **签名**：`ae_text_build.txt` 里 `saved layers` 显著大于历史值（v37=32 → 60 = 累加）。
- **标准流程（缺一不可）**：
  1. 注入 `base_reset.jsx`（关污染工程 → 打开纯净 `run53_premium_v3.aep`，回读 `layers=4`）；
  2. 跑 `build_text_overlay.py`（自带 send_bridge 注入，日志 `saved layers=32 texts=22`）；
  3. aerender 全片渲染；
  4. `tmp/verify_v38.py` 复核 + `tmp/rhythm_strip_v38.py` 出节奏带。
- **验收视图**：`render/v38_zone_compare.png`（分区 v37 vs v38 对照）、
  `render/v38_rhythm_strip.png`（每 ~2.6s 一帧的全片节奏带，一眼看到哪些时段重、哪些留白）。

### 本轮结论

"局部/某些时段应用"的落地形式不是"少给特效"，而是**让文字本身的体量按时段收放**：
intro 极小无光晕 → build 小字干净 → drop 巨字全特效 → outro 中等收尾，
事件之间保留空档（节奏带上可见 5.6s / 24.3s / 27.0s 的无字留白）。

## 附录：v39-v41 踩点收口（Boss："几乎能跟上音乐节奏踩点，继续推进"）

### 先把"几乎"量化：三个口径，别用自证式指标

| 口径 | 定义 | 为什么需要它 |
|---|---|---|
| A 入场对齐 | 事件 `t_in` 到最近 onset 的距离（帧） | **事件本来就锚在 onset 上**，此项必然接近 0 → 只能当体检，不能当成绩 |
| B 出场对齐 | `t_out` 到最近 onset 的距离 | 结束切点也是观感切点 |
| C **强拍覆盖** | 音乐最强 N 个 onset 中，有多少被文字踩到 | **分母是音乐而不是文字** —— 这才是"几乎"里的那个"几乎" |

**口径陷阱（必须先修）**：`true_onsets.json` 覆盖整首音乐（40s+），而正片只有 30s。
不裁剪会把**片外的拍**误报成"漏拍"（第一次跑出来 outro 漏 24 拍，全是 t>30s 的）。

修正后的真实诊断（最强 25 拍）：

- **入场对齐：25/25 全部 0.00 帧** —— 起点踩点本来就满分；
- 处置分布：`ENTER=12 / PULSE=9 / PULSE-=1 / GAP=3`；
- 失分点只有 4 个，且集中在两处：
  1. **drop 区 23.24→26.01 有 2.77s 无字空档**（其间 25.55 强度 0.81 = 全片第 14 强），
     16.78→18.62 另有 1.84s 空档（17.70 强度 0.71）；
  2. **保持期内的强拍 29.23（归一 0.76）无任何动作**（因为"取窗内最强 3 拍"，它排第 4）。

### v39 最大空档约束（补洞）

空档的成因**不是 cap 单一原因**，而是"强度贪心 + 0.60s 间距护栏"的交互：贪心先选了 A，
就必然剪掉 A±0.6s 内的强拍 B，但 B 可能是填洞的唯一人选。

→ 解法是按**时间轴覆盖率**单独再做一遍补位（`MAX_GAP`：drop 1.15s，其余时段不管，
因为 build 的长保持是"收"，有意为之）。**不能靠放松阈值** —— 放松阈值会让强拍邻居更早被剪，反而更糟。

- cap 12→15；事件 22→25（drop 12→15），补入 17.70 / 24.16 / 25.09；
- **drop 最大空档 2.77s → 0.94s**；时间线覆盖 81% → 88%；
- 保持期脉冲由"最强 3 拍"改为"强度达标即入选"（≥0.55，上限 5）：**脉冲总数 55→76**，
  29.23 等漏拍全部纳入。

### v40 踩拍发光闪（试做，收益有限，保留为次要手段）

给发光强度 `ADBE Glo2-0004` 加 1.22-1.72 倍闪光。实测**中位变化仅 +0.0001**：
亮背景下发光本来就看不见（与之前"有些字段发光看不出"是同一个物理限制）。
只有暗背景样本有效（#15 光晕 +0.021、#22 +0.021）。**保留**（暗背景仍有收益）但**不作为主手段**。

### v41 踩拍上跳（本次有效解）

**根因**：drop_impact 样式的 `scale` 由 **elastic 表达式**持有（`amp*sin/exp` 砸入），
`setValueAtTime` 对表达式属性无效，而脉冲代码有 `&& !ev.elastic` 守卫
→ **高潮段 13 个事件一个节拍脉冲都没有**。

实证（A1 铁律：读 AE 属性真值，不猜）——探针 `probe_pulse_state.jsx` 输出：
`TXT8`-`TXT22`（全部 drop 层）的 scale **无关键帧**，而 `TXT0`-`TXT7`/`TXT23`/`TXT24`
有 max=110.7-113.8 的脉冲键。这与"只有 build/outro 有脉冲"完全吻合。

**为什么改 position 而不是继续调发光**：亮/暗背景都要可见，只能靠**几何位移**；
而 elastic 只占用了 scale 表达式，**position 未被占用**，可安全打键。

实现：保持期内踩拍上跳 `14 + 22×强度` px，0.09s 回落（守卫：`t_in+0.40s` 之后、
`t_out−0.12s` 之前，避开入场动画与出场漂移键）。

**验证（最干净的 A/B）**：v40 与 v41 **事件表完全相同**，同一帧的素材画面完全一致
→ 差异只可能来自文字自身。测亮像素（≥250）垂直质心：

| 事件 | 拍点 | 设定 kick | Δv40 | Δv41 | 差 |
|---|---|---|---|---|---|
| #9 BREAK | 14.48 | 32.9px | +2.69 | +18.39 | **+15.70** |
| #11 無下限 | 16.32 | 32.3px | +3.00 | +28.12 | **+25.12** |
| #15 無下限 | 20.02 | 32.9px | +3.00 | +23.95 | **+20.95** |
| #17 虚式 | 21.86 | 31.8px | +2.30 | +20.72 | **+18.42** |
| #19 崩壊 | 23.71 | 33.2px | +3.38 | +34.25 | **+30.87** |
| #21 虚式 | 25.55 | 31.8px | +6.49 | +39.01 | **+32.53** |
| #22 最強 | 26.68 | 28.3px | −0.83 | +15.80 | **+16.63** |

**8 个弹性拍点中 7 个上跳 +16~+33px（中位 +19.7px）**；
唯一反向的 #13 拍点本身处于素材运动峰值（Δv40 = −9.76），非反例而是被素材运动掩盖。

> 符号约定：屏幕 y 向下为正。Δ = cy(回落帧) − cy(拍点帧) **> 0 表示拍点帧更高**（上跳）。
> 第一次跑我把判定写成 `< 0`，差点把"生效"误判成"没生效" —— **位移类指标必须先确认符号方向**。

验收视图：`render/v41_kick_proof.png`（v40@拍点 / v41@拍点 / v41@回落 三格并排 + 同一参考线，
上跳肉眼可辨）、`render/v41_rhythm_strip.png`（全片节奏带）。

### 方法沉淀（本轮新增）

1. **踩点指标的分母必须是音乐**。用"事件是否落在 onset 上"当指标是自证式的（事件本就锚在 onset）；
   必须问"音乐最强的那些拍，有多少被画面回应了"。
2. **对照表要裁剪到正片时长**，否则片外的拍会被算成漏拍（本次第一次跑就踩了这个坑）。
3. **"有字在画面"≠"有动作"**：保持期内的强拍若不做任何事，观感就是"没跟上"。
   分类统计 `ENTER / PULSE / PULSE- / GAP` 才能定位到具体失分点。
4. **脚本化属性的陷阱**：`setValueAtTime` 对**表达式驱动**的属性无效（AE 不报错、静默失效）。
   判断方法：读 `numKeys`，表达式驱动的属性没有关键帧。
5. **可见性要按背景分**：发光类效果在亮背景上天然不可见，几何位移（位置/缩放）才是通用手段。

### v42 加狠（Boss："更狠"）

| 参数 | v41 | v42 |
|---|---|---|
| 上跳幅度 | `14 + 22×强度` px（27-34px） | `24 + 36×强度` px（45-56px） |
| 回落时间 | 0.09s | 0.07s（更脆） |
| 回弹 | 无（起→落两点） | **过冲**：弹起 → 回落 → 向下过冲 `0.16×kick` → 归位（4 键） |
| 最强拍（强度≥0.85） | — | 附加水平冲击 6px |

**实测（v41 vs v42 同帧 A/B）**：上跳中位 **+19.6px → +39.0px**，
8 个弹性拍点中 6 个增强 >+5px，最大 #19 崩壊 **+55px**。

守卫也相应收紧：过冲需要额外的收敛时间，故条件从 `bt < t_out−0.12` 改为
`bt + 0.25×sp < t_out−0.02`，避免回弹键与出场漂移键（`t_out−fout`）打架。
