## 零、现状架构（实读确认，非推测）

```
[Python 剪辑链]  unified_edit.py
   Stage1 beat → Stage2 motion → Stage3 → EDL落盘(edl.py: build/save/lint) → Stage4a LUT → 4b SFX
   产物: production_report.json + edl.json(cuts/inputs+sha1/cut_points/toolchain) + LUT底片
   R1 五轮修复在 ai/production_director.py(已提交 5 commits)——引擎级已生效

[AE 视觉链]  mastercut_agent.py::execute("render_cut")
   → _apply_effects_to_video() → build_master_polish.py <run_dir> <tag> --effects-json
        (读 run_dir/production_report.json；SCHEMA_TO_RECIPE 翻译；effects_injection_report 对账)
   → polish/master.aep → render_master.py → <tag>_master.mp4
   ✅ visual_effect_schema 已于 09-08 接入此链（10/18 类型可渲染）

[AE 文字链]  build_text_overlay.py <run_dir> <tag>   ← ⚠️ 孤儿：无人调用
   读 run_dir/production_report.json + tmp/{true_onsets,music_envelope,shot_motion,shot_scenes_raw}.json(run53 专属)
   → text_overlay_vN.jsx → send_bridge 注入 → run53_text_vN.aep → aerender
```

**三处结构性断点**（=集成咽喉）：
1. **文字链是孤儿**：`unified_edit.py` 与 `mastercut_agent.py` 均不调用 `build_text_overlay`（grep 证实）。
2. **AE 链吃 production_report 而非 edl.json**：EDL 已产出却无消费端 → K3「双链无桥」的契约级根因。
3. **EDL 只承载 cuts，无效果/覆盖层轨道**：无法把"独立渲染的效果"绑回主时间线（video-use 的 `overlays` 段正是此物[5]）。

### 1.2 集成顺序与依赖（关键路径）

```
Step0 EDL 契约扩展  ──→  Step1 AE 链改吃 edl  ──→  Step2 注册进编排器  ──→  Step3 端到端基线 run
  (edl.py 加轨道段)      (--edl 参数+回退)        (ToolRegistry/stage)      (r1_fixed 载体全链)
        │                                                                   ↑
        └──→ Step5 Skill Registry + 卡片 + 验证闸门（用 EDL/evidence）──────┘
Step4 木偶线 alpha 轨道进 EDL inputs + master_polish 合成层（独立并行，依赖 Step0）
```

- **Step 0｜EDL 契约扩展（地基，半天）**：在 `scripts/edl.py` 的 EDL schema 增三段，**FORWARD 兼容**（旧 consumer 忽略新段[29]）：
  ```jsonc
  "effects":     [{"effect_id","effect_type","time_range","parameters","envelope","evidence_chain"}],  // 视觉特效(对齐 visual_effect_schema)
  "text_events": [{"t_in","t_out","word","style_id","font","x","y","size","enter","skill_id"}],          // 文字线(对齐 events.json)
  "overlays":    [{"file","start_in_output","duration","source_skill_id"}],                              // 独立渲染的效果/木偶 alpha(video-use 式[5])
  "schema_version": "1.1"   // 从 1.0 升；lint_edl 加 L7: overlay/effect 时间不越界、onset 对齐≤2帧
  ```
  依据：video-use edl.json `overlays[{file,start_in_output,duration}]`[5] + OTIO Track/Composition[1]。
- **Step 1｜AE 链改吃 EDL（1 天）**：`build_text_overlay.py` 与 `build_master_polish.py` 增 `--edl <path>`（消费 edl.json 的 cuts+effects/text_events/overlays），**保留 production_report 回退**（BACKWARD 兼容）。效果：R1 修复经 edl.json 自动传导到文字/视觉层。
- **Step 2｜注册进编排器（半天）**：在 `mastercut_agent.ToolRegistry` 注册 `render_text_overlay`（与 `render_cut` 并列），或作 `unified_edit.py` 的 `enable_ae` 通道可选 stage（该钩子已存在）。消除孤儿。
- **Step 3｜端到端基线 run（1-2 天）**：对 `unified_r1_fixed_v7`（或新 clean run）跑 `unified_edit → edl.json → build_text_overlay(--edl) + build_master_polish(--edl) → render → 五门/可读性门`。产出首个"切点干净+文字就位+特效挂载"的全链基线。
- **Step 4｜木偶线进主链（并行，2-3 天）**：`wa2_to_alpha` 产物 → EDL `overlays`/inputs alpha 轨道实测 → master_polish 合成层 → 15s 样片（闭合 K9）。
- **Step 5｜Skill Registry（见 §二，1-2 天，Step0 后可启）**。

**依赖关系**：Step0 是所有 AE-链集成的前置；Step1→2→3 严格串行；Step4/Step5 可与 Step1-3 并行（Step4 依赖 Step0，Step5 依赖 Step0 的 evidence 字段）。

## 二、是否封装 Skill + 粒度划分（Q2）

### 2.1 判定：哪些成 Skill 卡片，哪些留管线内部模块

判据（综合 ComfyUI[10]/MLT[7]/OFX[33]/Nuke-Gizmo[40]/Model-Card[20]）：**"一次验证、多次复用、声明式参数化、与宿主版本绑定"的能力单元 → Skill 卡片；基础设施/管线胶水 → 内部模块。**

| 类别 | 归属 | 理由 |
|---|---|---|
| 视觉特效配方（bloom/badtv/glitch/radial_blur/motion_blur/burst_*/fmb_directional/particular/bokeh 共 10 种已实现） | ✅ **Skill 卡片** | 已渲染验证、参数化、可跨 run 复用 |
| 文字动画预设（60 个已验证 + v6-v15 的字体分池/对比度感知/彩光/3D-Z/冲击力包配方） | ✅ **Skill 卡片** | 同上；含大量"探针实证 matchName"知识 |
| 转场冲击 D7 / 节拍脉冲 D4 配方 | ✅ **Skill 卡片** | 已实证、可复用 |
| 木偶线 WA2→alpha 配方 | ✅ Skill 卡片（Step4 验证后） | 待 15s 样片实证 |
| `edl.py` / `build_master_polish.py` / `render_master.py` / `unified_edit.py` / `mastercut_agent.py` | ❌ **管线内部模块** | 是 harness/编排器/渲染器，非可复用能力单元 |
| `cut_visibility_v3.py` / `check_delivery_spec.py` / 五门 | ❌ **契约闸门**（GE 式[39]，非 skill） | 是校验基础设施 |
| 未实现的 5 种 premium 类型（sapphire_glow/optical_flares/delirium/magic_bullet/film_stocks） | ⚠️ **experimental 卡片**（matchName 未实证，禁进 production） | 遵循 A1；OFX"宿主不支持→降级"[33] |

### 2.2 粒度划分建议：**按「效果类型 × 功能域」，不按管线阶段**

- **理由**：ComfyUI 节点 / MLT filter / OFX plugin / Nuke gizmo 的粒度**都是"一能力=一卡片"**，而非"一阶段"。管线阶段是基础设施（不跨项目复用），效果配方才是可复用知识。
- **分组（功能域）**：`glow`（bloom/彩光）· `blur`（motion/radial/directional）· `distortion`（badtv/glitch/turbulent）· `particle`（particular/burst）· `text-style`（描边/投影/字体分池）· `text-3d`（Z 纵深/假挤压）· `transition`（D7 冲击）· `color`（LUT/Color Balance）。
- **每卡一原子能力**，域内可组合（如"drop 冲击"= radial_blur + text-style + burst 三卡组合，组合关系记在 EDL effects 段而非卡内）。

### 2.3 Skill 卡片模板（综合 MLT-YAML[7]+ComfyUI-pyproject[11]+Model-Card[20]+Nuke-Gizmo[40]+SLSA[36]+现成 SKILL 实例[41]）

```yaml
# schemas/skill_cards/glow/bloom_drop.yaml
skill_id: bloom_drop              # = evidence_chain.skill_id 引用锚
domain: glow
effect_type: bloom                # 对齐 visual_effect_schema enum
version: 1.2.0                    # SemVer（见 §三）
stage: active                     # validated | active | deprecated | archived（MLflow 式[34]）
requires_host: "AE>=25.0"         # 宿主版本兼容（ComfyUI requires-comfyui / OFX kOfxPropVersion 式）
recipe_ref: build_master_polish.RECIPES['bloom']   # 实现位置（Nuke gizmo：定义外置、按名引用）
parameters:                       # 参数 + 范围 + 暴露契约（MLT YAML / Nuke Export gizmo 式）
  threshold: {type: float, range: [0.5, 1.0], default: 0.80, editable: true}
  radius:    {type: int,   range: [3, 12],    default: 6,    editable: true}
  intensity: {type: float, range: [0.2, 0.6], default: 0.38, editable: true}
intended_use: "drop/climax 高光发光；亮底需配对比度感知描边"
out_of_scope: "整片静态叠 bloom（会洗白，见 v8 教训）；暗底用白辉光卡"
evidence_chain:                   # in-toto 式 attestation（SLSA[36] + W3C PROV[18]）
  validated_at: "2026-09-04T00:00:00Z"
  was_generated_by: {run: "run50", render_diff: "output/.../v11_grid.png"}
  source_commit: "727be41"
  inputs_sha1: "…"                # 复用 edl.py 的 sha1
  output_digest: "…"
  host_version: "AE 25.0"
checksum: "sha256:…"              # 钉死 recipe 实现（Terraform lock 式[35]）
version_history:                  # 现成 SKILL 实例范式[41]
  - {version: 1.2.0, date: "2026-09-11", commit: "727be41", note: "彩光三参数 0007/0012/0013"}
  - {version: 1.0.0, date: "2026-09-04", commit: "…", note: "run50 首验"}
```
- **落地位置**：`schemas/skill_cards/<domain>/<skill_id>.yaml` + `schemas/skill_cards/registry.json`（索引）。把 `data/style_cards/beat_grammar_validated_v1.json` 迁入。
- **治理闸门**：`build_master_polish` 对"无卡片/stage≠active/requires_host 不匹配/checksum 不符"的效果 → 计入 `unmapped/skipped` 并记原因（复用现有 `effects_injection_report`），实现"**无有效卡片不进 production**"[22][34]。

## 三、后续开发如何更新与维护 Skill（Q3）

### 3.1 版本管理（SemVer，Terraform 契约规则[35]）

| 变更类型 | 版本位 | 例 |
|---|---|---|
| 参数范围收紧/配方实现 bugfix（不破契约） | **PATCH** | bloom radius 上限 12→10 |
| 新增可选参数/新增域内配方 | **MINOR** | 加 `color_mode` 可选字段 |
| effect_type/schema/参数语义破坏性变更 | **MAJOR + 弃用周期** | `radial`→`radial_blur` 统一；参数索引变更 |
| 宿主升级导致语义漂移 | **强制重验 + requires_host 升** | 参照 Resolve SetLUT nodeIndex 0→1 基[27]、AE 字体/Glo2 陷阱 |

### 3.2 防"卡片与代码脱节"的四道机制（核心）

1. **单一真源生成（根治手写漂移）**：schema 与卡片由 `RECIPES`+参数范围**生成**（CUE[37] 或 Pydantic[38]），不再手写两份。`visual_effect_schema.json` ← 生成自卡片/RECIPES。
2. **CI 一致性闸门**：`tests/test_visual_effect_schema.py` 扩展为校验 `enum ↔ RECIPES ↔ skill_cards` 三方一致（钉死 `radial`/`radial_blur` 分裂[guide]）；卡片 `checksum` 与 recipe 实现哈希比对，不符即红灯。
3. **验证时间戳 + 重验触发**：卡片任何 `parameters`/`recipe_ref`/`requires_host` 变更 → **必须重跑渲染差分验证** → 更新 `validated_at`+`version_history`+`output_digest`。未重验的改动 = `stage` 自动降级为 `validated`（不得 active）。
4. **changelog + 弃用周期**：`schemas/skill_cards/CHANGELOG.md`（卡片级）+ `schemas/CHANGELOG.md`（schema_version 级）；MAJOR 变更走弃用周期 + 通知 consumer（数据契约规则[28][29]）。

### 3.3 证据链/血缘（解 K7 acceptance_log 0/30）

- 卡片 `evidence_chain` 用 in-toto 式 attestation[36]（离线本地 JSON，不上 Sigstore/Rekor 云端）：`skill_id → wasGeneratedBy(验证 run + 渲染差分) + inputs(SHA1，复用 edl.py) + validated_at + output_digest + host_version`。
- 与 `data/evolution/{render_history,render_audit}.jsonl` 血缘打通；每次 run 强制落一条 acceptance 记录（GE Checkpoint 式[39]），累积 ≥30 解锁 R8/GEPA。
- Dagster 资产视角[30]：`output/<run>/` 三件套报告 = 天然资产，用资产血缘串 acceptance_log。

### 3.4 变更追踪落点一览

| 变更 | 更新什么 | 自动化 |
|---|---|---|
| 特效配方升级 | 卡片 `version`(SemVer)+`validated_at`+`version_history`+`checksum` | 重验脚本 + CI 校验 |
| 新增效果类型 | schema enum（生成）+ 新卡片 + RECIPES 实现 | CI 三方一致闸门 |
| 参数范围调整 | 卡片 `parameters.range` → 生成 schema | 单一真源生成 |
| 宿主(AE)升级 | 全卡 `requires_host` 复核 + 抽样重验 | requires_host 不匹配→闸门拦截 |

## 四、风险与纪律

1. **不过度 schema 化**（video-use anti-pattern[5]）：优先"把已验证的 10 种接进主链并注册"，冻结 5 种未实现 premium 类型为 `experimental`，**不扩未实现 schema**。
2. **FORWARD/BACKWARD 兼容**：EDL 1.0→1.1 加段必须让旧 consumer 忽略新段[29]；`--edl` 与 production_report 双通道并存过渡。
3. **FSM 递归限制**[38]：若上约束解码生成配方，注意 `allOf/if-then` 条件 schema 的 FSM 开销；离线优先 outlines。
4. **多会话隔离**：Step1-3 改 `build_text_overlay.py` 与 v16 并行会话**同文件冲突**——须待 v16 会话告一段落、或按协作规约§九串行执行；本方案文档纯新增，不改代码。
5. **依赖严格声明**：卡片带依赖（8GB 显存/离线约束），防 ComfyUI 式依赖地狱[13]。

## 五、建议起点

**Step 0（EDL 加 overlays/effects/text_events 段，FORWARD 兼容）+ Step 5 的卡片模板落地 3-5 张已验证配方（bloom_drop / badtv_kick / radial_burst / text_style_contrast / text3d_z）**——两者零依赖、当天可出，且立刻让"双链有共同契约"与"能力可注册复用"同时起步。随后 Step 1→2→3 打通端到端基线 run。
