## 四、战略判断：下一阶段的主轴是"合流"而非"扩张"

三个论据：

1. **呈现质量的天花板由双链短板决定**。Python 链切点质量（frozen 率）再高，若视觉强化/文字只叠加在旧 run53 载体上，最终成片呈现不会提升；反之 AE 链特效再好，底下是 72.9% frozen 的剪辑就是空中楼阁。**两链必须经由 EDL 桥共享同一份剪辑真相**——edl.json（Python 链已落盘）→ AE 链消费，是唯一低成本路径（桥的一端已存在）。
2. **边际收益排序变了**。09-08 五维评分时"文字 P0 = 23 分最高"的前提是其前置未动；现在前置 100% 就绪（事件表/JSX/字体栈/门禁/Bridge 通道），剩余成本只剩"AE 会话执行 5 步"，单位收益进一步放大。同期 R3 已满分、R4 已收官、R6 已清零——R 线的可收割项显著变少，资源应回摆文字/视觉线。
3. **风险窗口**。文字事件表是按 run53 的 tmp 数据生成的（onset 对齐 0.0 帧）；每拖一天，run53 基线与主链修复（drift 钳制等）的偏差就多一分，未来重跑 unified_run53 时事件表要重新生成——注入验证越早做，schema 契约（P1-P3 依赖）锁定越早。

**主轴定义：波次1-2 完成文字 P0 闭环 + R1 定性收口 + EDL 桥合流，产出第一个"切点干净 + 文字就位"的全链基线 run；波次3-4 在该基线上做视觉强化全量与数据泛化。**

## 七、GLM-5.3 能否胜任推进开发工作（分析）

> 视角声明：本节以"任务类型 × 项目实证"评估，不做空泛的模型自评。项目近 25 个 commit（R1 钳制/R3 满分/R4 修复/EDL 框架/测试清零）均由 coding agent 会话产出，本计划全部波次的工作类型与之同构。

### 7.1 按任务类型的胜任度矩阵

| 任务类型 | 波次覆盖 | 胜任度 | 依据与边界 |
|---|---|---|---|
| **Python 管线开发/调试**（production_director/unified_edit/EDL/回归框架） | W0-W4 全部 | **强** ✅ | drift 钳制、repair 接线（run62 实证）、alimiter 修复均为此类；长上下文跨文件根因追踪是 LLM 强项 |
| **"推翻纸面结论"型根因分析** | W1-B（R1 分桶）、验收口径审查 | **强** ✅ | 项目三个灾难级发现（v2 幸存者偏差、applicability 纸面声明、_tl_drift 失控 2.8e34s）全部由 agent 会话完成——读全库+交叉验证+量化复现正是这类模型最可靠的模式 |

### 7.2 结论

**胜任，且项目已经用实践证明**——但胜任的前提是三个机制继续严格执行：

1. **实证主义铁律（A1）不变**：模型对 AE API/枚举值的记忆不可信，这正是项目把"实机探针→matchName 固化→模板化生成"做成流程的原因。新配方（扫光逐字/liquid/粒子化爆炸）语法全部未实证，**必须探针先行**，这是波次3的第一道工序。
2. **人机分工边界清晰**：模型管"可量化验证的一切"（五门中的四门 + 可读性代理指标），人管"目视门 + 词库 + 决策清单 D-1~D-5"。把不可委派项显式写进波次（W1-A 的用户触点已标）。
3. **记忆与协作规约**（§九）：多会话并行是本项目常态，模型间上下文隔离靠 MEMORY.md 铁律 + 交接文档 + 本计划的会话分工矩阵维持——这个机制本身已经受住 09-09/10 三会话并行的考验（也出过 GPU 互斥/提交卷入两次事故，规约是从事故中学来的）。

**风险与对策**（针对 GLM-5.3 具体短板）：

| 风险 | 场景 | 对策 |
|---|---|---|
| 记忆噪声 | 新 JSX 配方凭训练记忆写 matchName | A1 探针流程 + 先例模板库强制引用 |
| 长任务失稳 | aerender 全片渲染/全量测试超时 | 分段渲染（CRF 预览→高质量）+ 后台任务 + 轮询 |
| 上下文耗尽 | 5474 测试全量跑、多文件大改 | 分批提交/子代理隔离/以 MEMORY.md 续接（项目已验证） |
| 幻觉式"自我表扬" | 验收报告报喜不报忧 | v3 铁律（分母=声明切点全集）+ 三件套量化证据落盘 + "任何 X 报告必须报 v3 数字否则不算数"类硬口径 |

## 八、会话协作规约（多会话并行，事故驱动的十条）

1. **GPU 任务互斥**：启动 GPU 任务（WA2/BiRefNet/ComfyUI/R3 评测）前查 `nvidia-smi --query-compute-apps`；本机 8G VRAM/15.7G RAM 只容一个。
2. **AE 会话唯一**：Bridge 注入/监听器操作同一时刻只允许一个会话（防双开冲突，交接文档既定分工原则）。
3. **提交前复核 stage**：`git diff --staged` 逐文件核对归属，防并行会话卷入（c00175a 教训）。
4. **删除三禁忌**：bash rm（进回收站不释放）/后台 python os.remove/Remove-Item 全被拦；唯一通道 `[System.IO.File]::Delete` + `Clear-RecycleBin -DriveLetter D`；≥50 次删除分跨 turn。
5. **后台任务带 `V23_KEEP_INTERMEDIATES=1`**（沙箱删除熔断规避）。
6. **记忆分节**：各会话只追加自己的分节，不覆盖他人；铁律级发现进 MEMORY.md 主文件。
7. **验收必带口径**：切点可见性只认 v3；新增度量先定义分母再报数。
8. **改动即测试**：任何管线改动配单测，回归全绿才算完。
9. **跨会话交接**：会话结束写 00-每日记录交接文档（本计划与交接文档互为载体）。
10. **动手前复核清单时效**：清理/资产类动作先复核实物（旧清单三项已失效的教训）。
