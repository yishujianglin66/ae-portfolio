## 二、专业分析与方向推理

### 2.1 技术栈成熟度与能力缺口

**成熟度判断**：文字动画"单效果执行"能力已到 85%+（预设库/生成器/验证闭环完整），但**"合成编排"能力几乎为零**——现有管线是"一次调用一个效果脚本"，缺少：
- 多层合成编排（前景文字+粒子+背景+调整层的组合成）
- 时序编排（多层动画的时间轴级联/节拍对齐）
- 风格级生成（一句话/一个风格卡 → 完整合成工程）
- 渲染质量闭环（合成后视觉评估 → 参数回修）

**能力缺口表**（按影响排序）：

| 缺口 | 现状 | 对"后期特效合成"的阻碍 |
|---|---|---|
| G1 合成编排层 | 无（只有单脚本执行） | 无法生成"完整特效合成" |
| G2 时序/节拍对齐 | 仅 textImpact beat_sync 雏形 | 特效与音乐脱节（漫剪卡点铁律已验证节拍是刚需） |
| G3 风格生成闭环 | smart_director 雏形 | 无端到端风格卡→工程 |
| G4 视觉质量评估 | 仅渲染尺寸校验 | 无"好不好看"的客观反馈 |
| G5 3D 深度 | 4 预设 + C4D 渲染器不可控 | 3D 特效上限受限 |

### 2.2 从"文字动画"向"后期特效合成"延伸的可行性

**可行，且是自然演进**：文字动画的产物本质是"图层+效果+关键帧"的组合，后期特效合成只是把"单文字层"推广为"多图层多效果的合成树"。现有资产（JSX 生成器/关键帧动画器/预设库/验证管线）都是合成系统的现成零件。**关键新增只有两块**：编排器（composition orchestrator）与风格入口（style card → 合成树）。

**已有基础设施支撑**（本会话实测资产）：
- v23 AMV 引擎（叙事/节奏/运镜三层）+ 漫剪卡点铁律（鼓类型切点锚定）——提供**节拍锚定与叙事上下文**
- 抠像链路（MatAnyone 分段 + BiRefNet 补抠）——提供**合成素材（带 alpha 的人物层）**
- AE 高级运镜通道（zoom_back/pulse 贝塞尔缓动+运动模糊）——提供**镜头运动合成**
- 这些拼起来就是"后期特效合成"的完整原料链：素材（抠像人物）→ 镜头（运镜）→ 节拍（卡点）→ 特效（文字/粒子）

### 2.3 候选方向排序（2-3 个）

**方向 A：合成编排引擎（Synthesis Orchestrator）** — P0
> 把"单效果脚本"升级为"多图层多效果合成树"：图层栈（前景文字/粒子/背景/调整层）+ 时间轴编排 + 组合成渲染。直接对治 G1，且是方向 B/C 的地基。
> 理由：①复用率最高（所有现有 JSX 生成器直接成为叶子节点）②闭环最短（AE Bridge 已有，只缺编排层）③用户刚完成抠像链路，人物层素材已就绪，合成需求即刻存在。

**方向 B：节拍锚定特效系统（Beat-Locked FX）** — P1
> 把漫剪卡点铁律（鼓类型切点）与特效触发绑定：文字 pop/粒子爆发/glitch 精确落在 kick/snare 上。对治 G2。
> 理由：①项目已把"音乐驱动剪辑"验证为铁律，特效侧是空白 ②OpenMontage beatgrid 资产已集成（v23 kick 优先锚定）③差异化价值最高——这是"漫剪感"的灵魂。
> 依赖方向 A 的时序编排能力。

**方向 C：风格卡→合成工程生成（Style-to-Composition）** — P2
> 风格卡（已有 style_card schema：amv/cyberpunk/ambient）→ LLM 规划 → 合成树 JSON → 自动执行。对治 G3。
> 理由：①smart_director 已有雏形 ②但依赖 A（执行层）+B（节拍层）成熟后才有完整效果，先做会产出"无节拍感的堆砌"。

**排序结论**：A → B → C，串行依赖（C 依赖 A+B 的产物质量）。

### 2.4 与并行开发线的关系（smart_director/Resolve 线）

8/13 的活跃方向是"智能导演（smart_director）+ Resolve 管线"。本方案与之**互补不冲突**：
- smart_director = **规划层**（三档强度选择/场景标签推理/预设追踪）——解决"选什么"
- 本方案 Orchestrator = **执行编排层**（合成树生成/多图层组合/Bridge 执行）——解决"怎么组合执行"
- 两者接口点：smart_director 的强度/风格决策输出 = Orchestrator 的合成树参数输入；Resolve 管线负责调色端，本方案负责 AE 合成端
- ⚠️ 协作风险：两线都写 JSX 生成代码，需约定模块边界（smart_director 不直接生成 JSX，统一经 Orchestrator 的生成器层）

### 3.1 技能与工具链

**已有（直接复用）**：

| 资产 | 角色 |
|---|---|
| JSX 生成器族（textfx/text_3d/effect_depth/text_impact/particleFX） | 合成树叶子节点 |
| `core/jsx_keyframe_animator.py` | 关键帧动画（缓动 DNA 8 种） |
| AE Bridge（文件轮询）+ aerender | 执行与渲染 |
| `integrations/smart_director.py` | 规划层雏形 |

| OpenMontage beatgrid / v23 卡点锚定 | 节拍信号 |
| 抠像链路（人物 alpha 层） | 合成素材 |
| registry P0 已集成：adobe_mcp/qwen_mm/resolve_mcp | 执行/视觉/调色 |

**需新引入（外部，评估后接入）**：

| 工具 | 用途 | 评估 |
|---|---|---|
| nexrender（已注册 P1，未深度集成） | 模板化 AE 渲染编排——与合成编排引擎高度互补，可直接复用其 job/template 概念 | 高价值，集成难度中 |
| Qwen-MM 视觉（已注册 P0） | 合成效果视觉评估（G4 闭环的眼睛）——比"训练评估模型"便宜得多 | 高价值，API 已通 |
| After Effects MCP（已注册 P1） | 若 adobe_mcp 对 AE 支持不足时兜底 | 备选 |

**需自研（核心增量）**：

| 组件 | 职责 | 规模估计 |
|---|---|---|
| **CompositionTree** 数据模型 | 图层/效果/时间轴的树形 JSON schema | 1-2 天 |
| **SynthesisOrchestrator** | 合成树 → JSX 工程代码生成 + Bridge 执行编排 | 3-5 天 |
| **BeatLock 触发器** | beatgrid → 合成树事件挂点 | 2-3 天 |
| **视觉评估网关** | 渲染帧 → Qwen-MM 评分 → 参数回修循环 | 2-3 天 |

### 3.2 知识库覆盖与补充

**现有覆盖**：风格化剪辑知识库（262 文件）、效果参数映射库、AE ExtendScript API 手册、漫剪卡点铁律——**单效果知识与剪辑节奏知识已充足**。

**缺口与补充条目**：

| 新条目 | 内容 | 优先级 |
|---|---|---|
| 合成编排知识卡 | 图层栈规范/组合成最佳实践（前景-背景-调整层顺序、混合模式搭配表） | P0 |
| 特效-节拍映射表 | 每种特效类型的节拍适配（pop→kick、burst→crash、glitch→snare roll） | P1 |
| 风格卡→合成模板 | 3 个 pilot 风格（amv/cyberpunk/ambient）的完整合成树模板 | P1 |
| AE 合成 API 补丁 | 本次盘点新发现的硬限制（Geometry Options 只读等）写入避坑指南 | P0 |

### 3.3 开源项目整合

| 项目 | 集成价值 | 难度 | 推荐路径 |
|---|---|---|---|
| **nexrender**（已 vendored） | ★★★ 模板化渲染编排可作 Orchestrator 的执行后端（省 3 天自研） | 中 | P0：先评估其 job schema 与 CompositionTree 的映射，能复用就复用 |
| OpenMontage（已集成） | ★★ beatgrid 节拍信号 | 已集成 | 维持，BeatLock 直接用 |
| ComfyUI（已 vendored） | ★ 若需 AI 生成背景/纹理素材 | 已就绪 | P2 可选：生成背景层 |
| 外部新项目（待调研） | 候选：TextFX 类开源（如 rive/lottie 转换） | 待评估 | P2 |

### 3.4 数据集需求分析

**需要，但规模小**：
1. **特效参数数据集**：风格卡参数 → 合成效果评分对。来源：自产（本管线批量生成风格变体 + Qwen-MM 评分）——**无需外部数据集**，自产即可（每条合成树跑 3-5 个参数变体）。
2. **风格样本库**：高质量 AMV/片头参考片段（已有 data/real_amv_test 37 支素材 + 风格化剪辑知识库案例）——**已够起步**。
3. **标注数据**：暂不需要人工标注（视觉评估用 Qwen-MM 自动打分，人工只做抽查）。
4. 规模估算：pilot 阶段 100-300 条自产参数-评分对，即可训练/校准参数预测小模型或做风格参数优选。

### 3.5 模型训练评估

**结论：P0/P1 阶段不需要训练模型；P2 可训练一个参数预测小模型。**

- **不需要训练的替代路径**：风格生成用 LLM 规划（DeepSeek，已在用）+ 预设库查表；视觉评估用 Qwen-MM API；参数优选用"网格变体+自动评分"（3-5 变体选最优）——三者组合即可闭环 G3/G4，**零训练成本**。
- **P2 可选训练**（当自产数据积累 300+ 条后）：
  - 选型：小型 MLP/GBDT 参数预测器（输入：风格卡+节拍特征 → 输出：效果强度/颜色/缓动参数档位）
  - 数据：自产参数-评分对（3.4 节）
  - 算力：CPU 即可（GBDT）或轻量 GPU（MLP），无需云训练
  - 预期收益：把"参数优选"从 3-5 次网格降为 1 次预测，速度 ×3
  - 风险：低（失败即回退网格变体，无阻塞）

## 四、执行步骤、里程碑与优先级

### 里程碑与依赖图

```
M0 资产修复（盘点缺口清理）          ← P0，无依赖，0.5-1 天
   ├─ 6 个未实现预设：实现或从声明中移除
   ├─ style 引用 bug / font_size 生效
   ├─ effect.json 键缺失/重复修复
   ├─ 硬编码路径清理
   └─ validate_jsx 铁律落地（text_3d/effect_depth）
        ↓
M1 合成编排引擎核心（方向A）          ← P0，依赖 M0（干净的叶子节点）
   ├─ M1a CompositionTree schema + 3 风格模板
   ├─ M1b Orchestrator：树→JSX→Bridge→渲染
   └─ M1c 端到端 demo：1 个风格合成工程（文字+粒子+背景+调整层）
        ↓（M1 完成）
M2 视觉评估闭环（G4）                ← P0，依赖 M1（有产物可评）
   └─ Qwen-MM 评分网关 + 3-5 参数变体优选
        ↓
M3 节拍锚定特效（方向B）             ← P1，依赖 M1（时序编排）
   └─ BeatLock：beatgrid→事件挂点 + 特效-节拍映射表
        ↓
M4 风格卡→合成生成（方向C）          ← P2，依赖 M1+M3
   └─ LLM 规划 + 风格卡模板 + 端到端"一句话→工程"
        ↓
M5 参数预测小模型（可选）            ← P2，依赖 M2 数据积累
```

### 优先级与工期

| 里程碑 | 优先级 | 工期 | 验收标准 |
|---|---|---|---|
| M0 资产修复 | P0 | 0.5-1 天 | 6 预设全实现或移除、effect.json 键校验通过、validate_jsx 全绿 |
| M1 合成编排引擎 | P0 | 5-7 天 | 1 个完整合成工程端到端渲染 PASS + 三风格模板 |
| M2 视觉评估闭环 | P0 | 2-3 天 | 自动评分与人工抽查一致率 ≥80%（30 样本） |
| M3 节拍锚定 | P1 | 2-3 天 | 特效事件 90%+ 落在 beatgrid 节拍 ±1 帧 |
| M4 风格生成 | P2 | 3-5 天 | 一句话生成完整工程，主观验收 |
| M5 参数模型 | P2 | 3 天（数据满 300 条后） | 预测与优选结果一致率 ≥70% |

### 需实机验证的不确定点（明确标注）

1. ⚠️ **nexrender 与 AE Bridge 的执行冲突**：两者都驱动 AE，需实测互斥/融合方式（可能 nexrender 渲染段与 Bridge 交互段串行）
2. ⚠️ **Qwen-MM 对渲染帧的评分能力**：动漫特效帧的主观质量评估是否与人工一致（M2 验收标准本身要验证）
3. ⚠️ **AE 2025 组合成的稳定性**：多层多效果 JSX 工程一次生成的崩溃率（历史利威尔 MAD 表明复杂工程有崩溃风险，需分段提交）
4. ⚠️ **BeatLock 的节拍精度**：OpenMontage beatgrid 与 AE 时间轴帧对齐的实际误差（本会话抠像链路经验：帧对齐在 Windows/FFmpeg 链路有已知偏移坑）
