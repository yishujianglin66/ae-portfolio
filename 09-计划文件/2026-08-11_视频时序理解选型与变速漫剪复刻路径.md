## 1. 参考视频真实时间结构（全时域实测，非抽帧）

对全部 491 帧逐帧分析（`tmp/ref_biansu_analysis.py`），关键结论：

| 维度 | 实测值 | 含义 |
|------|--------|------|
| 镜头数 / 切率 | 33 镜 / 1.96 切/秒 | 高密度卡点剪辑 |
| 镜头时长 | 中位 0.433s，最短 **0.067s（仅2帧）** | 存在"闪帧"级超短镜头，任何抽帧方案必然漏检 |
| 卡点对齐 | beat 对齐 40.6%，**onset 对齐 56.2%** | 再次验证专业剪辑对齐的是鼓点瞬态(onset)而非节拍网格 |
| 变速证据 | 12 镜有变速痕迹；shot#9（7.4-8.13s）**59% 重复帧** | 典型的"慢放不插帧"手法（setpts 直接拉长），这是帧级取证的铁证 |
| 运镜分布 | mixed/shake 15、zoom_in 5、zoom_out 6、pan 5、static 2 | 抖动+推拉复合运镜占 45% |
| 运镜曲线 | zoom 速度标准差 0.011-0.535，大量"非匀速" | 推拉是缓动曲线（ease）而非线性 |
| BPM | 音轨实测 123-125（beat_this 34拍/16.33s）；**BGM 原曲仅 100 BPM（拍间隔恒定0.6s）** | 参考片把 BGM **加速了 1.23x**（包络互相关 0.02→0.69，偏移4.2s，见下） |

**v15 成片 vs 参考片同轴对比**（同一把尺子）：

| 指标 | 参考片 | v15 | 差距定性 |
|------|--------|-----|---------|
| beat 对齐 | 40.6% | **50.0%** | 已反超 ✓ |
| onset 对齐 | 56.2% | 46.9% | 差 9pp，可追 |
| 超短镜头(≤0.15s) | 10 个 | 少量 | **缺"闪帧"节奏** |
| 变速痕迹 | 12 镜 | 0 | **最大差距：我们全是原速** |
| 复合抖运镜 | 45% | 15% | 运镜丰富度差距 |

> 结论：卡点精度已接近达标，**真正的差距在"变速 + 闪帧密度 + 缓动运镜"**——这正是帧级分析看不到、此前被系统性遗漏的部分。

### 1.1 ⭐ S1 双验证重大发现：参考片 BGM 被加速 1.23x（v1.1 新增）

对 BGM 原曲与参考片音轨分别用 beat_this 测拍 + 包络互相关扫描（`tmp/verify_bgm_speed2.py`）：

| 检验项 | 结果 | 含义 |
|--------|------|------|
| BGM 原曲拍间隔 | 恒定 0.6s → **100 BPM** | 原曲并非 123 BPM |
| 参考片音轨拍间隔 | 恒定 0.48-0.5s → **125 BPM** | 与 100×1.25 吻合 |
| 包络相关（原速 1.0x） | **0.023** | 原速假设被否决 |
| 包络相关（最优 1.23x + 偏移 4.2s） | **0.69** | 参考片 = BGM 加速 1.23x、从原曲 4.2s 处开始 |

## 2. 为什么现有逐帧采样分析（video_analyzer_accelerated.py 类）在变速漫剪上失准

该方案的核心是"帧对 Farneback 光流 + 锐度/噪声帧级特征"（`_detect_zoom(flow)`、`_sharpness`、`laplacian_var`），在变速漫剪上有五个环节的结构性错误：

1. **均匀抽帧 → 短镜头整体消失**：参考片 10 个镜头 ≤0.15s（2-4 帧），任何 ≥2 帧间隔的抽帧都会直接跳过它们，"镜头切点分布"从源头失真。
2. **光流幅度被变速混淆**：`光流大 = 运动快` 的假设在变速片上不成立——慢放段光流被压缩（误判为"静止"），加速段光流被放大（误判为"剧烈运动"），**速度的时间导数信息被抽帧破坏**。
3. **单帧/帧对特征看不到"曲线"**：ease-in-out 推拉、变速斜率都是 ≥3 帧的时序结构，帧级特征（锐度、噪声、单对光流）数学上无法表达。
4. **无音频流 → 卡点逻辑不可知**：帧分析永远回答不了"这个切点为什么剪在这里"，因为答案在 BGM 的 onset 时间轴上。
5. **慢放不插帧的重复帧被当"静止"**：shot#9 的 59% 重复帧是变速铁证，但帧级方案会把它归为"画面几乎不动"，得出与事实相反的结论。

## 3. 帧级分析系统性盲区清单（含昨天的参考视频分析）

| # | 盲区 | 后果 | 正确工具 |
|---|------|------|---------|
| 1 | 变速段检测 | 慢放/加速被误读为内容运动强弱 | 重复帧取证 + 光流连续性（无需训练） |
| 2 | 变速曲线形状 | 只能得到"有变速"，得不到 ease 曲线参数 | zoom 速度时序拟合（本地回归） |
| 3 | 超短镜头(≤4帧) | 抽帧漏检，切点分布失真 | 全帧切点检测 TransNetV2 |
| 4 | 闪白/故障转场 | 被阈值法误判成多个硬切 | TransNetV2 的渐变概率输出 |
| 5 | zoom(内参) vs dolly(外参) | 推近与前进混淆 | CameraBench 分类法（CMU 2025 结论：SfM 与 VLM 各有盲区，需融合） |
| 6 | beat vs onset | 对齐节拍网格=对齐错误时间轴（10.7% vs 53.6% 实测） | onset 检测 + downbeat 跟踪（beat_this/madmom） |
| 7 | 剪辑语义（为什么切在这里） | 无 | VLM 时序理解（Qwen2.5-VL 绝对时间编码） |
| 8 | 音视频联合结构 | 帧单流永远缺失 | 双流分析（librosa + 视觉同轴） |

### 4.2 "直接可用" vs "需要训练" 分界

- **直接可用（零训练成本）**：TransNetV2、beat_this、重复帧变速取证、Qwen2.5-VL、rhythm_reward（已训好）、场景分类器（已训好）。
- **需要训练（本期不做，仅留路径）**：
  - CameraBench 风格微调 VLM 做运镜原语分类——论文路线是微调生成式 VLM，LoRA 于 4090 约 2-3h ≈ ¥6；**但 MVP 阶段用 Qwen2.5-VL 零样本 + taxonomy 提示词即可覆盖**。
  - SpeedNet 式自监督变速检测——需在 Kinetics 量级数据重训且官方无权重，**明确否决**；帧级取证法已在本参考片上实证有效（抓到 shot#9 慢放）。

## 6. 推荐方案与复刻路径（同 BGM = 时间线可 1:1 移植）

**首选方案：本地混合管线**——信号处理取证负责精确（切点/节拍/变速），VLM 只补语义缺口（转场类型、运镜意图），完全符合《低成本开发方案》"信号量化 + VLM 补语义"原则。

**关键杠杆：参考片与项目用同一条 BGM**。这意味着参考片的镜头时间轴（相对音乐的拍位）可以**逐镜移植**到我们的素材上，不需要"风格迁移"，直接"结构复刻"。

### 复刻管线（5 步，全部本地）

```
参考片 ─┬─ TransNetV2 → 高置信切点（区分闪帧/真切）
        ├─ 重复帧取证 → 每镜速度段（slow/normal/ramp）
BGM ────┼─ beat_this → beat/downbeat/onset 网格
        ├─ zoom速度拟合 → 每镜缓动曲线参数（幅度/中点/ease类型）
        └─ Qwen2.5-VL → 转场类型 + 运镜语义复核
             ↓
   ReplicationSpec JSON（33 镜 EDL：拍位/时长/速度曲线/运镜/转场）
             ↓
   production_director 消费 spec：setpts 变速 + zoompan 缓动 +
   xfade 闪白 + 帧网格吸附（已有能力）→ 渲染 v16
             ↓
   验收：同轴对比脚本（compare_ref_vs_v15.py 扩展）
   目标：onset对齐≥55%、变速镜头数≥10、镜头时长中位数±0.1s 内
```

### 实施顺序与成本

| 步骤 | 内容 | 耗时 | 费用 | 状态 |
|------|------|------|------|------|
| S1 | `pip install transnetv2-pytorch beat_this`，对参考片复跑切点/节拍双验证 | 0.5 天 | ¥0 | ✅ 完成（2.7s GPU 推理；发现 BGM 1.23x 加速） |
| S2 | 变速取证器产品化：重复帧比例→每镜速度段，固化进 `core/style_spec_extractor.py` | 1 天 | ¥0 | 待做 |
| S3 | `production_director._extract_clip` 接 `speed` 字段（setpts 分支）+ 缓动 zoompan 曲线参数化 | 1-2 天 | ¥0 | 待做 |
| S4 | 生成 ReplicationSpec → 渲染 v16（**音频用参考片原音轨**） | 1 天 | ¥0 | 待做 |
| S5 | （可选）Ollama 装 qwen2.5vl:7b 做转场语义复核 | 0.5 天 | ¥0 | 待做 |

### 同期完成的能力升级（v1.1）

- **rhythm_reward v2**（`models/rhythm_reward_v2.pkl`）：新增 onset 三特征（frac_near_onset/onset_claim/frac_near_beat_or_onset）+ 参考片专家样本 + 标签改为 0.6×soft_beat+0.4×soft_onset；视频级 5 折成对排序准确率 **95.3%**（305 样本/23 视频），参考片真实切点在方案排序中位列前 3（与小抖动变体同档，符合预期）。
- **运镜分类器对照实验**（`models/camera_primitive_clf.pkl`）：合成曲线训练的 RF 在参考片锚点仅 69.7%，**低于现有手调规则的 100%**（大幅值 shake 带净位移时误判）——结论：保留 v1 规则，分类器留作候选，待 AE 工程真值到位后再训。

### 明确否决项（成本/可得性不成立）

1. SpeedNet/Video-ReTime：官方无权重无代码，自监督重训需 Kinetics 级数据 → 否决。
2. 端到端视频风格迁移（diffusion 系）：需 A100 级显存且输出不可驱动剪辑层 → 否决。
3. SfM/SLAM（DPVO、MegaSaM）解运镜：动漫 2D 内容特征点稀疏、8GB 显存不足 → 否决，用 zoom 速度时序拟合替代（已实证有效）。
