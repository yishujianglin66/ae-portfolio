# 木偶动画骨骼操纵升级方案（2026-08-16）

> 触发：木偶动画骨骼操纵链路薄弱；3渲2 渲染反复调参（100+ 版本）达不到目标
> 方法：3 路并行调研（Blender 技术 / UE 可行性 / 开源工具链）+ 本地资产诊断

---

## 一、根因诊断（为什么 100+ 版本不达标）

**不是渲染参数问题，是动画机制错了。**

- `puppet-automation/src/engines/blender/cel_shading.py` v10 已记录死结：
  **FBX 为纯静态网格导出，程序化骨骼 + auto-weight 蒙皮导致网格严重变形 → 回滚移除骨骼系统**
- 现状 = 静态网格整体位移/缩放模拟"木偶" → 没有真正的关节转动
- 结论：先修动画机制，再谈渲染。机制对了，渲染参数一次就能收敛。

## 二、UE 是否接入？—— 明确不接

| 维度 | Blender（继续走） | UE5 |
|---|---|---|
| 三渲二描边 | Freestyle/LineArt 原生，可控性强 | 无矢量描边，靠材质/后处理，可控性差 |
| 三渲二色阶 | 已有 5 套预设 + 91 篇踩坑文档 | 须自建 Unlit 卡通管线（PBR 默认更"错"） |
| 骨骼/权重自动化 | bpy 全 API 可编程 | **自动绑骨刷权重最弱环节**，Python 覆盖薄 |
| 无骨骼 FBX | 程序化建骨已实现 | 一样没骨架，不解决根因 |
| 批量渲染 | `blender -b -P` 秒级 | 编辑器启动+编译，8GB 显存吃力 |
| 与 AE 衔接 | PNG序列→FFmpeg→AE 已跑通 | 同样可跑，但无增量收益 |

**结论：两大痛点（无骨骼、三渲二）都是绑定/美术问题，不是引擎问题。UE 换过去无骨骼依然无骨骼，且自动化更难。不接 UE。**

## 三、核心路线：部件木偶 + 刚性骨骼（Live2D 式）

放弃"整体蒙皮变形"，改为"刚性部件 + pivot 旋转"：

1. **FBX 部件保持独立**（头/身/四肢/扇，已有部件识别逻辑）
2. **每关节建 Empty 或骨骼作 pivot**，部件 `parent_type='BONE'` 刚性挂接
   - 已在你发冠/武器上验证：零变形、零权重、程序化可靠
3. **骨骼只做旋转/位移，不做蒙皮变形** → 100% 无 auto-weight 风险
4. 个别需柔感的部位（宽袍/裙摆/袖）→ B-Bone 细分 + Envelope 或小范围权重，无需全局完美
5. 全流程参数化：pivot 位置、旋转角度、相机运动全走 Python → 批量可复现
