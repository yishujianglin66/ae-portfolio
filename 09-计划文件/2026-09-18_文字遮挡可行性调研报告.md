# 文字遮挡（文字从人物后面穿过）可行性调研报告

**日期**：2026-09-18
**动机**：文字线四轮审美迭代后确认"高级感"最缺的一块是**文字与画面的融合**——
其中最有效单项是**文字被前景人物遮挡**。本报告按"完美调研、闭环后再执行"的要求，
完成选型比对与本机实证，给出 go/no-go 与执行计划。

## 二、网络根因与解法（重要，普适）

**症状**：代理退出后"全网不可达"（连 modelscope/清华源都失败），但 ping/TCP 直连全通。

**根因**：本机开过代理（注册表 `ProxyServer=127.0.0.1:7897`）。代理进程退出后
`ProxyEnable` 仍=1 → Python urllib 按系统代理把所有请求塞进**死端口**。

**解法**：`urllib.request.ProxyHandler({})` 显式空代理=直连，不读注册表。
实测直连可达：`dl.fbaipublicfiles.com`（SAM2 官方 CDN）、GitHub（codeload/raw/clone）、
`hf-mirror.com`、`modelscope.cn`。**SAM2 权重根本不需要代理。**

**git clone 会中途断**（`early EOF`，网络 0.3MB/s 且不稳）→ 改用 **codeload tarball + Range 断点续传**（实测 53MB/114s 成功）。

### SAM 2.1 tiny 在我们素材上的实证（三轮，全部落空）

对 3 帧真实成片帧（8.5s 清晰人物 / 25.5s 火焰场景 / 14.5s 特效场景）：

| 策略 | 覆盖率（3 帧） | score | 目视判读 |
|---|---|---|---|
| 自动方框（中央 60%） | 10.9%/17.0%/18.8% | 0.62–0.79 | **圈到背景/火焰，未贴角色** |
| 单正点（画面中部） | 1.7%/1.1%/5.7% | 0.77–0.92 | 抓到点附近**局部碎片** |
| 多正点+负点（手工选点） | 61.7%/3.4%/5.9% | **0.13**/0.67/0.57 | 最好一帧**过分割糊进背景**，其余仍碎片 |

**结论**：SAM 2.1 tiny 对本片素材（动漫线稿 + 重度模糊/特效 + 高饱和）**不能可靠产出可用的角色 mask**。与"SAM 2 训练于自然视频"的已知限制一致；我们的素材又特别难（细节在剪辑阶段已损失 10 倍，见前一附录）。

## 六、结论

1. **基建全部闭环**：GPU/依赖/下载通道/推理/导出全通，且发现并解决了"系统代理残留导致全网假性不可达"这个会反复坑人的环境问题。
2. **质量不闭环**：SAM 2.1 tiny 三种提示策略在我们的素材上全部失败——这是有数据的否定结论，不是猜测。
3. **下一步的最短路径**是拿到动漫专用的 ISNet（ Apache-2.0，专为动漫角色训练），它若单帧质量过关，再与 SAM2 的视频传播组合解决时序。

## 执行结果（2026-09-18 当晚，全部闭环）

### ① ISNet 下载（步骤②）

正确模型仓库是 **`skytnt/anime-seg`**（README 链接指向它；`anime-segmentation` 是数据集名，
此前 404 的根因）。经 hf-mirror 直连下载 `isnetis.onnx` 167MB（542s @ 0.3MB/s，断点续传）。

### ② ISNet 质量（步骤③）——关键分叉

| 素材类型 | 结果 |
|---|---|
| 干净源素材帧（猫2/五条悟源） | **正常**：18.6% / 9.0% 覆盖，mask 贴住角色 |
| 成片帧 3 帧试测 | 8.5s 帧正常（29.6%，mask 贴人物）；火焰帧/特效帧 **0.0%** |
| 成片 30 帧全扫描 | **43% 帧检出角色**（覆盖≥5%），其中多帧覆盖 35–96% |

**结论**：ISNet 本身工作正常；**成片上的失败集中在被剪辑处理破坏的镜头**（火焰/特效/高糊段）。
这再次印证"细节损失在剪辑阶段"的诊断——同一条根因的第三个症状。

**架构决策**：不追求全帧覆盖。**按事件窗做置信门控**——只对"检出覆盖≥阈值且窗内稳定"的
事件启用遮挡；其余事件保持现状（本来就没有可靠的人物前景，无需遮挡）。

### ③ AE track matte API 探针（步骤①）——通过

- `layer.trackMatteType = TrackMatteType.ALPHA` **可写且生效**（像素级验证：圆内绿/圆外黑）。
- **枚举名陷阱（实证）**：`TrackMatteType` 的合法成员是 `NO_TRACK_MATTE(5012) /
  ALPHA(5013) / ALPHA_INVERTED(5014) / LUMA(5015) / LUMA_INVERTED(5016)`——
  **没有** `*_MATTE` 后缀的成员（`ALPHA_INVERTED_MATTE` = undefined，首跑即栽在这）。
- `setTrackMatte` 方法**存在**但未单独验证；用 `trackMatteType` 赋值即可。

### ④ 端到端验证（步骤⑤的核心）——通过

对事件 #14（18.62–19.47s，IMPACT @700,380，落在扫描中覆盖率 96% 的区段）做了完整链路：

```
底片 → ISNet 逐帧分割(27帧 mask PNG) → AE: 视频+文字+mask序列三层合成
     → 文字层 trackMatteType=ALPHA_INVERTED → aerender 27 帧
```

**证据**：`render/occlusion_e2e_proof.png`（三时刻 × 成片/mask 对照）——
左列可见 IMPACT 文字的下半段被前景人物的剪影裁掉，右列同帧 mask 与人物位置吻合。
`render/occlusion_e2e_test.mp4` 为动态版本。

**已知口径问题（诚实记录）**：e2e 测试合成用默认输出模块渲出，与母版的色彩管理不匹配
（全帧 100% 像素有偏移），所以"文字区亮像素 0.83→0.0"的数字**不可信**，判读以 proof 图目视为准。
正式集成时把遮挡层挂进 `run53_text_v50.aep` 的管线合成即可消除该口径问题。

### ⑤ 剩余工作（下一步）

1. 集成进 `build_text_overlay.py`：读事件表 → 对每个事件窗跑 ISNet → 置信门控
   （覆盖≥15% 且窗内中位≥10%）→ 生成 mask PNG 序列 → 注入 JSX（导入序列+设 trackMatteType）。
2. 全片渲染 + 与 v50 同帧 A/B 验收。
3. 预估：集成 2–3 小时（含每帧 ~1s 的 ISNet 推理 × 19 窗 × ~30 帧 ≈ 10 分钟）。

**判定：方向从"调研"转为"实施"——技术链路全通，剩工程集成。**
