**行业共识（三个被反复验证的结论）**：

1. **后训练是 Agent 能力的核心杠杆**——DeepSeek V4-Flash 架构参数不变、仅重做后训练就全面反超 Pro 预览版；GLM-5.3 基座不变、后训练 Scaling 提升 50%
2. **模型能力已经无法与 Harness 分离**——Kimi K3 评测混合使用多种 Harness；DeepSeek 直接把自己的 Harness 开源，"Agent = Model + Harness"
3. **长程稳定执行是当前所有模型的软肋**——VibeBench 上 Claude Opus 5 / GPT-5.5 均不及格；各家都把"数小时持续执行"作为主攻方向

## 三、实验室级推进架构（三层实验室闭环）

把散落的管线能力重组为**执行层 / 观测层 / 学习层**三层实验室架构，每层有明确组件与接口：

```
┌─────────────────────────────────────────────────────────┐
│ 学习层（Learning Layer）                                  │
│  数字孪生校正 ← 经验质量门(M10) ← ExperienceRecord       │
│  自进化引擎规则蒸馏 ← 失败重放用例库(M5) ← 回归测试集      │
│  任务合成器(M6): 知识库 → 新测试任务                      │
├─────────────────────────────────────────────────────────┤
│ 观测层（Observation Layer）                               │
│  events.jsonl 事件流(M7,M12) ← 唯一事实源                 │
│  ├→ 数字孪生（ExecutionObservation 消费）                 │
│  ├→ 经验收割器（FlagshipManifestParser 消费）             │
│  ├→ 轨迹回放/复盘工具                                     │
│  └→ 实验室周报（度量自动汇总）                             │
│  critic_reports(M1,M4,M8): 中途自评 + 过程质量 + 证据链    │
├─────────────────────────────────────────────────────────┤
│ 执行层（Execution Layer）                                 │
│  flagship_runner S0~S7（天然宏步）                        │
│  ├→ StageCritic 边界自评节点(M1)                          │
│  ├→ 阶段检查点(M2): 失败可续跑                            │
│  └→ 候选比较(M-TEMPO): 低成本采样排序后全量渲染            │
└─────────────────────────────────────────────────────────┘
```

**与原 TEMPO 方案的关系**：原方案的 P0-1（StageCritic）、P0-2（失败回流）、P0-3（原子化）全部保留并升级——
- StageCritic 增加 M4 过程质量维度、M8 证据链字段
- 失败回流的载体从 manifest 扩展字段升级为 events.jsonl 事件流（M7）
- 原子检查项改为插件化注册（M11），支持热插拔新检查项

## 五、模型选型矩阵（实验室用脑配置）

本项目不自部署大模型（无多卡 GPU），全部走 API。按任务类型分配：

| 任务类型 | 首选模型 | 备选 | 理由 |
|------|------|------|------|
| 视觉自评（渲染产物抽帧/视频片段） | dots3-note（API） | Qwen3.8-Max | 唯一轻量多模态且视频含音轨；Qwen 更贵但联网搜索强 |
| 高频批量文本任务（素材标注/知识抽取） | DeepSeek V4-Flash | GLM-5.3（API 上线后） | 输出价 $0.28/M，便宜 21 倍且 Agent 能力接近 Opus |
| 长程编码/管线脚本开发 | Kimi K3 API | GLM-5.3 | 开源第一的编码 Agent，1M 上下文装得下整个管线 |
| 最难推理/创意决策 | Qwen3.8-Max | Grok 4.6（贵，慎用） | AA 53 分，格式对齐最好 |
| 本地编排/日常 | 已部署 DSH + V4-Pro | — | 本地插件生态（AE/PR/知识库 MCP）已接入 |

**接入动作**：全部经 `core/llm_gateway.py` 统一路由，新增 `model_router` 按任务类型字段自动选择（P1 任务）。

## 七、实验室级度量体系（验收与追踪）

| 度量 | 基线（当前） | Phase 0 目标 | Phase 2 目标 |
|------|------|------|------|
| 末端质量门失败率 | 100% 故障在 S7 暴露 | 50% 故障被中途拦截 | ≥80% 中途拦截 |
| 故障平均发现成本 | 全流程耗时 | 降低 40% | 降低 70% |
| 回流样本密度 | 1 观测/run | 4+ 观测/run（中途观测） | 6+ 观测/run |
| 数字孪生预测误差 | 成功率预测 0.31（校正后） | 收敛提速 3 倍（样本密度证据） | 平均绝对误差 <0.1 |
| 回归用例增长 | 手工维护 | +故障重放自动生成 | 每周 ≥3 条自动用例 |
| 经验污染率 | 未度量 | 建立隔离区，污染样本可追溯 | 隔离样本 <5% |

## 八、风险与边界

1. **API 依赖风险**：选型矩阵全部依赖外部 API，价格/可用性会变——llm_gateway 保持多供应商可切换，选型矩阵作为活文档每月复核
2. **过度工程风险**：三层架构按 Phase 逐步建，每 Phase 有独立验收；Phase 0 未通过验收前不启动 Phase 1
3. **DSH v0.1 稳定性**：已知子代理 bug，实验室编排任务一律用 headless 模式，不在 Web UI 跑多步任务
4. **评测公正性**：实验室周报数字全部来自 events.jsonl 自动统计，不允许手工修饰——可审查性是实验室级的前提（M4 精神）
5. **许可证**：Kimi K3 权重需商用授权审查；AREX/CutClaw 类项目引用前核验 LICENSE（延续此前审美调研的教训）
