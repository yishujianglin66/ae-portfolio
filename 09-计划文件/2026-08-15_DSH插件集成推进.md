## 二、配置改动明细（`C:\Users\Administrator\.dsh\profiles\web\`）

1. **package.json**
   - `dependencies` 新增 4 个包（dsh-voice-webspeech / dsh-vision-proxy / dsh-bilibili / dshmarket）
   - `dsh.profile.bundles` 追加上述 4 个包名（bundle patch 契约激活）
2. **pnpm-workspace.yaml**
   - `allowBuilds` 新增：dsh-voice-webspeech@codeload-URL、dshmarket@git#hash、`onnxruntime-node: true`、`sharp: true`
   - （原因：pnpm 11 拦截 git 依赖 prepare 脚本；onnxruntime/sharp 为 bilibili 本地 ASR 与 vision-proxy 缩图的构建依赖）
3. **cordis.patch.yml**
   - 新增 `dsh-vision-proxy` 覆盖行：baseURL→`https://api.siliconflow.cn/v1`、model→`Qwen/Qwen3-VL-30B-A3B-Instruct`（later layers win per row，覆盖 bundle 默认 DashScope 配置）
4. **环境变量（User 级，注册表）**
   - `VISION_API_KEY` = 项目 .env 中的 SILICONFLOW_API_KEY（值未落盘到任何配置文件）
   - 说明：.env 里的 `DASHSCOPE_API_KEY` 是空占位，唯一可用视觉 key 是 SiliconFlow，故端点切换而非用默认 DashScope
5. **备份**：改动前 4 个文件快照在 `profiles\web\.backup-20260815-110650\`

## 三、重启与验证（需人工执行）

1. 重启 web profile：关闭当前 DSH GUI 后重新运行 `dsh web`（**对侧未重启，避免打断当前会话**）
2. 验证清单：
   - [ ] 输入框旁出现麦克风按钮（语音输入），Edge 下说中文→识别进输入框
   - [ ] Settings → Plugins 出现插件市场（dshmarket）
   - [ ] 发一个 BV 号，模型可调用 `bilibili_extract` 分析（首次会自动跑环境体检）
   - [ ] 模型设置中把路由切到 `deepseek-vision`（vision-proxy 注册的新 provider 路由），贴一张渲染帧截图 → 对话中出现 `[图片转译]` 文字描述；启动日志的 PRIVACY NOTICE 应显示 siliconflow 端点
3. 若 vision-proxy 未走 SiliconFlow（仍报 DashScope）：检查启动日志 PRIVACY NOTICE 端点；同 id 双行若未被合并，可把覆盖行改为直接编辑 bundle 默认行（先记录再动）
