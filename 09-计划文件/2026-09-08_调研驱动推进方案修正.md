## 二、机制级发现：规则蒸馏的国际同构（增强信心的证据）

本项目"经验→规则→A/B 证伪→投票退场→自动回退"不是土法炼钢——调研确认与三个独立前沿同构：

1. **ExpeL（AAAI'24，LeapLabTHU）**：成功/失败轨迹对比归纳 insight，ADD/EDIT/UPVOTE/DOWNVOTE 增删——与 R-2026-0001/0002 生命周期同构。**其教训：反思型 insight 直接入库反而掉点，必须经其他轨迹检验**——印证本项目"投票翻负即 standby"设计的正确性。
2. **AutoGuide（ExpeL 后继）**：insight 带"适用状态描述"，运行时按当前 state 检索匹配——正是本项目 applicability schema 的进化方向：**从"全量注入+白名单裁决"升级为"状态条件检索"**。
3. **Agent Skills 开放标准（Anthropic，2025.12 发布，20+ 产品采纳）**：SKILL.md = YAML frontmatter + Markdown，三级渐进披露——**ruleset.jsonl 的 schema 可直接对齐 frontmatter 字段（name/description/metadata），规则正文渐进加载**。

**结论**：规则蒸馏机制的下一步不是发明新东西，而是向这三个成熟范式对齐（详见 §三-R8）。

## 三、修正后推进方案（八条主线）

### R1 · 主攻 cut_visibility 结构性差距（不变，第一优先）
- 撞击帧内容方案（AEKV_IMPACT_SHIFT=1）+ 先修 tmp/post_freeze.py 滤镜图 bug
- **新增**：冲击帧设计参考 video-use 的"每个切点 self-eval"范式——撞击帧生成后即时评分，不合格自动换帧，不再等整体评分
- 验收线不变：cut_visibility 0.870 → ≥0.92

### R2 · 评估体系升级（修正）
- 参照集 13→50+（不变）；人类盲评协议（不变）
- **修正**：异源评分器选型 = DOVER（内部基准，注意 S-Lab 非商用仅限评测研究用途）+ VideoScore（MIT，对外可用）；VLM 异源评分保留为第三路
- 验收线：三路评分器对 50 部参照集的斯皮尔曼相关性 ≥0.7，否则评分器不可作为闸门

### R3 · 素材检索三档升级（修正）
- **档1（1 周）**：BGE-M3 保留 + **bge-reranker-v2-m3** 二阶段重排。验收线 recall@10 ≥0.70
  - **⚠️ 2026-09-08 晚实测结论**：验收线字面上通过（重排后 0.975），但**基线在伪标签扩充索引（1075 条）下已饱和至 1.000**——0.400 是 38 条索引时代的旧测量，基准对改动失去判别力；重排器无可测正收益且对无别名锚定的情绪查询有负收益（"热血战斗"1.0→0.5）。**决策：不接入生产**。证据：`output/evidence/r3_tier1_rerank_20260908/`。**档2/档3 前置：先硬化基准**（查询 20→50+ held-out 措辞、帧级 nDCG/MAP、混淆集），否则换模型测不出差异。
  - **✅ 基准 v2 已完成并再修正（同日晚）**：`ai/r3_benchmark_v2.py`（36 条 held-out + nDCG/MRR + 四臂）。**推翻档1 初判**：重排器在难查询上有真实收益（纯语义池+重排 R@10 0.400 vs 纯语义 0.286，+11.4pp）；关键词通道在自然语言查询上是负资产（hybrid 0.267 < 纯语义 0.286）；真正瓶颈是"词袋文档 vs 自然语言查询"的语义鸿沟。档1 验收线按 v2 重定标：0.70→0.40（已达），档2 目标 ≥0.55、档3 ≥0.70。接入策略建议分流：别名命中走原链路、自然语言走纯语义+重排（开关默认关）。证据：`output/evidence/r3_benchmark_v2_20260908/`。
- **档2（2 周）**：**Qwen3-Embedding-0.6B + Qwen3-Reranker-0.6B** 整套替换（Apache 2.0）。验收线 ≥0.78
- **档3（3 周）**：**InternVideo2-CLIP**（1B fp16 ≈2GB 显存，Apache 2.0）加视频-文本跨模态向量，与文本检索做倒数排名融合（RRF）。验收线 ≥0.80
- 每档独立 evidence 落盘，不可跳档声明

### R4 · 第二母版泛化验证（不变，与 R3 并行）
- 叙事向/慢节奏 BGM 全链跑通，验证 R-2026-0002 applicability 域
- **新增**：B 站 YouTube 各一部异风格参照进集，第二母版 beat_hit_rate ≥ 该曲风参照中位数

### R5 · 生成能力最小闭环（修正选型）
- **商用路线**：Wan2.2-TI2V-5B，GGUF Q4（7-9GB 实测 720p@24fps，Apache 2.0），ComfyUI 原生模板集成
- **自用探索**：LTX-2 蒸馏 GGUF（≈8GB，权重 Community License 需自用边界声明）
- **明确排除**：MiniMax H3 全系（显存 21GB 超物理边界 + 许可证限制）——09-06 调研的 BSA/Comfy Compiler 不适用本项目
- 验收线不变：生成镜头混入后语义分非劣；**新增闸门**：显存峰值实测 <8GB 落盘（超界即降 Q 档或 offload，禁止"勉强能跑"）

### R6 · 工程补课（不变 + 产物治理并入）
- 产物治理按《产物治理扫描报告_2026-09-08》执行（C1-C6 候选 42-44 GB，待 Boss 确认）
- 修 unified_edit.py:199 F821；31 项未提交变更按三批方案落库；P1-B 覆盖率采集

### R7 · 音乐链补强（新增）
- **Demucs**（Meta，MIT）：与 Mel-Band RoFormer 对比评测，胜出则替换或双轨（stem 质量是锚点链的根）
- **beat_this**（CPJKU，MIT，2024 最新）：替换 madmom/librosa onset 链，精度更优
- **all-in-one**（Apache 2.0）：intro/build/drop 结构分段自动化——规则 applicability 的 bgm_structure 从人工标注改为模型输出
- **whisperX**（MIT）：歌词词级时间戳，为"歌词锚点"类规则铺路
- 验收线：beat_this vs 现有链的 beat_hit_rate A/B 对比（同口径评分器）；结构分段与人工标注一致率 ≥85%

> **R7 A/B 结论（2026-09-10 补记，证据 `reports/r7_beat_ab.json`，3 BGM 同口径实测）**：
> 1. **不整体替换 onset 链**——librosa 网格规整度显著更优（拍间隔 CV 0.036 vs 0.155），两法拍点分歧大（匹配率 0.31/0.46/0.76，3 首中 2 首 <0.5），且现链已被 beat_hit_rate 0.85+ 验证过；
> 2. **下拍通道按需引入**——beat_this 提供 4/4 下拍（22/35/90 个/首）而现链为零，这是唯一结构性优势；仅当 R-2026-0002 类网格量化规则需要下拍锚时，以"旁路附加输出"方式接入（不做主链替换）；
> 3. all-in-one 结构分段与 whisperX 歌词轴维持原计划（结构分段进 2026-09-10 计划波次4），Demucs 对比未启动、按需排期。

### R8 · 规则蒸馏机制向国际范式对齐（新增，机制升级）
- **① schema 标准化**（1 周）：ruleset.jsonl 对齐 Agent Skills frontmatter 字段；规则正文改为渐进披露（元数据先行、正文按需加载）
- **② 适用域检索化**（2 周）：引入 AutoGuide 式 state-conditioned 检索——规则不再全量注入，按当前 run 的（时长/曲风/能量层）向量匹配适用规则
- **③ GEPA 归纳路径**（acceptance_log 积累 ≥30 条后启动）：DSPy GEPA 消费验收日志反射生成候选规则 → 强制过 A/B 证伪 + 冻结验证集回归 → 才能进 active（沿用现有生命周期，GEPA 只产候选不直插）
- 验收线：GEPA 产出的首批候选规则中 ≥1 条通过完整生命周期进 active
