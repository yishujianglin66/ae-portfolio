# 骨骼层级设计（Root→Hips→Spine→Chest→Neck→Head + 四肢）

## 问题场景

为无骨骼FBX模型程序化创建骨骼时，需要设计合理的层级结构。层级决定了权重分配的有效性、动画变形的自然度、以及附件归位的参考坐标系。

## 核心原理

### 本项目使用的16骨骼层级

```
Root (地面中心)
└── Hips (骨盆, 模型50%高度)
    ├── Spine (脊柱)
    │   └── Chest (胸腔)
    │       ├── Neck (颈部)
    │       │   └── Head (头部, 模型85%高度)
    │       ├── UpperArm_L → ForeArm_L → Hand_L
    │       └── UpperArm_R → ForeArm_R → Hand_R
    ├── UpperLeg_L → LowerLeg_L → Foot_L
    └── UpperLeg_R → LowerLeg_R → Foot_R
```

### 骨骼位置计算（基于模型高度）

def calculate_bone_positions(model_height=6.0):

        'UpperArm_R': {'head': (-h*0.12, 0, h*0.72), 'tail': (-h*0.25, 0, h*0.72)},

### 层级设计原则

1. **Root在地面**：所有变换的基准点
2. **Hips在重心**：模型50%高度，动画时整体平移的参考
3. **脊柱分段**：Spine/Chest分段允许躯干弯曲
4. **Head足够高**：发冠parent到Head时需要正确的TAIL位置
5. **手臂水平（A-pose）**：与FBX网格的A-pose匹配
6. **左右对称**：X轴正负对称

## 常见陷阱

| 陷阱 | 后果 | 解决 |
|------|------|------|
| 骨骼位置与网格不匹配 | 权重分配错误，变形异常 | 基于实际顶点分布计算位置 |
| 手臂骨骼角度与网格不一致 | A-pose网格绑到T-pose骨骼 | 保持骨骼与网格同姿态 |
| Head骨骼太短 | 发冠parent后偏移 | Head length ≥ 模型高度15% |
| 缺少Root骨骼 | 整体动画无参考点 | 始终创建Root作为最顶层 |
| 骨骼命名不规范 | 后续代码按名称查找失败 | 使用标准命名（Hand_R等） |
