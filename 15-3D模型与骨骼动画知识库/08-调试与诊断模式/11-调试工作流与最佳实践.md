# 调试工作流与最佳实践

## 问题场景

系统化的调试工作流可以大幅提升问题定位效率。本文总结Blender脚本调试的最佳实践：从问题复现、日志分析、隔离测试到修复验证的完整流程。

## 核心原理

### 调试工作流

```
┌─────────────────────────────────────────────────────────┐
│                    调试工作流                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 问题复现                                            │
│     ├── 记录错误信息（完整traceback）                   │
│     ├── 记录执行环境（Blender版本、参数）               │
│     └── 确认复现步骤                                    │
│                                                         │
│  2. 日志分析                                            │
│     ├── 解析错误类型和位置                              │
│     ├── 查看上下文日志                                  │
│     └── 对比正常/异常日志                               │
│                                                         │
│  3. 假设与验证                                          │
│     ├── 提出可能原因假设                                │
│     ├── 设计验证实验                                    │
│     └── 执行最小化测试                                  │
│                                                         │
│  4. 修复与测试                                          │
│     ├── 实施修复                                        │
│     ├── 回归测试（确保不破坏其他功能）                  │
│     └── 边界测试（不同模型/参数）                       │
│                                                         │
│  5. 文档记录                                            │
│     ├── 记录问题原因                                    │
│     ├── 记录解决方案                                    │
│     └── 更新知识库                                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 二分法定位

```python
# 当管线某处出错，用二分法快速定位

# 步骤1：确定问题范围
# 完整管线：导入 -> 骨骼 -> 权重 -> 归位 -> 渲染
# 问题：渲染结果错误

# 测试中间点：权重分配后dump状态
# 如果状态正确 -> 问题在归位或渲染
# 如果状态错误 -> 问题在导入、骨骼或权重

# 步骤2：继续二分
# 归位前dump -> 归位后dump
# 对比差异定位具体问题

def binary_debug(pipeline_stages):
    """二分法调试"""
    for i, stage in enumerate(pipeline_stages):
        print(f"\n[STAGE {i+1}/{len(pipeline_stages)}] {stage['name']}")
        
        # 执行阶段
        stage['func']()
        
        # 验证
        if not stage['validate']():
            print(f"[FAIL] Stage {stage['name']} failed validation")
            return stage['name']
        
        print(f"[OK] Stage {stage['name']} passed")
    
    return None  # 全部通过

# 使用
stages = [
    {'name': 'Import', 'func': import_fbx, 'validate': check_import},
    {'name': 'Bones', 'func': create_bones, 'validate': check_bones},
    {'name': 'Weights', 'func': assign_weights, 'validate': check_weights},
    {'name': 'Reposition', 'func': reposition, 'validate': check_position},
    {'name': 'Render', 'func': render, 'validate': check_render},
]

failed = binary_debug(stages)
if failed:
    print(f"Problem isolated to: {failed}")
```

# 2. 断言检查
def create_bone(armature, name, head, tail):
    """创建骨骼（带断言）"""
    assert armature is not None, "Armature is None"
    assert name, "Bone name cannot be empty"
    assert len(head) == 3, f"Head must be 3D vector, got {head}"
    assert len(tail) == 3, f"Tail must be 3D vector, got {tail}"
    assert Vector(head) != Vector(tail), "Head and tail cannot be same"
    
    bone = armature.edit_bones.new(name)
    bone.head = head
    bone.tail = tail
    return bone

from typing import Optional, List, Tuple

    """获取顶点列表"""

### 日志级别策略

```python
# 开发阶段：DEBUG（详细）
# 测试阶段：INFO（关键步骤）
# 生产阶段：WARNING（只记录问题）

import os

def get_log_level():
    """根据环境获取日志级别"""
    env = os.environ.get('PIPELINE_ENV', 'development')
    
    levels = {
        'development': 'DEBUG',
        'testing': 'INFO',
        'production': 'WARNING',
    }
    return levels.get(env, 'INFO')

# 使用
LOG_LEVEL = get_log_level()

def log(msg, level='INFO'):
    levels = {'DEBUG': 0, 'INFO': 1, 'WARNING': 2, 'ERROR': 3}
    if levels.get(level, 1) >= levels.get(LOG_LEVEL, 1):
        print(f"[{level}] {msg}")
```

## 常见陷阱

### 陷阱1：修改后未重新测试
```python
# 修复一个问题后，确保：
# 1. 原始问题确实修复
# 2. 没有引入新问题
# 3. 其他模型/参数也正常
```

### 陷阱2：只修复症状不修复根因
```python
# 错误：绕过问题
if bone_name not in armature.bones:
    bone_name = "default"  # 绕过，但根本问题未解决

# 正确：找到为什么bone_name不存在

```
