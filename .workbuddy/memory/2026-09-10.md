### v2 验收口径的幸存者偏差（灾难级发现）
- v2 用 ffmpeg 场景检测发现切点，**只给"本来就合格的切点"打分**，坏切点被静默丢弃
- run61 自有检测器已判定 132 issues（frozen 76 + audio_pop 56），但 v2 报"v2=1.05/frozen 2.94%"自我表扬
- v3（`scripts/cut_visibility_v3.py`）以 EDL 声明切点为分母重写：`frozen_rate = frozen/n_declared`
- 实测对照（v3）：

  | 视频 | v3 | frozen |
  |---|---|---|
  | run61_final (Python 渲染) | 0.4001 | **72.9% (78/107)** |
  | master_hr (AE 渲染) | 0.8405 | 29.9% |
  | repair62 (重渲新 EDL) | 0.9166 | 22.2% |

  → Python 渲染链 73% 切点没换画面——**不是度量误差，是渲染 bug**。

### 根因：_tl_drift 累加器失控（run61 实测 49.62s vs plan 30s，+19.62s 漂移）
- `_extract_clip` 对慢放段 (speed<1) 算 `read_dur = duration * speed`，
  输入窗口 < 输出帧所需；30fps 源经 `fps=24` 重采样后输出帧数 < out_frames，
  但 ffmpeg `-frames:v` 按 out_frames 计期望 → `_ad < render_dur`
- `drift += render_dur - _ad` 持续累加，无衰减
- 漂移巨大后 `_extract_clip` 边界保护 `start_time = src_dur - read_dur`
  把 source_start 推回素材尾/头 → 多段坍塌到同一画面 → 切点冻结

### 修复（committed）
- `ai/production_director.py:4079` 加 `_TL_DRIFT_LIMIT = 2.0/24.0`（±83ms）+ 钳制逻辑
- `tests/test_rl_drift_clamp.py` 4 个用例全过：
  - 旧逻辑 108 段灾难场景漂移 3.24e34s（失控）
