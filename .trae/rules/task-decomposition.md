# 任务拆分与子智能体策略

## 核心原则：一次 Query 多做事
TRAE 速通次数按 Query 计数（1 Query = 1 次），同一 Query 内的拆分请求不额外计费。
因此**优先将多个相关任务合并到一个 Query 中**，而非分多次发送。

## 任务拆分决策树
收到任务时，按以下优先级处理：

### 级别1：直接执行（不拆分）
- 单文件修改、单函数实现、简单 bug 修复
- 预计 < 100 行代码变更
- 只涉及一个模块

### 级别2：批量合并（一个 Query 多任务）
- 多个独立的小修改（改字段名、加注释、调参数）
- 同一模块的多处改动
- **策略**：在单个 Query 中列出所有任务，让 AI 一次性完成

### 级别3：子智能体派发（Task 工具）
适用于以下场景，必须使用 `Task` 工具派发：
- 跨多个模块的大型重构
- 需要并行探索代码库的多个区域
- 产出大量中间结果但最终只需摘要
- 独立的功能开发（前端+后端+测试）

**子智能体使用规范**：
```
Task 工具调用时必须：
1. 提供完整的任务描述（子智能体看不到主对话上下文）
2. 指定 subagent_type（search 用于研究，general_purpose_task 用于编码）
3. 明确期望的输出格式
4. 并行启动多个独立子任务
```

### 级别4：分阶段执行（多 Query）
- 需要用户确认的架构决策
- 依赖前一步结果的链式任务
- **策略**：每阶段结束暂停，等用户确认后再继续

## 模型选择策略
根据任务复杂度选择模型，降低排队概率：

| 任务类型 | 推荐模型 | 理由 |
|---------|---------|------|
| 架构设计/算法设计 | Claude 3.5 Sonnet | 推理能力强 |
| 多文件重构 | Claude 3.5 Sonnet | 上下文理解好 |
| 单文件实现 | Auto 模式 | 自动选合适模型 |
| 简单修改/注释 | Auto 模式 | 轻量任务排队少 |
| 文档编写 | Auto 模式 | 不需强推理 |
| Debug 复杂问题 | Claude 3.5 Sonnet | 需要深度分析 |

## 上下文管理
- 单个对话不超过 20 轮，超过应开新会话
- 使用 `#文件路径` 精确引用，避免让 AI 扫描全项目
- 长对话接近上限时，主动总结当前进度后开新会话继续
- 子智能体的探索结果不会占用主对话上下文
