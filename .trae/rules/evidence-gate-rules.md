# 证据闸门铁律 - 禁止纸面结论进入执行链

> 源自 2026-08-18 WorkBuddy 失实结论事故的复盘（证据: `output/evidence/workbuddy_claims_audit_20260818.json`）。
> 当日三大失实: "62引擎待同步"（实测差异=0）、"BiRefNet/FATE 资产缺失"（实测 844MB/445MB 均在位）、
> "6类重训 YAML 就绪"（底模/数据路径/类名/架构/启动脚本五项全虚构，270 行细节无一可执行）。
> **细节丰富度与证据真实度无关**。任何 AI 会话（含 WorkBuddy/子智能体）产出的结论进入执行链前，必须过以下五道闸门。

---

## 闸门 1：存在性闸门（READY 声明的前置条件）

任何配置/计划被标记为"就绪 / READY / 可执行"前，**必须**附一键存在性检查的实际输出：

```python
# 最低标准：所有被引用路径 exists == true 才能标 READY
import pathlib
paths = ["models/xxx.pt", "data/xxx.jsonl", ...]  # 配置中引用的全部路径
for p in paths:
    print(("OK  " if pathlib.Path(p).exists() else "MISS"), p)
```

- 任一路径 MISS → 状态强制为 `PLAN`，禁止标 `READY`
- 检查目标是**文件系统**，不是 git 索引（.gitignore 排除的大文件仍在磁盘上，
  "git 里没有" ≠ "磁盘上没有"——2026-08-18 BiRefNet 844MB 被误判"缺失"即此盲区）

## 闸门 2：首行证据（数据驱动决策的强制动作）

任何基于数据的决策（训练方案/分布分析/根因归因），**必须**先打印真实数据的样本：

- jsonl → 打印首行完整字段 + `collections.Counter` 类别分布
- 模型权重 → `torch.load` 后打印 keys 数量 + 首末层 shape
- 视频素材 → `os.path.getsize` + 实际时长探测

**禁止**凭记忆、凭旧报告转述、凭文件名推测描述数据内容。
反面案例: YAML 写了 `diag_pan` 类，而真实标签里该类不存在、`orbit` 仅 7 条——
读一次真实分布（3 秒）即可揭穿。

## 闸门 3：任务签名三对齐（训练/管线配置互证）

训练配置（及一切 模型×数据 任务）落地前，**必须**三者互证通过：

```
模型架构签名（num_labels / 输入尺寸 / 任务类型）
  × 数据路径签名（真实数据文件的字段与类别清单）
  × 配置类名清单（YAML/argv 中的 classes）
→ 三者交集一致才算对齐
```

- 特别警惕**任务身份混淆**：IP 分类 ≠ 运镜分类 ≠ 风格分类，
  底模 checkpoint 的任务类型必须与当前任务一致
- 类名清单必须来自闸门 2 的实测分布，禁止手写 invented 类名

## 闸门 4：快照失效即结论失效（时间戳纪律）

- 分支差异 / 未跟踪文件 / 同步状态类结论，**必须**携带生成时间戳落盘
- 该时间戳之后的**任何 git 提交/检出操作**，使相关结论自动降级为"待重测"，
  后续会话禁止引用降级结论作为决策依据
- 反面案例: "62 引擎待同步"来自提交前快照（48 个文件路径，且文件数被说成引擎数），
  提交完成后快照已失效，但结论仍被写进交接清单继续传播

## 闸门 5：纸面/可执行分级（PLAN ≠ READY）

- `PLAN`（纸面方案）与 `READY`（dry-run/冒烟通过）**强制分级**，不可混用措辞
- 升级为 READY 的唯一路径：真实 dry-run（训练=小样本冒烟；脚本=AST+import+执行；
  渲染=单帧输出）
- **验收报告只能引用 READY 级产物**；PLAN 级内容只能出现在"规划"章节
- 报告的视觉完整性（HTML/JSON 体积）不构成任何证据效力

## 执行检查清单（会话收尾自查）

1. 本次所有"XX 就绪"声明是否都附了存在性检查输出？
2. 数据结论是否都见过真实首行/分布？
3. 训练/管线配置是否过了三对齐？
4. 引用的分支差异/资产状态结论是否在时间戳之后未被提交操作作废？
5. 交付清单里每一项是 PLAN 还是 READY，是否标清？

任何一条不满足 → 回补证据，不得带病交付。
