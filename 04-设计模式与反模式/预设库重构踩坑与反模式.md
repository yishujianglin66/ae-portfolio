# 预设库重构踩坑记录与反模式

> 版本: v1.0 | 日期: 2026-07-27

## 一、字体PostScript名静默替换 (Critical)

### 现象
在AE中设置 `TextDocument.font = "SomeFont-Bold"` 后，AE不会报错，而是**静默替换**为默认字体（通常是Myriad Pro或Adobe Clean）。脚本执行显示"成功"，但渲染出来的字体完全不对。

### 根因
- AE的字体系统使用**PostScript Name**（如 `SourceHanSansSC-Bold`），而非显示名（如"思源黑体 Bold"）
- 同一字体族的不同字重有独立PostScript名（`-Bold`/`-Heavy`/`-Light`）
- 中文字体的PostScript名规则不统一：方正用`FZ`前缀、华文用`ST`前缀、汉仪用`HY`前缀
- 某些字体安装了但AE的`app.fonts.allFonts`枚举不到（需重启AE）

### 验证方法
```javascript
// probe30_font_registry.jsx 核心逻辑
var td = textLayer.property("Source Text").value;
td.font = candidatePostScriptName;
textLayer.property("Source Text").setValue(td);
// 读回验证
var actual = textLayer.property("Source Text").value.font;
if (actual === candidatePostScriptName) { /* OK */ }
else { /* FAIL - 被静默替换为: actual */ }
```

### 防御策略
- **永远先跑字体探针**，不要假设字体名正确
- 在jsx_template中使用已验证的PostScript名，不用显示名
- 批量分配后执行去重检查（本次发现3对重复）

## 二、插件matchName不匹配 (High)

### 现象
`layer.Effects.addProperty("Saber")` 失败，但AE菜单里明明能看到Saber。

### 根因
- AE效果的**显示名**和**matchName**经常不同
- 第三方插件的matchName由开发者自定义，无统一规则

### 已确认的matchName映射
| 显示名 | matchName | 常见错误尝试 |
|--------|-----------|-------------|
| Saber | VIDEOCOPILOT LightSaber | "Saber", "VC Saber" |
| Optical Flares | VIDEOCOPILOT OpticalFlares | "VC Optical Flares" |
| Element 3D | VIDEOCOPILOT 3DArray | "Element", "VC Element", "Element 3D" |
| Trapcode Particular | tc Particular | "Trapcode Particular" |
| Trapcode Shine | tc Shine | "TC Shine", "Trapcode Shine" |
| Trapcode Starglow | tc Starglow | "ADBE Starglow", "Starglow" |
| Trapcode Form | tc Form | "Trapcode Form" |
| Trapcode Sound Keys | tc Sound Keys | "Trapcode Sound Keys" |
| Magic Bullet Looks | MB LookSuite3 | "Magic Bullet Looks 4" |
| Deep Glow | PEDG | "ADBE Deep Glow" |

### 防御策略
- 使用 `probe31_plugin_registry.jsx` 枚举验证
- 插件代码必须用 `try/catch` 包裹
- 参数访问格式: `effect.property("matchName-XXXX")` (如 `"S_Glow-0050"`)

## 三、ExtendScript ES3 限制 (Medium)

### 踩坑点
1. **无JSON对象** - 需要手动polyfill或避免使用JSON.stringify
2. **无模板字面量** - 不能用反引号，只能字符串拼接
3. **无let/const** - 只有var
4. **无箭头函数** - 只有function
5. **无Array.includes** - 用indexOf替代
6. **文件路径必须用正斜杠或双反斜杠**

### 防御策略
- 所有JSX用IIFE包裹: `(function(){ ... })();`
- 纯ASCII输出（中文用Unicode转义或避免）
- Node.js生成器负责JSON处理，JSX只做AE操作

---

## 四、PowerShell与Node.js交互 (Medium)

### 踩坑点
1. `&&` 不是PowerShell语句分隔符 → 用 `;`
2. `node -e "..."` 中的模板字面量/反引号被PowerShell解释 → 写入.js文件再执行
3. 中文路径在cmd/powershell中编码问题 → 用UTF-8 BOM或避免中文路径

### 防御策略
- 所有复杂逻辑写入 `.js` 文件，用 `node script.js` 执行
- AE命令用 `& "path\AfterFX.exe" -r "script.jsx"` 格式

---

## 五、批量操作后的状态一致性 (Medium)

### 踩坑点
- 批量脚本的索引映射与实际预设顺序不完全对齐 → 产生字体重复
- 旧的验证结果文件未删除 → 误读为新结果

### 防御策略
- 批量操作后立即运行唯一性检查脚本
- 验证前删除旧结果文件
- 结果文件包含时间戳或计数校验

---

## 六、反模式清单

| 反模式 | 正确做法 |
|--------|---------|
| 在旧模板上patch参数 | 完全重写jsx_template |
| 假设字体名正确 | 先跑探针验证 |
| 插件代码无保护 | try/catch + graceful降级 |
| 用显示名访问效果 | 用matchName |
| 手动逐个测试65个预设 | 自动化验证管线 |
| 同类别用相似字体 | 跨风格分配（书法/像素/衬线混入） |
| 所有预设用同一缓动 | 8种缓动DNA轮换 |
| 验证时不检查表达式错误 | 遍历所有属性检查expressionError |
