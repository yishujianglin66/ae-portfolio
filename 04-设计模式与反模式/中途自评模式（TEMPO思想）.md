# 中途自评模式（TEMPO 思想）

> 来源：小红书 dots 实验室 TEMPO（Test-time-scaled Value Estimation with Macro-step Policy Optimization），随 dots3-note preview 开源发布（2026-08-14）
> 收录日期：2026-08-15
> 关联文档：`09-计划文件/2026-08-15_TEMPO与dots3-note知识提取与落地方案.md`

## 模式定义

在长流程（多阶段管线 / 长轨迹 Agent）中，**不要只在终点做评价**。把流程切成若干宏步（macro-step），每个宏步结束时执行一次轻量自评：

1. **估值**：`value_estimate = α × 先验预测 + (1-α) × 后验检查`
   - 先验：数字孪生对后续阶段链式成功率的预测
   - 后验：当前产物的原子检查通过率（ffprobe / 抽帧 / 指标采样）
   - α 随先验模型的数据积累逐步上调
2. **三态裁决**：`continue`（继续）/ `retry`（回退本阶段重跑，限次）/ `abort`（止损终止）
3. **评价即信号**：每次裁决落盘为结构化报告，无论流程最终成败都回流到学习系统

## 为什么有效

- TEMPO 实测：任务前半程与传统终局奖励 RL（GRPO）无差异，**后半程（深水区）持续拉开差距**
- 根因：终局反馈"来得太晚"，昂贵阶段的错误只有跑完全程才暴露；中途估值让错误在引入点附近被拦截
- 副产品：失败/中断的轨迹也产出学习信号（中途估值 vs 实际终局的偏差），训练数据利用率大幅提升

## 反模式一：终局质量门

只在流程末端做质量验收。

**本项目实证**：旗舰管线 QG-1 帧亮度方差=0 故障（S3 渲染问题），要跑完 S4 PR 粗剪、S5 DaVinci 调色、S6 AME 导出后才在 S7 暴露——浪费约 80% 的管线耗时。

## 反模式二：失败即弃

流程失败后丢弃中间观测，只保留成功 run 的数据。

**代价**：学习系统只能从成功样本学习，失败样本中"哪个阶段开始恶化、恶化前的中间状态长什么样"的信息全部丢失。TEMPO 证明未完成轨迹的中途估值本身就是有效训练信号。

## 本项目应用要点

- 宏步 = 旗舰管线 S0~S7 阶段（结构天然具备，无需改造）
- 自评收益最大区间 = S3→S6（占总耗时约 80% 的昂贵段），边界检查必须秒级轻量
- 落地模块：`pipeline/midstep_critic.py`（StageCritic），裁决写入 manifest 的 `critic_reports` 字段
- 回流链路：FlagshipManifestParser 解析中途裁决 → ExperienceRecord → 数字孪生 Beta 分布校正
