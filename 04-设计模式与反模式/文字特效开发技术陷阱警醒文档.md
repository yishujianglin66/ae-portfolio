# 文字特效开发技术陷阱警醒文档

> **用途**：AE 文字特效 JSX 开发前必读。每条陷阱均来自真实渲染事故/实测，标注了“错误写法 → 正确写法”与验证手段。
> **维护**：每发现一个新陷阱，按现有格式追加一条，并注明实测日期与版本。
> **最近更新**：2026-07-29（陷阱17：valueAtTime 数组拼接假错误，曾致 shadow 表达式误诊）

---

## 一、致命陷阱（导致渲染近黑 / 文件极小 <100KB）

### ⚠️ 陷阱 1：opacity 单位是 0-100，不是 0-1【V3 实际踩坑】
- **错误写法**：`L.opacity.setValueAtTime(1, 0.08)` —— 意为 t=1s 时 opacity=**0.08%**，文字几乎不可见，渲染文件 33-39KB 近黑。
- **正确写法**：`L.opacity.setValueAtTime(0.08, 100)` —— t=0.08s 时 opacity=100%。
- **参数顺序**：`setValueAtTime(time, value)`，value ∈ [0,100]。
- **验证手段**：渲染后检查文件大小，>100KB 才算内容可见。
- **实测日期**：2026-07-24（test_feasibility_v31.py）

### ⚠️ 陷阱 2：ADBE Curves Custom 调整图层导致渲染仅 24KB
- **现象**：使用 Curves Custom 的调整图层后，渲染输出近黑、文件极小。
- **对策**：避免在批量特效中使用 Curves Custom 调整图层；调色改用 Glow/色相饱和度等已验证效果。

## 二、API 不存在 / 不可用陷阱（调用即报错）

### ⚠️ 陷阱 3：`ADBE Text Position` 动画器属性在 AE2025 不存在【实测报错】
- **错误写法**：`pr.addProperty("ADBE Text Position")` → 报错"无法将名为'ADBE Text Position'的属性添加到PropertyGroup"。
- **正确写法**：逐字动画统一用 `ADBE Text Opacity`（唯一已验证可靠的逐字动画器属性），配合 Range Selector 的 Offset 实现打字机/逐字点亮。
- **实测日期**：2026-07-24（test_charpos.py）

### ⚠️ 陷阱 4：Bridge 渲染队列（RQ）API 在 AE2025 不可用
- **对策**：渲染一律走 aerender 命令行（`-project -comp -output`），不要用 RQ API。

### ⚠️ 陷阱 5：aerender 模板参数不兼容
- **现象**：`-OMtemplate` / `-RStemplate` 在当前环境报错。
- **对策**：省略模板参数，使用默认输出模块。

## 三、matchName / 参数格式陷阱（AE2025 与旧版不同）

### ⚠️ 陷阱 6：Text Animator 相关 matchName
1. Text Properties 组：`"ADBE Text Animator Properties"`（**非** "ADBE Text Properties"）。
2. Wiggly Selector：用 `"ADBE Text Wiggly Max Amount"` 和 `"ADBE Text Temporal Freq"`（**非** "ADBE Text Wiggly Selector-0001/0002"）。
3. Text Blur：需 2 元素数组 `[水平,垂直]`（如 `[40,40]`），不接受标量。
4. Bevel & Emboss 不能直接应用于文字层，需 Drop Shadow 替代或预合成。

### ⚠️ 陷阱 7：aerender 的 `-mp` 参数不接受空格分隔数字
- `-mp 2` 会报错，应省略或改用其他格式。

### ⚠️ 陷阱 11：CC Particle World 属性索引与猜测不符【V4 实测发现】
- **错误假设**：Birth Rate 在 `CC Particle World-0001`（按常规效果第一个参数猜测）——实际 setValue 报错/不生效。
- **真实索引**（AE2025 实测探测 matchName 得出）：**Birth Rate = `CC Particle World-0050`**，Longevity = `-0002`，Producer 位置 = `-0008`。
- **正确做法**：第三方/内置效果的属性索引因版本而异，**必须先遍历 `effect.numProperties` + `property(i).matchName` 实测探测**，再写入代码；非核心参数用 try/catch 保护。
- **核心结论**：CC Particle World **默认参数即产生大量可见粒子**（实测 11620KB），核心效果不依赖索引微调。
- **实测日期**：2026-07-25（test_feasibility_v4_p1.py）

### ⚠️ 陷阱 12：摄像机/灯光只影响 3D 图层【V4 实测】
- **现象**：给普通 2D 文字层加摄像机/点光后，动画/光影完全不生效（渲染内容静止）。
- **正确写法**：被摄像机/灯光影响的层必须先 `layer.threeDLayer = true`，position 为三维 `[x,y,z]`。
- **实测日期**：2026-07-25（test_feasibility_v4_p1.py）

### ⚠️ 陷阱 13：路径动画 pointOnPath 返回图层坐标，必须 toComp 换算【V4 实测】
- **错误写法**：直接把 `maskPath.pointOnPath(t)` 的返回值用作 position——该值是参考层图层坐标（相对其锚点），导致运动层位置完全错误。
- **正确写法**：`var p=ref.mask('Mask 1').maskPath.pointOnPath(t01); ref.toComp(p);`——用 `toComp()` 换算到合成空间。3D层再拼 `[p[0],p[1],z]`。
- **实测日期**：2026-07-25（test_feasibility_v4_p2.py，FX_PathMove 328.3KB）

### ⚠️ 陷阱 14：3D 图层 scale 需三元素数组【V4 实测】
- **错误写法**：3D层的 scale 表达式返回 `[v,v]`（2元素）——3D层scale是三维，可能报错或z异常。
- **正确写法**：3D层 scale 返回 `[v,v,100]`（2D层才用 `[v,v]`）。
- **实测日期**：2026-07-25（dof_focus 生成器）

### ⚠️ 陷阱 15：景深 focusDistance 是镜头到主体的距离，非z坐标【V4 实测】
- **错误理解**：把 focusDistance 设为主体z坐标（0）——实际应为镜头到主体的距离（相机z=-1600、主体z=0→焦跞1600）。
- **正确计算**：焦跞 = |主体z - 相机z|。背景z=-900→焦跞700；主字z=0→焦跞1600。
- **实测日期**：2026-07-25（test_feasibility_v4_p2.py，FX_DOF 891.4KB）

### ⚠️ 陷阱 16：Text Animator 属性不能重复 addProperty【P1 实测】
- **错误写法**：`props.addProperty("ADBE Text Tracking Amount").setValueAtTime(0, 300); props.addProperty("ADBE Text Tracking Amount").setValueAtTime(2, 0);` —— 第二次 addProperty 报错（属性已存在）。
- **正确写法**：`var trk = props.addProperty("ADBE Text Tracking Amount"); trk.setValueAtTime(0, 300); trk.setValueAtTime(2, 0);`
- **规则**：同一动画器内，每个 matchName 只能 addProperty 一次，后续操作必须用存储的引用。
- **实测日期**：2026-07-26（P1_3D_Cascade_Test 开发过程）

## 四、语法陷阱（ExtendScript = ES3）

### ⚠️ 陷阱 8：ES3 保留字与语法限制
- 禁用 `let` / `const` / 箭头函数 / 模板字符串，一律用 `var` + 字符串拼接。
- **`int` 是 ES3 保留字**，不能用作函数参数名/变量名。
- Python f-string 生成 JSX 时，JSX 里的 `{}` 必须转义为 `{{}}`；辅助函数返回纯字符串（用 `%` 格式化）再以 `{helper()}` 插入 f-string 是安全模式。

## 五之补、诊断陷阱（误诊来源）

### ⚠️ 陷阱 17：JSX 中把 valueAtTime() 数组直接拼进字符串触发假性「除以零」【7/29 实测，曾致 shadow 误诊】
- **错误写法**：`log.push("pos=" + prop.valueAtTime(t, false));` —— 把多维属性值数组直接做字符串拼接，AE 抛「Error: 数字结果无效（除以零？）」，即使表达式完全正常。上一会话据此误判 `td_shadow_drama` 表达式有 bug。
- **正确写法**：先取数组再逐分量访问：`var v = prop.valueAtTime(t, false); log.push("pos=["+v[0].toFixed(3)+","+v[1].toFixed(3)+","+v[2].toFixed(3)+"]");`
- **实证**（temp/probe2_shadow_result.txt）：带表达式逐分量求值 `A_CTRL_POS_EXPR comps=[1192.729,406.366,11.995]`（有限有效），与静态基线 `[1190.400,410.400,0.000]` 明显偏移 → 表达式工作正常。
- **黄金判定**：判断「表达式是否生效」必须用 **A/B 渲染对比 SHA256**，不能只看文件大小（H.264 不同内容可能同字节数）。实测动画版与静态版同为 100017B，但 SHA256 `8E164836…DAF4` ≠ `3393184D…4DBF` → 表达式确实影响渲染。
- **规则**：看到「除以零」先怀疑诊断脚本自身的数组拼接，而非被测表达式；`expressionError` 为空 + 求值报错 → 高度提示假错误。
- **实测日期**：2026-07-29（probe2_shadow.jsx / shadow_ab_test.jsx）

## 五、方法论陷阱（流程层面）

### ⚠️ 陷阱 9：禁止"假设可行性"，必须实测证明
- **背景**：V3.1 升级时曾对遮罩揭示/3D翻转提出"try/catch 降级"策略，被用户明确拒绝——不要降级，要最好效果，且可靠性必须**实测证明**（非假设）。
- **正确流程**：新手法先写独立测试脚本（Bridge 建合成 → 保存 AEP → aerender 渲染 → 验证文件 >100KB），确认 100% 可靠后再写入主生成器。
- **实测结论**（2026-07-24，AE2025+aerender）：
  - 矩形遮罩揭示 ✅ 279KB
  - 圆形遮罩揭示 ✅ 297KB
  - 3D Y轴翻转 ✅ 351KB
  - easeOutBack 过冲 ✅ 551KB
  - 四者全部 100% 可靠，**无需降级**。

### ⚠️ 陷阱 10：渲染验证必须以文件大小为硬指标
- 渲染"成功"（returncode=0）≠ 内容可见。必须验证输出文件 >100KB，否则视为近黑失败。
- 验证脚本：`temp/verify_v31_sizes.py`。
