# Lingma AI 使用安全手册

> **文档目的**: 规范 AI 辅助编程工具的安全使用，防止敏感信息泄露和不当依赖。
>
> **适用范围**: Lingma (通义灵码) 及所有 AI 编程助手
>
> **最后更新**: 2026-06-10

---

## 核心安全原则

### 🔴 绝对禁止

| # | 行为 | 原因 | 违规后果 |
|---|------|------|----------|
| 1 | **上传完整项目代码** | 包含商业逻辑、API 端点、文件结构等敏感信息 | 知识产权泄露风险 |
| 2 | **粘贴包含密钥的代码** | API 密钥、Token、密码等会在 AI 训练数据中留存 | 密钥泄露，需立即轮换 |
| 3 | **上传客户数据** | 用户音频/视频文件路径、个人信息 | 违反隐私合规 |
| 4 | **直接执行 AI 生成的系统命令** | AI 可能生成危险命令 (rm -rf / 等) | 系统损坏风险 |
| 5 | **将 AI 生成代码直接部署到生产** | 未经验证的代码可能含 Bug 或后门 | 生产事故 |

### 🟡 谨慎使用

| # | 行为 | 建议 |
|---|------|------|
| 1 | 粘贴超过 100 行的代码 | **先脱敏**：替换文件路径中的用户名、项目名用占位符 |
| 2 | 询问涉及网络请求的代码 | **先脱敏**：将真实 URL/IP 替换为 `example.com` |
| 3 | 让 AI 直接写安全相关代码 | **先人工设计**：安全策略由人决定，AI 仅辅助实现 |
| 4 | 用 AI 生成 SQL 查询 | **必须审查**：确认无注入风险 |
| 5 | 用 AI 解释第三方库代码 | **注意范围**：仅粘贴需要理解的函数，非整个文件 |

### 🟢 推荐使用

| # | 场景 | 说明 |
|---|------|------|
| 1 | 生成模板代码 (样板/片段) | 无业务敏感信息的通用代码 |
| 2 | 代码重构建议 | 粘贴足够小的代码片段供分析 |
| 3 | 错误诊断 | 粘贴错误信息和相关上下文（脱敏后） |
| 4 | 编写文档/注释 | 自然语言处理，无敏感信息风险 |
| 5 | 学习 AE API 用法 | 通用知识查询，不涉及项目特定实现 |
| 6 | 生成单元测试 | 基于公开接口的测试用例生成 |

## 脱敏操作指南

### 文件路径脱敏

```
原始: C:\Users\JohnDoe\Desktop\skills\ae-vocal-remover\host\main.jsx
脱敏: {PROJECT_ROOT}/host/main.jsx

原始: C:\Users\JohnDoe\AppData\Roaming\Adobe\CEP\extensions\
脱敏: %APPDATA%/Adobe/CEP/extensions/
```

### API 端点脱敏

```
原始: http://192.168.1.100:8765/api/v1/separate
脱敏: http://{SERVER_HOST}:{PORT}/api/v1/separate

原始: https://api.myservice.com/v2/auth?key=sk-abc123
脱敏: https://api.example.com/v2/auth?key={API_KEY}
```

### 用户数据脱敏

```
原始: audioPath: "D:/Music/用户上传/张三的录音.wav"
脱敏: audioPath: "{USER_UPLOAD_DIR}/sample_audio.wav"

原始: projectName: "客户A-2026-Q1广告片"
脱敏: projectName: "ClientProject-2026-Q1-video"
```

### 脱敏检查清单

粘贴代码到 AI 前，确认以下内容已处理：

- [ ] 文件路径中的用户名已替换为 `{USER}` 或 `~`
- [ ] 项目绝对路径已替换为 `{PROJECT_ROOT}`
- [ ] IP 地址和端口已替换为 `{HOST}:{PORT}`
- [ ] API 密钥/Token/密码已替换为 `{REDACTED}`
- [ ] 客户名称/项目名称已替换为通用占位符
- [ ] 邮箱地址/手机号已替换为 `user@example.com`
- [ ] 内网 URL 已替换为 `internal.example.com`
- [ ] 数据库连接字符串已替换为 `{DB_CONNECTION}`

## AI 生成代码审查清单

AI 生成的代码在并入项目前，必须通过以下检查：

### 必须检查项

- [ ] **语法兼容性**: ES3/ES5？无 const/let/箭头/模板字符串？
- [ ] **API 正确性**: 无 app.refresh()？使用 comp.selectedLayers？
- [ ] **安全性**: 无未过滤的 system.callSystem 拼接？
- [ ] **错误处理**: 所有函数有 try/catch？错误有 code 字段？
- [ ] **编码**: .jsx 文件有 BOM 声明？
- [ ] **路径规范**: 无硬编码绝对路径？
- [ ] **逻辑正确性**: 手动走读一遍核心逻辑
- [ ] **性能**: 长任务使用 scheduleTask？

### 推荐检查项

- [ ] 是否有冗余代码或死代码？
- [ ] 注释是否解释了"为什么"而非"做了什么"？
- [ ] 命名是否符合项目惯例 (camelCase)？
- [ ] 是否重复实现了已有的工具函数？

## 本地模型 vs 云端模型

| 维度 | 本地模型 (推荐) | 云端模型 |
|------|-----------------|----------|
| 适用场景 | 核心业务逻辑、安全代码、API 密钥相关 | 通用查询、文档生成、模板代码 |
| 数据安全 | ✅ 代码不离开本机 | ⚠️ 代码上传到云端服务器 |
| 响应速度 | 依赖本机 GPU | 通常更快 |
| 能力上限 | 受限于本地模型大小 | 通常更强 |
| 推荐任务 | ExtendScript 代码生成、安全审计 | 学习 AE API、技术问答 |

### 实际使用策略

1. **默认使用本地模型** (Lingma 离线模式)
2. 仅在以下情况切换到云端：
   - 本地模型无法理解复杂上下文
   - 需要最新 API 知识
   - 需要多语言翻译能力
3. 切换前确认代码已脱敏

## 敏感信息泄露应急响应

如果误将包含敏感信息的代码发送给 AI：

### 立即行动

1. **密钥/Token**: 立即轮换，撤销旧凭证
2. **内部 IP/URL**: 评估是否需要调整网络安全策略
3. **客户数据**: 通知数据保护负责人，评估合规影响
4. **商业逻辑**: 评估竞争风险，考虑架构调整

### 记录和回顾

- 记录泄露内容、时间、可能的后果
- 团队内分享经验教训（不指责，重改进）
- 更新本手册的脱敏清单

## AI 依赖管理

### 原则

- ❌ 不要让 AI 成为唯一的代码来源
- ✅ AI 是**辅助工具**，最终决策和责任在人
- ✅ 所有 AI 生成代码必须经过人工审查
- ✅ 关键算法和安全逻辑由人设计，AI 仅辅助实现

### 团队规则

1. Code Review 中标注 AI 生成的代码段（注释 `// @ai-generated — reviewed`）
2. 每次提交前运行 `🚀 全量提交前检查` VSCode 任务
3. AI 生成代码的测试覆盖要求比其他代码高 20%
