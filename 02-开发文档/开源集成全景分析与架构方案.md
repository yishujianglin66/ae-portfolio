### 3.2 数据流转协议

#### 统一数据格式 (ToolResult)
```python
@dataclass
class ToolResult:
    tool_name: str          # 工具标识 (rife/sam2/comfyui/...)
    operation: str          # 操作名 (interpolate_2x/segment_video/...)
    status: str             # pending/running/success/failed/simulated/degraded
    mode_used: str          # real/simulate/degraded
    output_files: List[str] # 输出文件路径
    output_data: Dict       # 结构化输出数据
    log: List[str]          # 执行日志
    error: Optional[str]    # 错误信息
    duration_ms: float      # 执行耗时
    used_fallback: bool     # 是否使用了降级方案
```

#### Bridge 文件轮询协议
```
Python (command.json)  →  JSX Listener (每 0.5-2s 轮询)  →  result.json
{"command": "ping", "timestamp": 1234567890}
→
{"status": "success", "result": "pong", "timestamp": "..."}
```

### 3.3 降级策略

```
┌─────────────────────────────────────────────────────────────┐
│  降级层级 (Fail-Closed)                                      │
─────────────────────────────────────────────────────────────┤
│  Level 0: 正常执行 (real mode)                               │
│    → 工具可用，完整执行                                       │
├─────────────────────────────────────────────────────────────┤
│  Level 1: 模拟模式 (simulate mode)                           │
│    → 工具不可用，返回模拟结果，管线继续                       │
│    → 例: ComfyUI 未启动 → 返回模拟图像路径                   │
├─────────────────────────────────────────────────────────────┤
│  Level 2: 降级模式 (degraded mode)                           │
│    → 服务不可用 (无 API Key/网络断开)                        │
│    → 例: Firecrawl 无 Key → 返回 {"status": "degraded"}      │
├─────────────────────────────────────────────────────────────┤
│  Level 3: 跳过 (skipped)                                    │
│    → 非关键步骤失败，记录日志，继续后续步骤                   │
│    → 例: SAM2 分割失败 → 跳过蒙版，使用原始素材               │
├─────────────────────────────────────────────────────────────┤
│  Level 4: 失败终止 (failed)                                  │
│    → 关键步骤失败，触发 Feedback Loop 重试                    │
│    → 例: AE Bridge 断开 → 重试 3 次 → 报告错误               │
─────────────────────────────────────────────────────────────┘
```

### 3.4 技术选型理由

| 选型 | 理由 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| **adobe-mcp** (VoidChecksum) | 47 ops / 8 应用，最全面 | PyMiere (仅 PR) | PyMiere 与 Bridge 架构相同，无法突破 API 限制 |
| **MediaCrawler** | 7 大中文平台统一接口 | 各平台独立爬虫 | 维护成本高，接口不统一 |
| **ComfyUI** | 节点式工作流，生态最丰富 | Stable Diffusion WebUI | WebUI 不支持 API 自动化 |
| **nexrender** | 数据驱动 AE 渲染，Node.js 生态 | AE 原生渲染队列 | 不支持批量/数据驱动 |
| **RIFE** | 实时插帧，6K+ stars | DAIN/FLAVR | RIFE 速度最快，支持 ncnn 部署 |
| **SAM2** | Meta 最新分割模型，支持视频 | SAM1/YOLO | SAM2 支持视频追踪，SAM1 仅图像 |
| **BlenderProc** | 程序化 3D + 自动标注 | Blender 手动 | 需要大规模 3D 数据生成 |

### 4.2 完整运行链路

```
用户: "帮我做一个进击的巨人风格混剪，30 秒，高燃节奏"
    │
    ▼
[1] LLM Gateway → INTENT_CLASSIFICATION (DeepSeek flash)
    → 识别: 动漫混剪 + 风格: 进击的巨人 + 时长: 30s + 节奏: 高燃
    │
    ▼
[2] VRS (视频逆向工程) → 分析参考视频
    → 提取: 剪辑节奏/转场类型/特效列表/色彩风格
    │
    ▼
[3] MediaCrawler → 采集素材
    → 抖音/B站搜索"进击的巨人 高燃混剪" → 下载候选素材
    │
    ▼
[4] Whisper → 音频分析
    → 检测节拍点/BPM/高潮段落
    │
    ▼
[5] LLM Planning → 生成剪辑方案 (DAG)
    → 时间线规划: 0-5s 开场 → 5-20s 高燃 → 20-30s 收尾
    │
    ▼
[6] Adobe MCP (AE) → 特效合成
    → 创建合成 → 导入素材 → 添加文字/粒子/转场
    │
    ▼
[7] Adobe MCP (PR) → 时间线剪辑
    → 创建序列 → 排列素材 → 对齐节拍 → 添加转场
    │
    ▼
[8] RIFE → 帧率提升 (如需要慢动作)
    → 关键镜头 4x 插帧
    │
    ▼
[9] Media Encoder → 最终输出
    → H.264 1080p 编码
    │
    ▼
[10] VMAF → 质量评估
    → 评分 ≥ 90 → 交付 / < 90 → Feedback Loop 重试
```
