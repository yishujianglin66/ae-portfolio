## 零、最关键的发现：AE 2026 V8 引擎不兼容（❌ 无法解决）

**本项目实测证据**（`10-风格化剪辑知识库/流派专属音画配方库.md` A.7）：

> AE 2026 (v26.x) 的 V8 引擎不兼容 ExtendScript，会导致 MCP Bridge 崩溃。必须使用 AE 2025 (v25.x)。

| 维度 | 详情 |
|------|------|
| **问题本质** | AE 2026 将脚本执行引擎从 ExtendScript 切换/共存为 V8，两者不兼容，导致 Bridge 轮询链崩溃 |
| **影响范围** | 所有依赖 ExtendScript 的自动化（MCP Bridge、listener、CEP evalScript） |
| **与语言的关系** | ❌ 无关。V8/ExtendScript 冲突是引擎级，英文版同样存在 |
| **与版本的关系** | ✅ 强相关。仅 AE 2026 (v26.x) 有此问题 |
| **能否解决** | ❌ 不能。除非 Adobe 后续修复版（如 26.3+）或恢复 ExtendScript 优先模式 |
| **本项目对策** | **主力环境锁定 AE 2025 (v25.x)**，AE 2026 仅作测试/新功能验证 |

**这是当初从 26 回退到 25 的直接原因，也是本报告最重要的结论：不要迁移主力环境到 AE 2026。**

## 一、问题根因分类总览

本项目遇到的所有 AE 自动化问题，按根因分为 **5 大类**：

| 类别 | 问题数量 | 版本相关性 | AE 2026 能否解决 |
|------|---------|-----------|----------------|
| **A. ExtendScript 引擎固有缺陷** | 12+ | ❌ 无关 | ❌ 不能（引擎未变） |
| **B. CEP 面板框架限制** | 5+ | ❌ 无关 | ❌ 不能（框架未变） |
| **C. Windows 文件系统特性** | 4+ | ❌ 无关 | ❌ 不能（OS 未变） |
| **D. AE API 设计缺陷** | 8+ | ⚠️ 部分相关 | ⚠️ 可能改善 |
| **E. 版本/语言特定问题** | 6+ | ✅ 强相关 | ✅ 能解决 |

**核心结论（修正版）**：约 **60% 的问题是架构性/平台性的**（A/B/C 类），与 AE 版本无关；约 **40% 是版本/语言特定的**（D/E 类）——但其中最关键的是 **AE 2026 V8 引擎与 ExtendScript 不兼容导致 Bridge 崩溃**（见第零节），这**不是换英文版能解决的**，且会直接导致主力环境不可用。

## 二、逐类深度分析

### A. ExtendScript 引擎固有缺陷（❌ 版本无关）

ExtendScript 是 Adobe 基于 **ECMAScript 3 (ES3)** 的定制引擎，自 AE CS6 以来**从未升级**。这意味着：

| 问题 | 根因 | AE 2026 能否解决 | 对策 |
|------|------|----------------|------|
| **ASI 陷阱**：`return` 后换行返回 undefined | ES3 自动分号插入机制 |  不能 | `return` 与代码同行 |
| **字体名不支持空格**：`"Arial Narrow"` 报错 | ExtendScript 字符串解析限制 | ❌ 不能 | 映射表去空格 |
| **`instanceof` 部分类名未定义**：`FootageSource` ReferenceError | ExtendScript 类型系统不完整 | ❌ 不能 | try/catch 包属性访问 |
| **无 ES6+ 特性**：无 let/const/箭头函数/模板字符串 | ES3 引擎 | ❌ 不能 | 用 var + 函数表达式 |
| **`new Function()` 执行上下文隔离** | ExtendScript 安全模型 | ❌ 不能 | 用 IIFE 包装 |
| **单线程执行**：alert() 冻结整个轮询 | ExtendScript 无 Web Worker | ❌ 不能 | 禁用所有模态 API |
| **枚举属性拒收裸数字**：`BlendingMode.NORMAL` 不能写 `1` | ExtendScript 类型检查严格 |  不能 | 用枚举对象 |
| **JSON 需手动 polyfill** | ES3 无原生 JSON | ❌ 不能 | 内置 JSON polyfill |
| **`$.evalFile()` 路径长度限制** | ExtendScript File 对象实现 | ❌ 不能 | 用短路径/中间脚本 |
| **属性访问无可选链**：`a?.b?.c` 语法错误 | ES3 无可选链 | ❌ 不能 | 逐层 try/catch |
| **无 Promise/async-await** | ES3 无异步原语 | ❌ 不能 | 回调 + scheduleTask |
| **正则表达式功能有限** | ES3 RegExp | ❌ 不能 | 简化正则/字符串操作 |

**科普**：ExtendScript 是 Adobe 2003 年基于 ES3 定制的脚本引擎，**20 年未升级**。Adobe 官方已宣布 ExtendScript 为"遗留技术"，但至今未提供现代 JS 引擎替代方案。CEP 面板的 HTML/JS 部分用 Chromium（现代 JS），但与 AE 通信必须经过 ExtendScript 桥接——这是所有痛苦的根源。

---

### B. CEP 面板框架限制（❌ 版本无关）

CEP (Common Extensibility Platform) 是 Adobe 的扩展面板框架：

| 问题 | 根因 | AE 2026 能否解决 | 对策 |
|------|------|----------------|------|
| **`$.evalFile()` 类型转换失败** | CEP→ExtendScript 类型映射 | ❌ 不能 | 用 `new File()` 构造 |
| **PlayerDebugMode 注册表要求** | Adobe 签名机制 | ❌ 不能 | 注册表设 `PlayerDebugMode=1` |
| **面板与 ExtendScript 通信延迟** | CSInterface.evalScript() 异步 | ❌ 不能 | 回调模式 |
| **CEP 版本兼容**：CSXS.11 vs CSXS.12 | manifest.xml 版本声明 | ⚠️ 可能 | 更新 manifest |
| **Node.js 集成限制** | CEP Node 版本固定 | ️ 可能 | 检查 AE 2026 CEP 版本 |

**科普**：CEP 面板本质是一个 Chromium Embedded Framework (CEF) 浏览器窗口，运行现代 HTML/JS/CSS。但它与 AE 的通信必须通过 `CSInterface.evalScript()` → ExtendScript 引擎。这意味着：
- 面板 UI 可以用现代 JS（ES2020+）
- 但所有 AE 操作必须"降级"到 ES3 ExtendScript
- 这个"翻译层"是类型转换错误的根源

---

### C. Windows 文件系统特性（❌ 版本无关）

| 问题 | 根因 | AE 2026 能否解决 | 对策 |
|------|------|----------------|------|
| **文件轮询竞态**：同一秒写两次命令，第二次被跳过 | Windows 文件 mtime 秒级精度 | ❌ 不能 | 串行间隔 ≥1.2s |
| **os.replace() WinError 5**：listener 恰好读文件时权限冲突 | Windows 文件锁机制 | ❌ 不能 | 短重试 + 降级直写 |
| **os.utime() 设到过去**：Python 时钟与 Windows 文件时间偏差 | Windows 文件时间 vs 系统时钟 | ❌ 不能 | 不碰 mtime |
| **路径分隔符**：`\` vs `/` | Windows vs POSIX |  不能 | 统一用 `/` |

**科普**：这是操作系统层面的问题，与 AE 版本完全无关。即使在 macOS/Linux 上运行 AE，也会有类似的文件系统竞态问题（只是表现形式不同）。

### D. AE API 设计缺陷（⚠️ 部分版本相关）

| 问题 | 根因 | AE 2026 能否解决 | 对策 |
|------|------|----------------|------|
| **`app.project.activeItem` 被 importFootage 劫持** | AE 导入素材后自动激活素材项 | ️ 可能 | 按合成名定位 |
| **Lumetri 首次加载 120s+** | 效果引擎懒初始化 | ⚠️ 可能 | 预热脚本 |
| **QuickTime 输出扩展名自动改写** (.mov→.mp4) | AE 25.3 输出模块行为 | ✅ 可能已修复 | 多扩展名候选 |
| **`comp.saveFrameToPng()` 参数顺序** (time 在前 File 在后) | AE API 设计 | ️ 可能 | 记住正确顺序 |
| **渲染队列残留污染** | `rq.render()` 渲染所有 Queued 项 | ❌ 不能 | 渲染前清空队列 |
| **表达式赋值不抛语法错误** | AE 表达式延迟求值 | ❌ 不能 | 预检配方 |
| **效果 matchName 随版本变化** | Adobe 内部重构 | ️ 可能 | 版本适配表 |
| **`FootageSource` 未定义** | ExtendScript 类型暴露不完整 | ❌ 不能 | try/catch |

## 五、核心结论

### 问题根因分布

```
ExtendScript 引擎固有缺陷  ████████████████████  40%
AE API 设计缺陷            ████████████          25%
版本/语言特定问题          ████████              15%
CEP 面板框架限制           ██████                12%
Windows 文件系统特性       ████                   8%
```

### 升级决策矩阵（修正版）

| 维度 | AE 2025 中文版 | AE 2026 英文版 | 改善幅度 |
|------|---------------|---------------|---------|
| **Bridge 稳定性** | ⭐⭐⭐⭐（已验证稳定） | ❌（V8 不兼容崩溃，实测） | **-200% 致命** |
| **脚本开发效率** | ⭐（需 matchName 遍历） | ⭐⭐⭐（若 Bridge 可用，但实际不可用） | 不可获得 |
| **插件兼容性** | ⭐⭐⭐⭐（已验证） | ⭐⭐⭐（需重新验证） | -10% |
| **长期维护性** | ⭐⭐（即将 EOL） | ⭐⭐⭐⭐⭐（最新） | +150%（但需等 V8 修复） |
| **社区支持** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | +100%（但无法落地） |

### 最终建议（2026-08-11 修正版）

**❌ 不建议迁移主力环境到 AE 2026。保持 AE 2025 中文版为主力。**

理由：

1. **致命障碍**：本项目实测——AE 2026 (v26.x) 的 V8 引擎不兼容 ExtendScript，MCP Bridge 直接崩溃。这是当初从 26 回退到 25 的直接原因，**换英文版不能解决**（引擎级问题与语言无关）
2. **升级净收益为负**：英文版确实能解决属性名本地化问题（约 15%），但代价是 Bridge 整体不可用（100% 自动化瘫痪），得不偿失
3. **中文版问题的正确解法不是换版本**：属性名本地化问题已通过 38 种 matchName 清单固化（`AE-Bridge避坑指南.md`），继续扩充该清单即可，成本远低于迁移
4. **AE 2026 仅作测试环境**：并行安装，用于体验新功能（Object Matte、-rjsx 标志等），不参与生产自动化
5. **何时再评估迁移**：Adobe 修复 V8/ExtendScript 兼容性（如 26.3+ 版本实测稳定），或官方确认恢复 ExtendScript 优先模式后，再做迁移评估

**升级只能解决约 25% 的问题**（纯语言类），且引入 1 个致命新问题（V8 崩溃）；剩余 **60% 的架构性问题**（ExtendScript ES3 限制、Windows 文件竞态、CEP 类型转换）无论哪个版本都必须依赖已固化的 workaround 方案。

## 六、附录：本项目已固化的 Workaround 方案

以下方案**无论 AE 版本如何都必须遵守**：

### 6.1 Bridge 通信铁律
- 串行间隔 ≥1.2s（放在写入之前）
- 原子写入（临时文件 + os.replace）
- 结果竞态防护（mtime 严格增大）
- 超时后 ping 探活再重发

### 6.2 ExtendScript 编码规范
- `return` 与代码同行（防 ASI）
- 字体名去空格（映射表）
- 枚举属性用对象（不传裸数字）
- 禁用 alert()/模态 API
- 按合成名定位（不依赖 activeItem）

### 6.3 渲染防护
- 渲染前清空队列
- 渲染前删除同名旧输出
- 产物校验用 ffprobe（不只看文件大小）
- 黑屏检测用 signalstats YAVG<20

### 6.4 CEP 面板规范
- `$.evalFile()` 用 `new File()` 构造
- PlayerDebugMode=1 注册表设置
- 路径用 `/` 分隔符
- 短路径避免长度限制
