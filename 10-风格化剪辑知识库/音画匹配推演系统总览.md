# 音画匹配推演系统总览

> [!abstract] 文档摘要
> 本文档是「音乐+片段→成片」正向创作链路的顶层蓝图。当用户给一首歌和几个视频片段时，引擎需要推演出：片段之间的联系、音画匹配方案、剪辑思路、效果参数、成片预判。本文档定义七层架构、原子输入输出规范、与现有逆向分析系统的衔接关系。

> [!tip] 使用指南
> - 系统设计者：从第二章七层架构开始读
> - 模块开发者：第三至五章是核心模块规范
> - 调用方：第六章是端到端调用示例
> - 缺口分析者：第七章是能力补全路线图

---

## 第一章 设计目标

### 1.1 核心场景

用户给一首歌 + N 个视频片段，引擎要能完成：

```
输入：  1 首音乐（含音频特征）  +  N 个视频片段（含视觉特征）
            │                              │
            ▼                              ▼
        音乐原子分析                  片段原子分析
            │                              │
            └─────────┬────────────────────┘
                      ▼
                音画匹配推演
                      │
                      ├─→ 片段之间的联系（叙事/色彩/节奏/能量）
                      ├─→ 每段匹配什么效果（效果+参数+时机）
                      ├─→ 剪辑思路（节奏/转场/情绪曲线）
                      └─→ 成片预判（视觉风格/节奏感/情绪曲线）
                      │
                      ▼
                原子参数 JSON
                      │
                      ▼
              Phase 1-5 引擎执行（既有能力）
                      │
                      ▼
                  AE 成片
```

### 1.2 三个层级的能力

| 层级 | 能力 | 现状 |
|------|------|------|
| L0 | 静态分析（音乐特征/片段特征） | ✅ 已有 |
| L1 | 智能匹配（音画关联推演） | ❌ 缺口 |
| L2 | 创作推演（思路+参数+预判） | ❌ 缺口 |

### 1.3 与既有系统的关系

```
既有能力（已建成）                    新增能力（本次构建）
─────────────────                ─────────────────
逆向分析（视频→参数）                 正向推演（音乐+片段→成片）
       │                                │
       ▼                                ▼
   参数-效果映射库                    音画匹配决策树
       │                                │
       └────────┬───────────────────────┘
                ▼
        原子参数 JSON（统一接口）
                │
                ▼
        Phase 1-5 引擎（既有）
                │
                ▼
            AE 执行
```

> [!important] 关键设计
> 新系统**不重复造轮子**，所有输出都收敛到「原子参数 JSON」这一统一接口，由既有 Phase 1-5 引擎执行。新系统只解决"推演"这一环。

## 第二章 七层架构

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────────────────────┐
│  P0: 输入预处理层（Input Preprocessing）                             │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：音乐文件 + 视频片段列表                                        │
│  输出：标准化音频流 + 标准化视频帧序列                                 │
│  技术：FFmpeg 解码 / 音频重采样 / 帧抽取                              │
├─────────────────────────────────────────────────────────────────────┤
│  P1: 音乐原子分析层（Music Atom Analysis）                           │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：标准化音频流                                                   │
│  输出：BPM / 节拍点列表 / 段落结构 / 能量曲线 / 频谱特征              │
│  技术：librosa/onset detection/结构分割/FFT                          │
├─────────────────────────────────────────────────────────────────────┤
│  P2: 片段原子分析层（Clip Atom Analysis）                            │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：标准化视频帧序列                                               │
│  输出：每个片段的运动强度/色彩基调/构图/镜头时长/能量曲线             │
│  技术：OpenCV光流/颜色直方图/边缘检测/场景分割                        │
├─────────────────────────────────────────────────────────────────────┤
│  P3: 音画匹配层（Audio-Visual Matching）                             │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：音乐原子 + 片段原子                                           │
│  输出：匹配方案（节拍-片段对齐/情绪-视觉配对/效果-频段绑定）          │
│  技术：动态规划对齐/余弦相似度/能量相关性/规则推理                    │
├─────────────────────────────────────────────────────────────────────┤
│  P4: 剪辑思路推演层（Editing Reasoning）                             │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：匹配方案 + 风格意图                                           │
│  输出：剪辑脚本（节奏曲线/转场设计/叙事结构）                        │
│  技术：决策树 + 风格配方库 + 风格迁移                                │
├─────────────────────────────────────────────────────────────────────┤
│  P5: 效果参数推演层（Effect Parameter Inference）                    │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：剪辑脚本 + 匹配方案                                           │
│  输出：原子参数 JSON（与既有接口对齐）                                │
│  技术：参数-效果映射库反查 + 关键帧模板 + 置信度评估                  │
├─────────────────────────────────────────────────────────────────────┤
│  P6: 成片预判层（Outcome Prediction）                                │
│  ─────────────────────────────────────────────────────────────────  │
│  输入：原子参数 JSON + 剪辑脚本                                      │
│  输出：成片预判（视觉风格/节奏曲线/情绪曲线/质量评分）               │
│  技术：渲染模拟 + 视觉签名预测 + 风格匹配度                          │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流示例

```
用户："这是一首歌 + 3 个片段，做成赛博朋克卡点视频"

P0: 输入 → 音乐.mp3 + [片段A.mp4, 片段B.mp4, 片段C.mp4]

P1: 音乐分析 →
    BPM: 128
    节拍点: [0.47, 0.94, 1.41, ..., 180.3]
    段落: [前奏0-15s, 主歌15-45s, 副歌45-75s, 桥段75-90s, 副歌90-120s]
    能量曲线: [0.2, 0.3, 0.8, 0.6, 0.9]

P2: 片段分析 →
    片段A: 运动0.3 / 色彩蓝调 / 时长8s / 能量0.4
    片段B: 运动0.7 / 色彩红色 / 时长5s / 能量0.7
    片段C: 运动0.5 / 色彩多色 / 时长12s / 能量0.5

P3: 音画匹配 →
    节拍-片段对齐: 片段B 在副歌段（高能量音乐 ↔ 高能量画面）
    情绪配对: 片段A 蓝调 ↔ 前奏冷静段
    效果绑定: 低频段 ↔ 故障效果 / 高频段 ↔ 闪烁

P4: 剪辑思路 →
    节奏曲线: 前奏缓→主歌中→副歌急→桥段缓→副歌急
    转场设计: 故障切换 / 闪光切换 / 拉镜
    叙事结构: 冷启动→铺垫→爆发→冷却→终极爆发

P5: 效果参数 →
    [
      {compName: "卡点视频", frameRate: 30, duration: 120,
       operations: [
         {op: "addLayer", ref: "L001", source: "片段A.mp4", ...},
         {op: "addEffect", ref: "F001", matchName: "ADBE Gaussian Blur 2", ...},
         {op: "setKeyframe", ref: "K001", propertyPath: "Effects/F001/Blurriness",
          keyframes: [
            {time: 0, value: 0, easing: {type: "linear"}},
            {time: 0.5, value: 25, easing: {type: "ease_in_out"}},
            ...
          ]},
         ...
       ]}
    ]

P6: 成片预判 →
    视觉风格: 赛博朋克（青品对比/霓虹光/故障元素）匹配度 0.87
    节奏曲线: 与音乐能量曲线相关系数 0.92
    情绪曲线: 冷启动→张力→爆发→释放→爆发
    质量评分: 8.2/10
    潜在问题: 片段C 时长偏长，建议在第45s切分
```

## 第四章 与既有系统的接口

### 4.1 输出对齐：原子参数 JSON

新系统的 P5 层输出**完全采用**既有 `CompilerInput` 接口，确保无缝衔接：

```typescript
// 新系统 P5 输出 → 既有 Phase 1 编译器输入
interface CompilerInput {
  operations: Array<
    | CreateCompOp
    | AddLayerOp
    | AddEffectOp
    | SetKeyframeOp
    | SetPropertyOp
  >;
  metadata: CompilerMetadata;
}
```

### 4.2 输入对齐：与逆向分析系统共用

新系统的 P2 片段分析层与既有「视频效果逆向分析系统」共用视觉特征识别能力：

```
既有：视频效果逆向分析系统 → AnalysisReport（含 effects/parameters/keyframes）
新增：片段原子分析层 → ClipAtom（含 motion/color/composition/energy）

复用关系：
- 视觉签名识别 → 复用 [[AE效果视觉特征库]]
- 颜色分析     → 复用调色理论
- 关键帧推断   → 复用 [[关键帧与速度曲线逆向分析]]
```

### 4.3 知识库调用关系

```
新系统调用的既有知识库：
  ├── 参数-效果原子级映射库（反查参数）
  ├── AE效果视觉特征库（视觉签名匹配）
  ├── 风格化预设宝典（风格配方）
  ├── 风格化剪辑技巧与预设（剪辑技巧）
  ├── 解析词汇表与推理决策树（词汇体系）
  └── 视频案例解析库（案例模板）
```

## 第六章 端到端调用示例

### 6.1 TypeScript 调用接口

```typescript
// 新增的自动剪辑入口
interface AutoEditRequest {
  musicFile: string;
  clips: string[];
  targetStyle?: string;       // 默认从用户输入推断
  targetDuration?: number;    // 默认跟随音乐
  preferences?: {
    cutDensity?: number;      // 切镜密度 0-1
    effectIntensity?: number; // 效果强度 0-1
    allowColorGrading?: boolean;
  };
}

interface AutoEditResponse {
  musicAtom: MusicAtom;
  clipAtoms: ClipAtom[];
  matchPlan: MatchPlan;
  compilerInput: CompilerInput;     // 衔接 Phase 1
  prediction: OutcomePrediction;
  reasoningPath: string[];          // 推演路径（可解释性）
}

// 主入口
async function autoEdit(req: AutoEditRequest): Promise<AutoEditResponse>;
```

## 第七章 能力缺口与补全路线

### 7.1 七大缺口模块
