## 二、三项关键概念修正

1. **"正立"的正确数学** = 把世界上方向**投影到与视线垂直的平面**并归一化：
   `up = normalize(world_up − (world_up · forward)·forward)`。
   旧实现返回常量 `(0,1,0)` 只在视线水平时偶然成立；**仰拍/俯拍时它与视线不垂直**，
   基向量退化 ⇒ 相机出现不可预期滚转。这是"相机正立"真正的坑。
2. **AE 侧的正确落地方式** = 设置 **Point of Interest**。AE 由 POI 推导朝向并保持
   up = 合成上方向，天然无滚转。因此生成物只写 `position` + `pointOfInterest`，
   **不写自定义旋转**（写了会与 AE 自身推导冲突而产生滚转）。
3. **坐标约定修正**：AE 3D 合成中心**就是原点 (0,0,0)**；`(w/2, h/2, 0)` 是 2D
   图层坐标。旧实现把两者混用，相机会绕一个偏移中心公转、目标不在画面中心。


### 引擎阶段行为（smoke + 测试覆盖）

| 输入 | 行为 |
|------|------|
| 有 bbox（归一化 `[x1,y1,x2,y2]`） | 目标点 = bbox 中心换算到 AE 3D（x 右为正、y **向上**为正），成功出片布点 |
| 无 bbox（检测降级） | 回退原点单目标，**如实标注** `degraded` 且写入 `stage.error` |
| 输出目录越界 | 优雅拒绝并说明原因，不抛异常、不写文件 |
| 异常输入 | 不抛出（相机阶段失败不得中断主流程） |

产出 `camera_plan.json`（含每台相机的基向量与正立诊断）+ `camera_setup.jsx`。

### 过程中被测试抓到的两个自身问题（如实记录）

1. **验收脚本的数值方法不当**：先用 `acos(点积)` 度量指向误差，在点积 ≈ 1 处导数
   发散，把 1e-16 级浮点噪声放大成 1.5e-06 度的"误差"→ 改用单位向量差范数。
2. **防护过严**：输出目录收敛检查最初只允许项目/仓库目录，把 pytest 的临时目录也
   拒了（6 项测试红）→ 允许集补上系统临时目录（临时产物落 temp 是常规用法）。
