### 1.2 现状要点（决定各项集成判断的前提）

1. **渲染层是"裸 FFmpeg 命令行"**：无渲染中间表示、无帧级回归验证——改一个滤镜参数后，只能靠人眼或 CNN 评分器（run 级）看结果。**这正是 HyperFrames 理念能补的洞。**

3. **DaVinci 只是机器上装了，不在 MasterCut 链路里**：全项目 grep 无 Resolve scripting 调用；渲染主力是 AE（aerender + ExtendScript，脚本能力完整无授权门槛）+ FFmpeg。

## 二、HyperFrames：确定性渲染理念的适配分析

### 2.1 它是什么（源码级事实）

- **管线**：组合 = 纯 HTML 文档 + GSAP 时间线（经全局 `__timelines` 暴露）；渲染 = headless Chrome（Puppeteer/Chrome-for-Testing）逐帧 seek 截图（rAF settle 等待渲染稳定）+ FFmpeg 编码。**同输入 → 同帧输出**，可进 CI 跑回归。
- **包结构**（monorepo 6 包）：`@hyperframes/core`（类型+HTML生成+GSAP工具）/ `cli` / `engine`（BeginFrame+FFmpeg）/ `producer`（Puppeteer+FFmpeg）/ `ui-player`（`<hyperframes-player>` 自定义元素，通过 iframe document 驱动 seeking）/ `studio`（React+Hono 编辑器）。
- **动画适配层**：GSAP 一等公民（含 AE 规范速度曲线拟合、velocity-based ease fitting）、Lottie（网络拦截捕获）、WebGL shader（hook `gl.shaderSource` 提取）、Three.js、CSS 关键帧。
- **agent 原生**：同时内置 `.claude-plugin/`、`.agents/skills/`（Codex）、`.cursor-plugin/` 三套技能发现机制；5 个核心技能注册在 `hyperframes:` 命名空间。
- **质量门禁**：`hyperframes lint`（音频分组校验、GSAP/内联 transform 冲突检测）、`check`（WCAG AA 对比度）、`seam-gate verify`（接缝门禁）、Docker 化回归测试、文档代码片段门禁。
- **工程要求**：Node>=22（✅ 本机满足）、FFmpeg（✅）、bun（开发用）、headless Chrome（需装 Chrome-for-Testing 约 220MB）。
- **成熟度**：4,243 commits / 892 branches，v0.8.33（2026-09-09 仍在发版），HeyGen 内部 monorepo 移植开源，已有采用者 PandaStudio。

### 2.2 适配度分析

**理念层（满分，必须抄）——"确定性渲染可测试"三件套：**

| HyperFrames 机制 | 对 MasterCut 渲染层的等价改造 |
|---|---|
| 同输入同帧输出（rAF settle + 逐帧 seek） | FFmpeg 天然确定性：**同版本二进制 + 同参数 + 同输入 = 同输出**。要做的是把"版本+参数+输入哈希"固化进渲染清单（render manifest） |
| 帧级回归测试（Docker 化） | 渲染后**逐帧 perceptual hash（pHash/dHash）比对基线**，超阈值即回归失败——目前 unified_edit 完全没有 |
| lint / check / seam-gate 门禁 | 把"渲染前参数校验"独立成 pre-render lint（LUT 存在性、时长边界、音轨完整性），CI 挡住坏渲染 |
| 组合=声明式文档（HTML+data 属性） | 渲染层引入**EDL/渲染清单中间表示**（与 video-use 的 EDL 结论合流，见 §3） |

**直接复用层（低，选择性引入）：**

MasterCut 的主输入是实拍/番剧素材剪辑，不是程序化合成视频。HyperFrames 能覆盖的只有 MasterCut 的**动图子域**：
- 标题卡 / 片头 KV 动效（对标 AE 现有 text_effect_service，HyperFrames 优势是 agent 可写 HTML 生成、免 AE 启动开销）
- 歌词视频 / 字幕动效（静止系 MAD 的歌词轴可视化预览）
- 数据可视化片段（评估报告里的评分曲线动画）
- 改版预告 / changelog 视频（changelog-video 技能即插即用）

**不适用**：漫剪主链路（素材检索→切割→节奏合成）与 HyperFrames 的"从零合成"范式正交，强行统一是路线错误。

### 2.3 集成成本与风险

- **理念移植（P0）**：2-3 天。在 `stage3_render_cut` 外包一层 `render_manifest.json`（输入哈希/ffmpeg 参数/版本），新增 `tests/test_render_regression.py`（pHash 比对，阈值参考 HyperFrames 的逐帧校验思路）。零新依赖。
- **CLI 引入（P3）**：3-5 天。`npx hyperframes@latest render` 作子渲染器，产物进 unified_edit 的素材池。风险：①引入 Node 渲染栈增加维护面；②220MB Chrome-for-Testing；③v0.x API 可能变（410 tags 迭代极快）。
- **许可证**：Apache 2.0（掘金报道与多方一致，仓库 LICENSE 页因截断未直接核到，集成前需再确认一次——这是本报告唯一未闭环的证据点）。

## 三、video-use：agent 编排剪辑的正面竞品拆解

### 3.1 它是什么

browser-use 出品，24k★（7 天 +2.6k，AI 视频类增速第一）。**不是**驱动 Premiere/Resolve UI，而是纯 FFmpeg 管线 + agent 技能：

```
Transcribe → Pack → LLM Reasons → EDL → Render → Self-Eval
                                                  └─ issue? fix + re-render (max 3)
```

- 管线：转写（ElevenLabs）→ LLM 推理出 **EDL**（编辑决策清单）→ FFmpeg 渲染 → **对渲染成品在每个切点边界跑 `timeline_view` 自检**（抓视觉跳变、音频爆音、字幕遮挡）→ 不过则修复重渲，**最多 3 轮**。
- 五条设计原则：① 文本+按需视觉（转写稿是推理表面，不 dump 帧）② 音频为主视觉跟随（切点来自语音边界与静默间隙）③ **询问→确认→执行→自评→持久化**（未经策略确认不动刀）④ 零内容假设 ⑤ 12 条硬规则管生产正确性，其余交给品味。
- 会话记忆：`project.md` 持久化，跨周续作。
- 动画覆盖层：HyperFrames/Remotion/Manim/PIL，**每动画一个并行子 agent**。

### 3.2 与 MasterCut 的对照（哪些已具备、哪些是真差距）

| video-use 机制 | MasterCut 现状 | 判定 |
|---|---|---|
| 转写为推理表面 | MelBand RoFormer + drumsep 鼓点 stem 锚定（音乐域对标语音域） | ✅ 已具备且更细（16 分音符网格量化） |
| LLM 推理出 EDL | 规则蒸馏引擎产出切割方案 | ⚠️ 已具备，但**无 EDL 中间表示落盘**（方案内嵌在 unified_edit 流程里） |
| 渲染后切点自检 | CNN 评分器（run 级，评分整体） | ⚠️ **粒度差一档**：无"每个切点边界"级自检 |
| 修复循环上限 3 轮 | 无自动修复循环（评估→人工介入） | ❌ 真差距，值得抄 |
| project.md 会话记忆 | .workbuddy/memory 体系 | ✅ 等价物已具备 |
| 策略确认门（ask→confirm→execute） | 用户确认 run 编号后执行 | ✅ 已具备 |
| 并行子 agent 出动画 | 无 | ❌ 差距，P3 阶段随 HyperFrames 引入时补 |

### 3.3 借鉴结论（集成成本 2-3 天，零依赖）

1. **EDL 落盘**：unified_edit 切割方案序列化为 `output/<run>/edl.json`（切点/素材引用/参数/理由），渲染层只吃 EDL——这同时满足 HyperFrames 的"渲染清单"需求（§2.2），**一箭双雕**。
2. **切点级 self-eval**：渲染后在每切点 ±6 帧窗口提 pHash 差分 + 音频 RMS 跳变检测，与 CNN 评分器互补（CNN 管"整体好不好看"，切点检测管"这一刀有没有技术事故"）。
3. **修复循环 max 3**：切点自检失败 → 规则引擎微调切点（±2 锚点网格内）→ 重渲 → 再检，3 轮不过则标记人工介入。与 R-2026-0002 规则生命周期机制天然契合。

**不需要抄的**：ElevenLabs 转写（语言域不同）、Telegram/VPS 常驻（非需求）。

## 四、Runway 插件 + Wan-Animate-2 + DaVinci MCP 与国产平台对比

### 4.1 Runway Adobe 插件（9/8 发布）

**事实**：Pr/AE 内嵌面板（Window→Extensions→Runway），直呼 Gen-4.5 / Seedance 2.5 / Kling 3.0 Pro / Veo 3.1；**Aleph 2 可对时间线上已有素材做整段风格化重渲**（时长不变、锚点帧改造）；HDR 转换/去背景/放大一键化。插件免费，生成按 credits 计费（付费套餐）。

**对 MasterCut 的适配判断——不进自动化主线，理由三条：**
1. **不可脚本化**：它是 UI 面板不是 API。MasterCut 的自动化链路无法驱动它；要程序化只能走 Runway API（另一套计费与集成工作）。
2. **云端 credits 成本不可控**：AMV 批量素材风格化重渲是吃 credit 的大户，与"本地 RTX 4060 + 开源权重"的项目路线冲突。
3. **动漫风格能力存疑**：Runway 系模型以写实见长，静止系 MAD 需要的 2D 动漫风格保真未有公开基准。

**保留价值**：手动素材补全/预览工具位（免费安装零成本），Aleph 2 的"整段重渲保时长"交互范式值得观察——它是 MasterCut 素材风格化线（R 线）的商业对照组。
**注意事项（若使用）**：素材上云的版权风险（番剧素材直接传境外云端服务，商用与发布场景有隐患）、账号 workspace 隔离。

### 4.2 Wan-Animate-2（木偶动画线正面候选）

**事实（官方仓库 + ComfyUI 官方文档 + 多方评测交叉验证）：**
- 架构：双分支 DiT（参考图+驱动视频同时作为条件），**端到端**——无姿态提取/骨架预处理中间件；Time-Align RoPE 对齐时序 + Sparse-Ref Attention 省算力。
- 能力：高保真动作迁移+强身份保持；**文本控视角**（输出相机与驱动视频解耦，可换机位）；多角色（一对多/多对多）；**蒸馏版 10 步无 CFG**；Lite 实时版。
- 生态：Apache-2.0，权重在 HF/ModelScope（Wan-AI/Wan2.2-Animate-2-14B + 蒸馏版），ComfyUI 原生工作流（INT8 convrot / BF16 / Distill INT8 / Distill BF16 四档 + lightx2v 480p 蒸馏 LoRA + FP8 文本编码器），另有 WanAnimate2Cache 节点（480×832/81 帧约省一半时间，约需 12.5GB **系统内存**）。
- **显存现状（关键）**：官方默认按 **8×A800** 调的并行配置；480P 在 2×A800 测过；第三方整合包称"建议 12G 起"；评测站数据：FP16 28GB 文件（24G 卡）、FP8 约 14GB（16G 卡）、**INT8 约 7GB（有可见的保真损失）**、GGUF 量化覆盖中间档。

**与木偶线现有选型（DWPose+LivePortrait）的对比：**

| 维度 | DWPose+LivePortrait（现方案） | Wan-Animate-2 |
|---|---|---|
| 机制 | 显式骨架提取→驱动 | 端到端，无中间件 |
| 显存 | 轻量，8G 从容 | 14B，8G 极限档 |
| 身份保持 | 中（骨架绑定视角） | 强（官方对比胜可灵 MotionControl/DreamActor-M2） |
| 视角解耦 | ❌ 骨架绑死拍摄视角 | ✅ 文本控机位 |
| 多角色 | ❌ | ✅ |
| 走 8G 本地 | ✅ 已验证路线 | ❓ 待实测 |

**8G 可行性评估与实测方案（P1，1 天）：**

判断：**理论可行但只剩一条窄路**——INT8 convrot 蒸馏版（~7GB 文件）+ lightx2v 480p LoRA + FP8 文本编码器 + ComfyUI 显存优化三件套（`--lowvram` / block swap offload / 触发式模型加载）。ComfyUI 的 WanAnimate2Cache 证明官方在推省显存路径（激活缓存省一半时间，代价 12.5G 系统内存——本机 RAM 需确认 ≥32G）。

实测矩阵（顺序执行，任一步 OOM 即降档）：
1. **冒烟**：480p / 49 帧（2 秒）/ INT8+蒸馏 / 单角色动画模式——看能否完整出片；
2. **量化档位对比**：同素材跑 INT8 vs GGUF Q4（QuantStack 有 14B GGUF）——pHash+SSIM 对比基线 BF16 输出（借云端 demo 出基线，ModelScope 在线 demo 免费），量化损失是否可接受以 MasterCut 的 CNN 评分器实测打分；
3. **边界**：逐步拉到 81 帧/720p，记录 OOM 边界与耗时（4060 的推理速度决定它只配做"关键镜头精修"，不配做全片量产）；
4. **风格测试**：投入木偶线真实素材（托尔芬参考图+驱动视频），验证 2D 动漫风格保真——这是 go/no-go 的最终判据，显存通过但风格崩等于不过。

**决策树**：冒烟通过且风格保真 ≥ LivePortrait → 升级为木偶线画质档（关键镜头用 WA2、批量过渡镜头仍用 LivePortrait 双轨）；冒烟 OOM → 等 Q4 以下 GGUF 或 Lite 版权重放出再测；风格崩 → 维持 LivePortrait 主线，WA2 归档观察。

### 4.3 DaVinci Resolve 21.1 原生 MCP：本机不可用，搁置

**事实链**：
- 21.1（9/8，IBC 抢发）内置**原生 MCP server**：Claude / Claude Code / ChatGPT Codex 经 File→Setup AI Assistants 连接，可执行"整理媒体→长片剪精华→删<1s 短切→渲 H.265"整链任务；能力含媒体池转写读取、多机位角度切换、场景变化标记、音频归一化、批量渲染。
- **硬门槛：仅 Studio 付费版**。免费版 scripting 整体禁用（External scripting 锁死为 None），AI 助手集成明确排除在免费版外。Studio 授权约 $295 / ¥2685。
- **本机实测：21.0.3.7 免费版**（`D:\app\Resolve.exe` VersionInfo 实读）——当前**连外部脚本都接不了**，遑论 MCP。

**MasterCut 适配判断（搁置，三重理由）：**
1. Resolve 不在 MasterCut 渲染主链路（主力 = AE aerender + FFmpeg，AE 的 ExtendScript 全量脚本无授权门槛且 5305 测试的 ae_automation 体系已就位）；
2. ¥2685 买到的是"第二个 NLE 的 agent 接口"，与既有 AE 线能力重叠；
3. MasterCut 的编排智能在自有管线（规则蒸馏+CNN 评分），不是缺一个"能被 Claude 遥控的 NLE"。

### 4.4 国产 IDE / agent 平台能否做到同等能力？

**关键认知：DaVinci 21.1 的架构是"DaVinci 当 MCP server，AI 客户端当大脑"。** 所以问题拆成两半：客户端能力（各家 IDE）× 服务端门槛（Studio 授权）。

**客户端能力对比（调研交叉验证，2026-09 时点）：**
