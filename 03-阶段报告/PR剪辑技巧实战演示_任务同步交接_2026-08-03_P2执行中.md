## 三、核心技术突破：MCP Bridge 脚本执行通道（P0 成果）

### 3.1 背景结论（实测）
- **PR 2025 没有** AE 那样的 `File > Scripts > Run Script...` 菜单（已用 UIA 全枚举文件菜单 29 项确认）
- Adobe 官方立场：CEP 面板是 PR 执行 ExtendScript 的唯一支持方式
- Startup 脚本方式（`pr_skills_cmd.json` 触发）存在"命令被消费但日志写不出"的不稳定问题

### 3.2 可靠执行机制（已验证 4 次成功）

**架构**：`90_pr_mcp_bridge.jsx`（Startup 脚本，v3.5）监听 `pr_command.json`，支持 `executeScript` 命令，用 `eval()` 执行任意脚本。

**触发时机**（两种）：
1. **PR 启动时**：bridge 加载后立即执行一次 `bridgeCheck()`（最可靠）
2. **运行中**：`onProjectChanged`/`onSequenceChanged` 事件触发（用 Ctrl+S 触发，需 PR 有焦点且无模态对话框）

**标准操作流程**：

```powershell
# 第 1 步：写入 bridge 命令（用 Python 避免 PowerShell 转义地狱）
# 创建临时 py 文件内容如下，然后执行：
# C:\Users\Administrator\AppData\Local\Programs\Python\Python312\python.exe <py文件>
```

```python
import json
script = (
    # 可选：先加项目等待循环（PR 启动后项目加载有延迟）
    'var _seq = null; '
    'for (var _w = 0; _w < 90; _w++) { '
    '  try { _seq = app.project.activeSequence; '
    '    if (!_seq && app.project.sequences.length > 0) _seq = app.project.sequences[0]; '
    '    if (_seq) break; '
    '  } catch(e) {} '
    '  $.sleep(1000); '
    '} '
    'if (_seq) { '
    '  var _f = new File("C:/Users/Administrator/Desktop/AE-Knowledge-Vault/scripts/<目标脚本>.jsx"); '
    '  _f.encoding = "UTF-8"; _f.open("r"); var _c = _f.read(); _f.close(); eval(_c); '
    '}'
)
cmd = {"command": "executeScript", "script": script}
with open(r"c:\Users\Administrator\Desktop\AE-Knowledge-Vault\.premiere-mcp-bridge\pr_command.json", "w", encoding="utf-8") as f:
    json.dump(cmd, f)
```

## 四、PR 2025 ExtendScript API 实测能力表（v3.0/v3.1 探查结论）

### 4.1 可用 API ✅
| API | 说明 |
|-----|------|
| `app.project.importFiles([paths])` | 导入素材（视频/音频） |
| `qe.project.newSequence(name, "")` | QE DOM 创建序列（标准 DOM 预设路径均无效） |
| `track.insertClip(item, ticks)` | 按 ticks 精确插入 clip |
| `clip.components` → Motion(`AE.ADBE Motion`) | 属性中文名：位置/缩放/缩放宽度/高度比例/旋转/锚点/防闪烁滤镜/裁剪上左右下 |
| `prop.setValue(v, true)` + `prop.addKey(t)` + `prop.setKeyValueAtKey(t, v)` | Motion 关键帧完全可用 |
| `clip.getSpeed()` | 可读（返回 1） |
| `app.project.save()` | 保存（新项目首次保存可能弹"替换"对话框） |
| `TICKS_PER_SEC = 254016000000` | 时间单位换算 |

### 4.2 确认不可用 API ❌（全部实测报错）
| API | 实测结果 |
|-----|---------|
| `clip.addComponent()` | `ReferenceError: not a function`（无法添加 Lumetri 等任何特效） |
| `clip.setSpeed()` | `undefined`（变速不可写） |
| `qvt.getClipAt()` | `ReferenceError: not a function`（QE DOM 轨道方法列表为空） |
| `track.addTransition()` | 不存在（标准 DOM 无转场能力） |
| 音频组件属性 `isKeyframable()` | 全部 `false`（Internal Volume/Channel Volume Stereo 组件存在，音量值 0.1778≈-15dB，但无法脚本关键帧） |
| `File > Scripts > Run Script` | 菜单不存在 |
| 调整图层/文字/嵌套创建 | DOM/QE DOM 均无接口 |

### 4.3 组件探查实证
- 视频 clip 组件仅 2 个：`不透明度(AE.ADBE Opacity)` + `运动(AE.ADBE Motion)`
- 音频 clip 组件 2 个：`Internal Volume Stereo`（2 属性）+ `Internal Channel Volume Stereo`（33 属性）
- 日志中中文显示为乱码是 ExtendScript 写文件的编码问题，**内存中匹配中文属性名正常工作**（v3.0 关键帧成功证明）

## 八、陷阱全集（血泪经验，必读）

1. **不要重复产出已完成的成果**：节拍剪辑/关键帧/转场/音频淡入淡出已完成，勿重做
2. **转场成果未保存**：新会话第一件事 Ctrl+S（或先确认标题栏 `*` 是否还在）
3. **强杀 PR 的代价**：启动必现崩溃横幅+可能 CEF 黑屏模态框；尽量不杀，必须杀后按 5.3 处理
4. **Ctrl+S 触发 bridge 的条件**：PR 有焦点 + 无任何模态对话框 + 项目处于脏状态；失败就改用重启 PR 方案
5. **脚本必须带项目等待循环**：bridge 在启动瞬间消费命令，此时项目未加载（实测 90s 内对话框处理完即可用）
6. **序列名会被 keepDirty 改写**：`VinlandEdit_d4318` → `_d704` → ……，按索引 `app.project.sequences[0]` 取
7. **PowerShell 内联 Python 必踩转义坑**：一律写 .py 文件再执行
8. **ExtendScript 无定时器无原生 JSON**：用 `$.sleep()`，JSON 用 polyfill（v3 脚本已内置）
9. **日志中文乱码不影响功能**：内存中字符串匹配中文正常
10. **编辑点导航**：上下方向键无效（无轨道目标定位），用时间码直接输入
11. **BGM 比视频短**：bgm 23.15s < 视频 27.69s，淡出在 BGM 自身尾部
