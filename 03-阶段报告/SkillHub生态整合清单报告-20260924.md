## 七、优先级排序与集成路径

**Tier-1（P0，随主线走）**
1. Resolve Studio 21.1 官方 MCP 评估——路径：备份 21.0.3 环境→升级→用 `resolve_engine` 现有 E2E 用例打等价性（SetProperty/CDL/渲染队列）→双桥并存，Lua 转 fallback；
2. 存量缺陷清零——本次已修 3 处（gateway 认证、vrs/effects 导入链）；余下 conftest token、blenderproc 入 `.venv`、`kb_loader` shim。

**Tier-2（P1，高收益）**
3. 词级粗剪链路——路径：whisper 词时间码→静音/赘词检测→生成 EDL/FCPXML→`davinci_timeline` 导入（对照 Alex 四技能拆解）；
4. Skill schema v0.1 + Top 50 脚本封装——路径：定义 YAML 元数据（借台账标注法）→`skill_loader.py` 扩展消费→`mcc skill` CLI；
5. Blender VSE 无头时间线评估——作为 Resolve-GUI 不可用时的第二降级位（FFmpeg 之上、Resolve 之下）。

**Tier-3（P2，卡位与生态）**
6. OTIO 时间线互换层（行业空白，差异化卖点）；
7. arjun988/blender-skills、kajisho5/ffmpeg-skill 收编（先过 skill 评测流程再入库）;
8. Remotion / Lottie 交付端；分发面 MVP（静态清单 HTML）。

**不集成清单**（显式决策，避免收藏夹式膨胀）：Houdini、3ds Max 双件、SoX（FFmpeg 已覆盖）、Runway（云端依赖与本地化路线冲突，保留接口不保留默认）。

## 八、深度分析段落

把四页台账叠起来看，公开生态给"剪辑自动化"划出的真实能力边界是：**无头世界（FFmpeg/MoviePy/Blender VSE/Whisper/yt-dlp）已经焊成完整产线，GUI 世界（AE/Resolve/FCP）只剩说明书**。本项目恰好站在缝合线上——AE Bridge、Resolve Lua 桥、BlenderProc 把三个"需 GUI/专有 API"的岛都打通了真执行面，这是公开台账做不到也没有的。因此生态策略应当是：

1. **对内**：把"手"的能力（JSX 链、resolve_engine、bpy）按台账 schema 反向技能化，让深度能力可被 agent 编排复用（P1-7 是杠杆点，一次封装全局受益）；
2. **对外**：只消费"手"类站外资产且过评测门禁，地图类只吸收方法论（标注法/断点法/缺口法）；
3. **卡位**：词级粗剪与 OTIO 是台账自己承认的结构性缺口，也是本项目 VRS/管线能力的自然延伸——先做出来即是差异化，无需等生态补齐。

风险面重申：台账数据截至其调研日（2026-09-23），"Studio 21.1 官方 MCP"等关键情报未经我们独立验证，落 P0 评估而非直接依赖；外部沙箱站点已不可复访，本报告以 `tmp/grok_site/` 归档为唯一事实源。
