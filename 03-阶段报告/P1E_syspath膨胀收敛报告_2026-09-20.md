# P1-E：sys.path 膨胀收敛报告（2026-09-20）

> 来源：`TASK_STATUS.md` P1-E「测试套件归并（含 08-27 复验发现的 sys.path 膨胀
> ~300 条目收敛）」。
> 结论：**膨胀量实测确认（287 条中 243 条是重复）并已收敛到 43 条**；过程中
> 连带发现一个**死配置陷阱**（pyproject 里从未生效的 pytest 段）。

---

## 一、量化现状（先测再改）

用临时插件 `tmp/_pathprobe.py` 在全量收集后打印：

```
[PATHPROBE] collected=5857  sys.path=287  unique=44  dupes=243
```

- **287 条路径里只有 44 条是唯一的**，243 条是重复。
- 成因：历史遗留的 **283 处测试文件模块级 `sys.path.insert(0, PROJECT_ROOT)`**
  （根目录治理 2026-08-26 之前写下的"防导入失败"写法）。如今项目根已由配置注入，
  这些插入变成纯重复。
- 代价：每次 `import` 都要多走一遍重复条目的 stat/查找；"到底哪个路径生效"也变得不可读。

---

## 二、三项动作

| # | 动作 | 文件 |
|---|------|------|
| E1 | **配置层统一注入项目根**：`pytest.ini` 增 `pythonpath = .` —— 新测试文件不必再手写插入 | `pytest.ini` |
| E2 | **收集后 + 每用例前收敛**：`_dedupe_sys_path()` 按"保留首次出现"去重（保持原顺序 ⇒ 各唯一路径解析优先级不变），挂到 `pytest_collection_finish` 与 `pytest_runtest_setup` | `tests/conftest.py` |
| E3 | **防回涨闸门**（6 项断言） | `tests/test_syspath_hygiene.py` |

### 为什么去重不能只在收集后跑一次

首次实现只挂了 `pytest_collection_finish` → 单独跑闸门通过、**全量跑却失败**：
运行期有 37 条重复重新出现（部分用例在运行中动态导入模块，再次触发模块级插入）。
故补 `pytest_runtest_setup` 每用例前收敛（单次约 50 次 `abspath`，微秒级）。

### 防回涨闸门断言

1. 收集后 sys.path **无重复条目**（去重被误删即红）
2. 唯一路径数有上界（防"再插一条新路径"式膨胀）
3. 生效配置必须声明 `pythonpath`（否则历史写法会蔓生）
4. pyproject 不得再出现不生效的 pytest 配置段（见 §四）
5. 项目根确实在 path 上
6. `tests/` 下 `sys.path` 操作点数有上界（283 处是债务，不是模板）

## 三、实测收益

**导入解析微基准**（10 个模块，5 次取中位，全新进程）：

| 条件 | 耗时 |
|------|------|
| path=287（重复 243） | 0.430 s |
| path=43（去重后） | **0.132 s** |
| 差 | **省 ~0.30 s/进程（约 69%）** |

会话内模块只导入一次，故这不是"全量测试快 69%"——真实收益在**进程启动与首次导入
解析**（含测试内部 spawn 子进程的场景）。

**全量测试**：5817 passed / 0 failed / 46 skipped。注意**墙钟时间不能用于对比**：
近几轮 512s / 557s / 685s / 740s / 853s 波动由机器负载主导，与本次改动无关（如实记录）。

**告警噪音**：90 → 58 条。并有反向对照证明是配置合并所致 —— 同一文件加
`-W default::DeprecationWarning` 立刻复现 2 条弃用告警，不加则 0 条。

## 四、连带发现：pyproject 里的死配置陷阱

`pyproject.toml` 有一段 `[tool.pytest.ini_options]`，**从未生效** ——
pytest 配置优先级是 `pytest.ini > pyproject.toml > tox.ini > setup.cfg`，
而仓库根存在 `pytest.ini`。

死段的实际代价（不只是冗余）：

- 里面的 4 个 marker（slow/integration/real_ae/silhouette）不生效；
- 里面的 **`filterwarnings`（忽略弃用告警）不生效** —— 维护者以为已经关掉了告警，
  而实际每个测试会话都在刷屏。这是"改了没效果"型陷阱：比没有配置更糟。

处理：把 marker 与 filterwarnings **并入 `pytest.ini`**（尊重项目原意），
删除死段并在原位留注释说明原因与去向；闸门断言防止它再被写回来。
