### 7.4 三条最相关技能的正文精读（深度分析）

#### a) `davinci-resolve` —— 它替我们钉死了一个架构事实

技能正文 Guidelines 原文：

> "DaVinci Resolve must be running for the scripting API to work; scripts connect to the
> active instance and **cannot launch Resolve headlessly**"

**这句是理论；我做了实测复现，成了事实**（§4 表）：`fuscript.exe -lua` 无头跑得出退出码 0，
脚本里 `Resolve()` 在 App 未运行时返回 `nil`，App 起来后立刻返回
`DaVinci Resolve Studio` / `21.0.3.7` / 29 个项目。

**这对主线的意义**：DaVinci 轨**不是无头渲染器，是"对活 GUI 实例的远程控制"**。
所以它只能进"人在场的交互/半自动通道"，**不能进无人值守的 CI 链**（对比：我们 AE 轨的
`aerender` 那条是能无人值守的）。这条结论比"装没装"重要得多，也是本轮最大的认知修正。

**能力差集**（技能给的操作面 vs 我们 `integrations/resolve_engine.py` 已覆盖）：

| 能力 | 本仓现状 | 差集 |
|------|---------|------|
| 媒体池导入/建时间线 | 已覆盖 | — |
| CDL / LUT 调色 | 已覆盖 | — |
| 变速 / 变换 | 已覆盖（`SetProperty`） | — |
| **跨片段套调色** `ApplyGradeFromTimelineClip` | 未见 | **可蒸馏** |
| **渲染队列 + 进度轮询** `AddRenderJob`/`GetRenderJobStatus` | 部分 | **可蒸馏（进度可观测性）** |
| **时间线导出 EDL/AAF/FCPXML** | 未见 | **可蒸馏（跨工具交接）** |
| **Fusion TextPlus 字幕叠加** | 有 `davinci_fusion.py` | 可对照补齐 |

#### b) `blender-vse-pipeline` —— 本批唯一能给"运镜质量"提供**新机制**的候选

它给的是真·无头剪辑路径：`blender --background --python script.py`，并且 VSE 的
**TRANSFORM 效果支持关键帧曲线 + 浮点精度变换**，SPEED strip 做变速，GAMMA_CROSS 做跨溶解。

> ⚠️ **本节初稿有一处误判，已更正**：初稿写"我们当前的撞击走 ffmpeg `zoompan` 的
> **线性斜坡、没有缓动曲线**"。**这是错的**——我当时读的是 `zoom_out` 分支
> （`on*0.998+0.002`，那个确实是线性的），而真正的撞击包络在
> `ai/production_director.py:4980-5017`：**双鼓点对**模式是 `easeIn 4 帧冲 → 保持 → easeOut 6 帧弹回`；
> **其余**模式是 `peak*((on-fi)/2)²`（二次加速=冲）+ `peak*(1-t/5)²`（二次减速=弹）的 **7 帧包络**。
> **即：现行实现本身就是二次缓动、且表达式层面是浮点的。**

所以 POC 的正确假设**不是**"给它加缓动"，而是缩小为三条**可量化的候选差异**：
1. `zoompan` 的裁剪在**整数像素**上取整（浮点意图 → 整数量化落地）；
2. 缩放由 swscale 单趟完成（插值/混叠）；
3. Blender 侧可用**任意贝塞尔曲线**，而非固定的二次形状。

**POC 已执行完毕，结论与两份证据见** [Blender_VSE_撞击运镜_POC_2026-09-23.md](Blender_VSE_撞击运镜_POC_2026-09-23.md)。
一句话结果：

> **不接 Blender VSE（就"运镜质量"这条理由而言）。** 受控实验（24/24 帧可测）显示现行
> `zoompan` 包络的**落地保真度已经足够**——把落地曲线按 +1 帧对齐意图后逐帧误差 ≤0.006（≈1–12px），
> 释放段尾巴在动、没有"卡住再跳回"。**H1（整数取整量化）被证伪**，H3 的改进前提不成立。
> 也就是铁律①的正当结论："**已评测、不接**"。

**但 POC 顺手量出两个真问题（都不在 Blender 射程内）**：

1. **撞击包络大多被段边界截断**（像素确认，25/25 段可测）：v9 计划 45 次撞击 → 9 次被
   `0 <= f < n` 静默过滤根本不触发 → 进入渲染的 36 次里**只有 11 次完整播完包络**，
   25 次被截断、其中 **13 次末帧仍有 ≥53px 缩放**（切走时镜头还压在峰上，"闪回"没播出来）。
   **成因**：排程只校验了相邻撞击的 `min_gap`，没有校验"包络能不能装进本段"。
   **为什么之前没发现**：验收指标 `scripts/punch_beat_check.py` 的 `punch_times()` 是**从剧本还原**
   撞击时刻的，不看像素，也没有"包络完整度"这个概念 → 它报"36 次撞击"时，成品里只有 11 次完整。
2. **`zoompan` 的 `on` 对输出帧是 0 起**（4 个独立单帧尖峰一致）：`eq(on,0)` 影响输出帧 1。
   这使"包络是否晚 1 帧"取决于帧索引约定（代码 `0 <= f < n` 暗示 0 起 → 则晚 1 帧），
   **我尝试用成片独立复核但失败了**（该段细节低 + 基准帧跨镜头，残差 61）。故此项**只有受控实验
   证据、没有成品证据**，不当作已定性缺陷。

修法（a/b/c）是**风格取舍不是技术问题**，且都会改动已验收的母版 → **列为 P10 交用户裁决**。

成本侧的实测事实：**Blender 5.1.0 已装**（`D:\Blender\Blender 5.1.0\blender.exe`），
度量侧 `cv2 5.0.0` / `numpy 2.0.2` / `PIL 11.3.0` 均可用；POC 全程只读素材、只写 `tmp/`。

### 7.9 纪律条目（防复发）

1. **否定性结论的门槛**："未安装/不存在/未启用"必须 ① 扫全部盘符候选 + 注册表；
   ② 用能力探针反证。本轮 §4 的误判就是只查一个默认路径造成的。
2. **同一外部工具只允许一处路径发现**：新增调用点必须用 `core.resolve_discovery`，
   代码评审把"又出现一张 `xxx.exe` 候选表"视为缺陷。
3. **能力 ≠ 安装**：Resolve 的"装了"和"此刻能调"是两件事（活实例约束）。可用性探测要区分
   `installed` / `headless_ok` / `api_reachable` 三态，不要合成一个布尔。
4. **中文 Windows 上所有读进程命令行输出的地方必须显式 `encoding + errors`**：
   否则解码异常会在读取线程里静默吞掉 stdout，把"在跑"变成"没在跑"。
5. **返回值必须来自实际结果**：`x = self._execute_lua(...)` 之后不用 `x` 就返回一个空结构，
   与注解 `-> bool` 却无条件 `return True`，是**同一个病灶**——返回值与执行结果脱钩。
   这类缺陷不崩不报错，只给出静默错值，比崩溃难发现得多。新增外部工具调用方法时，
   先问："我返回的这个值，哪个真实信号能把它变成 False？"答不出来就是假返回值。
6. **许可证必须逐条核，不得用"整库许可"代替**（§7.6）。全库 1021 份里有
   3 份 AGPL-3.0 + 1 份非 OSI 许可，而其中 `deep-live-cam`（AGPL-3.0）只差一格分类口径
   就会被写进我们的候选名单。**口径一松，许可证结论就变**，所以"先分类、再逐条核许可"两步
   都要留痕，不能合并成"整库是 XX 许可所以都行"。
7. **测试不得锁实现细节**（§7.7c 第 2 条）：用"源码里有没有某个字符串"验证"有没有某个能力"，
   在重构时会误报，且会诱使你把删掉的实现加回去来"修测试"——**测试变绿而质量下降**。
   要锁的是**契约**（谁委托谁、发现器有哪些来源、优先级顺序），不是**字面量**。
8. **测试必须环境无关**：本文件 7 条用例曾"单跑全绿、进全量全红"，因为全量里有
   `_import_redirect` 钩子让 `puppet_automation` 变成可导入、settings 随即命中 `D:\app`，
   抢在用例设定的候选目录之前。**凡断言依赖"发现链会走到我这一级"的用例，
   必须把更高级的来源显式打桩**，否则结论随机器状态漂移。
