## 二、缺陷 A：repair 把踩点刀按堆丢弃（听感「踩点没跟上」的直接来源）

### 证据链

1. **同窗口对照**（把 no-repair 表裁到前 20s 公平比较）：
   管线原始切点表 7/68 = **10.3%** 强锚命中；repair 后 3/55 = **5.5%**，
   7 把踩点刀只剩 2 把。
2. **被丢刀的成分**：被 repair 丢掉的 16 把刀里 5 把是踩点刀 = **31.2%**，
   而基线踩点率只有 10.3% → **踩点刀被丢弃的概率是普通刀的 3 倍**。
3. **误报机制定位**（`analyze_cutpoints` C1 判据）：原判据只比 `hashes[fi-1]` 与
   `hashes[fi]` 两帧。实测真实视觉边界比 EDL 标称切点**滞后 1-4 帧**
   （变速/慢动作起步），比较因此落进新镜头内部 → 两帧相同 → 恒判「冻结」。
   慢镜正是网格量化锚（R-2026-0002）放踩点刀的位置：

   | 指标 | 踩点刀 | 非踩点刀 |
   |------|--------|---------|
   | k=0 处 hamming ≤ 10（误判 frozen） | **8/12 = 67%** | 13/75 = 17% |
   | 窗口 ±3 内存在强边界 (d≥15) | 12/12 | 75/75 |

   即：**87/87 刀在 ±3 帧内都存在强边界，每一刀都是真实可见的切**；
   k=0 判据在 27s 片上产生 21 个误报，±3 窗口判据产生 **0** 个。

### 修复

| # | 文件 | 变更 |
|---|------|------|
| A1 | `scripts/cutpoint_selfeval.py` | C1 改为**窗口判据**（±`freeze_window` 帧内取最大帧差），默认 3；`freeze_window=0` 可复现旧语义 |
| A2 | `scripts/cutpoint_selfeval.py` | `repair_cutpoints` 增加节拍感知：frozen 在 ±120ms 内**重锚到最近强鼓点**（找不到才丢）；min_gap 保留踩点的那把；audio_pop 微调方向优先朝强锚 |
| A3 | `scripts/cutpoint_selfeval.py` | 新增**节拍回归守卫**：修复表强锚命中率相对下降 >15% → 判定伤节拍，原表退回（`stats['guard']='aborted'`） |
| A4 | `core/beat_anchors.py` | 新建：锚点缓存唯一读取实现（`sha256(bgm)[:12]/anchors.json`），收敛此前散在三处的重复实现，缓存缺席 fail-safe 返回空表 |

## 三、缺陷 B：合成阶段静默丢 40 帧（画面比音乐早结束 1.67s）

### 现象与定位

视频流 25.333s / 608 帧，而剧本 648 帧；容器时长 = max(视频流, 音轨) = 27.0s
**恰好达标**，故五项硬指标全过、缺陷被层层掩盖。日志中「时长守卫」甚至打印
`[时长守卫] 25.33s → 裁齐 27.00s` —— 它只裁不补，却在无变化时仍报「裁齐」。

在合成链加装逐环节帧数核对后，一次渲染即锁定：

```
[帧数核对] 剧本 648 帧 / 片段合计 608 帧 (109 片段) — 差 40 帧
[拼接核对] 链 608 帧 = 成片 608 帧 ✓          ← 拼接无损，洗清嫌疑
```

**丢帧在片段渲染环节，两个叠加来源：**

1. **速度曲线段子片段各自取整（主因，−40 帧）**：段落按速度包络拆成 2-3 个子片段，
   各子片段帧数 `round(子段时长 × fps)` 独立取整；21 个曲线段的取整误差累积成 40 帧。
2. **漂移累加器亚帧级偏差（残余 −11 帧）**：`_tl_drift` 基于容器时长探测，
   存在系统性小偏差，逐段累积压缩时间线 —— 切点随之离开鼓点网格。

### 修复

| # | 文件 | 变更 |
|---|------|------|
| B1 | `ai/production_director.py` | 子片段帧数改为**边界帧号差分**分配（末位回填段计划帧数），Σ 子片段帧数 ≡ round(段时长×fps)——**帧级守恒**；子段时长按分配帧数回写，与 `-frames:v` 严格一致 |
| B2 | `ai/production_director.py` | 新增 `_reconcile_segment_frames()` **段级帧数对账**：每段实测帧数 ≠ `round(段时长×fps)` 时在**段末片段尾部**补齐（不移动段内子片段边界，不移动段间切点 → 鼓点网格不受影响） |
| B3 | `ai/production_director.py` | 新增 `_probe_video_duration()` / `_probe_nframes()`：**视频流**时长与帧数探测（容器时长含音轨，会掩盖短视频） |
| B4 | `ai/production_director.py` | 「时长守卫」拆分为超长→裁、偏短→明确标注 `DURATION_SHORT` 交付缺陷，**不再谎报裁齐** |
| B5 | `ai/production_director.py` | `RenderResult.video_duration` + 汇总打印「视频流 vs 容器」一致性；`_validate` 的 ffprobe 增加 stream duration |
| B6 | `ai/production_director.py` | 新增 `_concat_filter()` **滤镜级 concat 兜底**：`-f concat -c:v copy` 在输入参数不一致时会静默丢弃后续输入且返回 0；滤镜 concat 逐输入解码归一化（scale+pad+setsar+fps+format），是丢帧场景的最终兜底 |
| B7 | `scripts/check_delivery_spec.py` | 新增交付项 **「音视频等长」**：视频流短于音轨 >0.15s → FAIL（堵住容器时长掩盖缺陷的盲区） |

### 验证（v4 渲染实测）

```
[帧数核对] 剧本 648 帧 / 片段合计 637 帧 (109 片段) — 差 11 帧
[段级对账] 段末补帧 11 处 (计划 648 帧 / 修正前 637 帧)
[拼接核对] 链 648 帧 = 成片 648 帧 ✓
视频流: 27.00s ✓ (与容器一致)
```

## 三之二、缺陷 C：运镜撞击触发源失焦 + 触发面过窄

> 本缺陷经**三轮听感迭代**收敛（v4「拉镜不如之前踩点」→ v6「不够，没跟小提琴
> 节奏变换，视觉冲击力不到位」→ v9 定稿）。三代参数与实测见下表。

### 机制

「镜头动感踩点」在本管线里由**脉冲运镜**实现：对剧本派发了 `push`/`zoom_in`
的镜头，在每个 onset 处做一次"拉进-闪回"（3 帧冲近 + 8 帧弹回 = **11 帧包络**）。
触发源是 `seg.onset_times` ← `self._onsets` = **全部鼓锚（无强度过滤）+ 全部旋律锚**。

### 量化定位

| 版本 | 撞击 | 密度 | 强鼓点占比 | 铺垫 / 爆发 | 包络占空比 |
|------|------|------|-----------|------------|-----------|
| 20s 集成版（用户认可其运镜） | 22 | 1.10/s | 18.2% | 0.21 / 1.46 | 50% |
| 27s v4（被吐槽） | 54 | 2.00/s | 31.5% | 0.21 / 3.92 | **92%** |

- **包络占空比 = Σ(撞击 × 11 帧) / 总帧**。v4 达 92% → 缩放几乎从不回落，
  相邻撞击经 `max()` 叠加成持续晃动，眼睛读不出离散"命中" → 听感"不踩点"。
- 触发源在 0-27s 有 ~10 事件/秒，而人耳感知的强拍（kick/snare ≥ 0.5）只有 1.07/s
  —— **三分之二的撞击打在弱鼓点或旋律音上**。
- 爆发段（14-27s）旋律锚 4.46 事件/秒 ≈ 节拍的 2 倍，与 0.46s 包络**必然重叠**。

### 修复（逐轮收敛）

| # | 文件 | 变更 |
|---|------|------|
| C1 | `ai/production_director.py` | 新增 `punch_onsets_from_anchors()`：鼓点侧触发源只取**强鼓锚**（`PUNCH_STRENGTH_DEFAULT=0.5`） |
| C2 | `ai/production_director.py` | 新增 `_punch_melody_allowed()` + `MELODY_PUNCH_STRENGTH_DEFAULT=0.85`（≈P80，"节奏变换/重音级"）：小提琴事件按**强度门槛精选**后参与撞击，而非全量旋律锚（全量 4.4-5.9/s 必然与包络重叠）。旋律范围默认 `all`（全曲跟随），`drop` 退回 2026-09-05 的原始范围 |
| C3 | `ai/production_director.py` | 包络提速 **11 → 7 帧**（3+8 → 2+5），峰值 **0.12 → 0.15**（顶到既有 1.15 上限）：用户 2026-08-14 定义"冲击力来自**快起快回**"，故以更快的起落换更硬的撞击；上升速率 0.04 → 0.075/帧（+87%） |
| C4 | `ai/production_director.py` | `PUNCH_ELIGIBLE_EFFECTS` 纳入 **static**：撞击改由音乐事件驱动后，落在静止镜头上的小提琴重音不该被忽略（静止镜头里撞击对比度最高）。平移/斜移类仍不承载撞击 |
| C5 | `ai/production_director.py` | 常量集中为单一真相源（`PUNCH_PEAK`/`PUNCH_ATTACK_FRAMES`/`PUNCH_RELEASE_FRAMES`/`PUNCH_ENVELOPE`/`PUNCH_MIN_GAP_FRAMES`），渲染表达式与质检脚本共用 |
| C6 | `scripts/punch_beat_check.py` | 新建运镜撞击体检脚本（此前项目只有切点指标，运镜维度是盲区），参数直接引用渲染端常量 |
| C7 | `ai/production_director.py` | 渲染日志新增 `[punch] 撞击触发源: ...` 行，显式给出实际生效的触发源构成与包络参数 |

### 验证（三代对照）

| 配置 | 撞击 | 铺垫 | 爆发 | 包络占空 | 强鼓点占比 |
|------|------|------|------|---------|-----------|
| v4 全量 onset+旋律，包络 11 帧，间隔 4 | 54 (2.00/s) | 0.21/s | 3.92/s | 92% | 31.5% |
| v6 仅强鼓点，包络 11 帧，间隔 8 | 20 (0.74/s) | 0.00/s | 1.54/s | 23% | 100% |
| **v9 强鼓点∪小提琴≥0.85，包络 7 帧，间隔 7，含 static** | **36 (1.33/s)** | **0.64/s** | **2.08/s** | **39%** | **50.0%** |

- v4 → v6 修的是"**重叠**"：全量触发源让缩放从不回落，读不出离散命中。
- v6 → v9 修的是"**触发面过窄**"：小提琴被完全排除 + 只允许 push/zoom_in 承载，
  导致铺垫段 0 次撞击、小提琴重音全部落空。
- v9 的两条硬约束同时成立：**每次撞击间隔 ≥ 包络（不重叠）** + **小提琴
  重音/音变点必有响应**（铺垫 0.64/s、爆发 2.08/s）。
- 切点指标无回退（强锚 15.56% → 15.22%，任意鼓锚 67.78% → 67.39%，旋律锚 95.65%）。

## 五、遗留与建议

1. **`repair_cutpoints` 的裁帧能力**：`_reconcile_segment_frames` 只补不裁（段超长仅记录
   `trims`）。段超长会打印告警但不自动处理，需人工或后续补重渲路径。
2. **极端短段退化**：`render_dur < 0.125s` 且 3 个子片段时，帧级守恒分配无法给每片 ≥1 帧
   （6000 次随机模拟中 18 次，最大偏差 1 帧），此时打印 `[帧数守恒]` 告警。
3. **`_probe_duration` 的失败回退值 60.0**：异常时返回 60.0 是个隐藏地雷（会让时长守卫
   误判为超长）。本轮未改动（避免影响面扩大），建议后续改为返回 0 并显式标注不可测。
4. **码率口径**：7.68 Mbps > AKROSS 偏好的 6.0。属历史各版一致的 WARN 项，
   若要在意可用两遍编码压到 ~4 Mbps（`check_delivery_spec` 已给命令）。
