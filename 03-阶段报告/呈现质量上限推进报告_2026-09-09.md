## 二、音频问题诊断

### 2.1 症状（三重独立测量确认）

| 工具 | 结果 |
|------|------|
| `loudnorm` | I=-6.78 LUFS / TP=**+2.48 dBTP** / LRA=5.20 |
| `ebur128` | I=-6.7 LUFS / LRA=5.3 |
| `volumedetect` | max_volume **0.0 dB** |
| 逐样本分析 | 1054 样本贴顶（0.037%），**6 个连续削波簇** |

对比：流媒体标准 -14 LUFS / -1.5 dBTP。当前响度高出 **7.2 LU**，真峰值超标 **4 dB**。

### 2.2 根因

**`core/sfx_layer.py` 的混音链缺少限幅器**：

```python
# 修复前
parts.append("".join(mix_labels) + f"amix=inputs={len(mix_labels)}:normalize=0[outa]")
#                                                                          ↑ 直接进 AAC 编码
```

`normalize=0` 关闭了 amix 的自动归一化，多路 SFX + BGM 叠加后必然超过 0 dBFS，而后面没有任何限幅。

**旁证**：`master.mp4`（更早版本）有 **64 处削波簇**，`master_hr.mp4` 6 处——说明链路一直存在此问题，只是被后续处理部分掩盖。

### 2.3 修复

```python
# 修复后
parts.append("".join(mix_labels)
             + f"amix=inputs={len(mix_labels)}:normalize=0,"
               "alimiter=limit=0.8414:attack=5:release=50:level=disabled[outa]")
```

`limit=0.8414`（-1.5 dBFS）为 AAC 编码过冲留余量——实测 run61 的 AAC 过冲约 0.5dB。

## 三、实测教训（三条，均写入代码注释与测试）

### 3.1 `loudnorm` + measured 参数不可靠

第一版用两遍 loudnorm（测量 + 线性归一），结果响度停在 **-12.59 LUFS**，偏离目标 -14 达 1.4 LU。

**改用直接增益**：`volume=(目标LUFS - 实测LUFS)dB` → 精确到 **-14.09 LUFS**。

### 3.2 `alimiter` 的 `level` 参数是陷阱

默认 `level=auto` 会做**自动增益补偿**，实测把响度抬高约 1.4 LU（-14.1 → -12.6）。

> 修正：先前判断"`level=0` 等价于 auto"**不准确**。受控信号实测中 `level=0` 与 `level=disabled` 结果相同（-1.1 dB），但代码中已统一用显式的 `level=disabled` 以避免歧义。

### 3.3 AAC 编码不改变响度

wav→aac 单独转码：两者都是 -14.0 LUFS。最初观察到的偏差来自 `alimiter`，不是编码器。
