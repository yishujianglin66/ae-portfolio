# cut_visibility 根因诊断报告（B1 / R1）

> 日期：2026-09-09 · 对象：`output/unified_run61/polish/master_hr.mp4`（当前最佳候选）
> 方法：新增逐切点诊断工具 `scripts/cut_visibility_diag.py`（与官方口径逐值对齐）+ 交叉验证 `scripts/cutpoint_selfeval.py`
> 结论性质：**指标本身数值病态——0.8698 是帧边界舍入的产物，不可作为可靠质量度量**

---

## 零、最重要的发现（先说）

**`cut_visibility` 这个指标在数值上是病态的。**

对同一批切点做 **±0.5 毫秒**的微扰，指标在 **0.3511 ↔ 1.1360** 之间跳变（3 倍波动）：

```
扰动 -0.0005s → 1.1360
扰动 +0.0000s → 0.8698   ← 报告值
扰动 +0.0005s → 0.3511
```

**成因**：指标比较 `frame(t - 1/24)` 与 `frame(t + 3/24)`，而 ffmpeg 的 `-ss` 在帧边界存在临界行为——时间值落在帧时间戳**前 0.5ms 内**会回退到上一帧，落在之后则命中目标帧。run61 的切点恰好都在帧边界附近，因此结果由浮点舍入决定。

**推论**：
1. 0.8698 与参照集均值 0.8392 的"3pp 差距"**在噪声范围内**，不构成真实的品质差距证据。
2. R1 原定的 `0.870 → ≥0.92` 验收线**无法作为有效目标**——该指标可能因重渲时的微小时间抖动而自发跨线。
3. 需要**替换度量口径**（见 §六）才能真正推进 R1。

## 三、交叉验证：两套独立检测器

`scripts/cutpoint_selfeval.py`（吸收 video-use "每切点 self-eval"）对同一成片：

```
verdict: FAIL
issues: 132 = frozen_cut 76 + audio_pop 56
```

frozen_cut 判据：切点两侧 ahash/dhash Hamming < 10。

**交叉结果**：26 个弱切点（vis<0.2）中 **16 个（62%）与 frozen_cut 对应**（±0.06s）。

### 两把尺子不等价

| t | cut_visibility | frozen_cut |
|---|---------------|-----------|
| 4.875 | 0.8327 | 是 |
| 25.500 | 1.0666 | 是 |
| 13.458 | **0.0529** | 是 |

→ 感知哈希会误报帧差很大的切点；**验收应以 cut_visibility 为主，frozen_cut 作候选定位**。

## 四、指标病态性的完整证据链

### 4.1 同一时间值、不同格式化 → 20 倍差异

```
-ss 13.416667  → 帧差 1.1757
-ss 13.417     → 帧差 0.0529
```

ffmpeg 在帧时间戳前 0.5ms 内会回退到上一帧。

### 4.2 同一切点、截断 vs 精确 → 750 倍差异

| 切点表示 | 差异值 |
|---------|--------|
| `21.708`（截断） | **1.0510** |
| `21.708333`（精确） | **0.0014** |

### 4.3 全样本扰动测试 → 3 倍波动

| 扰动 | 官方口径 |

| -0.0005s | 1.1360 |
| 0 | 0.8698 |
| +0.0005s | 0.3511 |

| 原报告说法 | 实测结论 |
|-----------|---------|
| "差距源于切点帧内容，参照集为硬内容跳变" | 方向部分成立（确有 76 处 frozen_cut），但**指标本身噪声主导，0.8698 不可靠** |
| "先修 `tmp/post_freeze.py` 滤镜图拼接 bug" | **无关**。`post_freeze.py` 是后期冻结帧实验脚本；`AEKV_IMPACT_SHIFT` 在 `build_master_polish.py:875`，是定格内容平移 |
| "AEKV_IMPACT_SHIFT=1 重评" | 该开关改变"定格帧显示哪一帧"，**不解决切点两侧相同，也不解决指标病态** |

| "cut_visibility 0.870 → ≥0.92" | **验收线不成立**：±0.5ms 微扰即可让指标在 0.35-1.14 间跳变 |

## 六、建议的替代口径

当前指标的两个缺陷：① 帧边界数值不稳定；② 采样 12/110 点，代表性差。

**替代方案（建议 R1 采用）**：

1. **帧号对齐 + 容差平均**：比较 `frame(fn-1)` 与 `frame(fn+1)`、`frame(fn+2)`、`frame(fn+3)` 三对的均值，消除单点舍入敏感性。
2. **全切点统计**：不做 12 点采样，报告全切点的均值 + p25/p50/p75（与参照集同口径重算）。
3. **双指标并用**：`cut_visibility`（帧差）+ `frozen_cut 率`（感知哈希），两者同时改善才算真实提升。
4. **参照集需重算**：现参照集 0.8392 同样受此影响，替换口径后必须整体重跑才能比较。
