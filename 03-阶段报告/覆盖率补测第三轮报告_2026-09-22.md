## 二、覆盖了什么

### `ai/material_intelligence.py`（+36 项）

承担一条**业务红线**的纯逻辑层，此前无断言：

- `normalize_ip`：别名精确匹配（大小写不敏感）、**子串匹配≥3 字符且长者优先**
  （docstring 例 `命运之夜：无限剑制 → FATE` 亦已验证）、无匹配回原样；
- `ip_matches`：**空关键词=True**（调用方靠它"不过滤"选全部）、空名字=False、双向子串回退；
- `MaterialIntelTag.matches_ip`：**教程/特效演示类恒 False**（绝不能混进 IP 成片）、
  低置信标签（<0.3）不作正向证据、非严格模式的描述/文件名证据、
  **严格模式的高置信负面排除**（主 IP 被 ≥0.8 置信度识别为别的作品时，
  仅凭描述里的偶然关键词不得匹配，阈值边界 0.5 不触发）；
- `MaterialIndex`：`filter_by_ip` 空关键词返回全部；`select_for_ip` 的
  **matched/mixed/unknown/excluded 四分类**与 `allow_mixed` 开关；`to_dict` 字段面
  （并纠正了我的一个假设：`ip_names` 是 property，不在序列化字段里）。

### `pipeline/flagship_runner.py`（+20 项）

模块级"坏情况下照样不崩"的容错语义：

- `run_cmd`：stdout/stderr 解码为 str；**非零退出码如实返回而不抛**；
  **超时抛 TimeoutExpired 而非挂死**（P0-1 加固点）；stderr 在失败时被捕获；
- `md5_file`：空文件与跨 8192 块读取的摘要正确；缺文件抛 FileNotFoundError；
- `emit_event`：JSONL 追加、payload 展开到顶层、**写失败只告警不抛**；
- `write_manifest_safe`：写 run 目录 + **镜像到 reports/flagship_runs/**；
  **run 目录被删时自愈重建**（这正是它存在的理由）；缺 run_id 用默认名镜像；
- `ffprobe_json`：真实小视频取到 format/streams；**缺文件返回空 dict**；
- `critic_gate`：通过/告警落事件；**abort 先落事件再抛 CriticAbortError**（证据不丢）。

## 三、测量方法发现：**单文件覆盖率有 ±15 行级噪声**

### 现象

`core/llm_gateway.py` 本轮未覆盖行 **743 → 758**（覆盖率 53.73% → 52.96%），
但该模块的测试集在两轮之间**只少了我在上轮删掉的 39 项文件**（替换后的 19 项文件
在第五、六两次全量运行中都在）。也就是说：**删除与新增其它模块的测试，
可能让某模块的被测行数发生 ±15 行级漂移**。

### 归因（未定论，如实标注）

最可能是**导入时序 / 追踪附着时机**类效应：某些测试在 coverage 追踪启动前就
import 了模块（coverage 自己的 `module-not-measured` 警告描述过这类情况），
增减测试会改变"谁先生效"的顺序。项目此前已记录过同类噪声。

### 对报告口径的修正（重要）

1. **只有大幅增量才可作为战果**：本轮 `material_intelligence` −71 行、
   `flagship_runner` −20 行、上轮 `experience_harvester` −258 行属真实增益；
2. **±20 行以内的变动视为噪声**，不作结论；
3. **更正上轮表述**：第二轮我写"新增该文件后未覆盖行数**一字未减**（743 → 743）"
   —— 该观测数值正确，但据此断言"完全冗余"过强：在 ±15 行噪声下，
   真实增量可能是 0~15 行。**当时的删减决定仍然成立**（既有测试确实已断言
   sk-/api_key/password/PEM/JWT/压缩器），但结论应表述为
   "**无可测量的增益**"而非"零覆盖贡献"。

## 四、过程记录

- **安全扫描器提示 MD5 弱算法（非阻断）**：本模块的 `md5_file` 是**素材指纹**
  （缓存/去重），不是安全原语；换 SHA-256 会改变既有调用方比对的摘要值，
  属行为变更而非修复。**保留 MD5 并记录理由**。
- **替身对象要跟真类型走**：`critic_gate` 测试最初自造轻量 verdict 替身，
  结果 `CriticAbortError` 依次要 `stage`、`value_estimate` 字段、逐个暴露；
  改用真实 `CriticVerdict` 后一次通过。**教训：替身只该替"外部依赖"，
  不该替"同仓数据类型"**。
- 一次 `to_dict` 断言写错（把 property 当序列化字段）——测试与实现不符时
  **以实现为准**，已按真实字段面重写。
