# 高级融合镜头落地报告（2026-09-25）

## 需求

用户：「挺好的，效果不错，只差高级剪辑技巧融合镜头了」——成片 94/94 段全是硬切，
12 类 ffmpeg xfade 融合转场库从未生效。

## 三个根因（层层叠加，全部实锤）

1. **变速禁令过时**：`_xfade_for` 对 speed≠1.0 一律强制硬切（2026-08-12 依据
   "变速版 98% 切点滞后"）。但 v21b 帧量化+链尾一次性补偿重构后从未复测，
   而 88% 的段是变速段——融合镜头被锁死在 12% 的镜头上。
   **受控实验**（tmp/xfade_drift_exp2.py，真实 _extract_clip+_xfade_chain，
   合成色块源逐帧定位）：1.5x/0.8x/0.55x 三处融合边界漂移全部 ≤2 帧
   （±83ms），帧守恒 32/32 精确 → 禁令解除。
2. **beat_lock 全局降级**：unified_edit 传 `beat_lock_hard_cuts=True`，渲染前把
   **所有**非 cut 转场砍成硬切（2026-09-02 治"渐变糊切点"，实测 p50 偏 122ms）。
   规划器分配的融合转场全被这道闸吞掉。
3. **弧首段严格判等失效**：边界经帧网格量化（实测 arc_start=0.256s vs 首段
   起点 0.25s），`abs(seg_start-arc_start)<1e-6` 永不成立 → 段落融合从未被
   分配过。另有一个物理事实：成片中位镜头仅 0.25s（6 帧），标准叠化
   (0.25-0.35s) 比镜头还长，渲染端安全化钳制 `t ≤ min(d前,d后)-0.1`
   （容不下就降级 cut）是必要的兜底。

## 实现（全部在 ai/production_director.py）

- `_xfade_for`：解除变速禁令（保留 V23_FORCE_CUT 总开关），注释附实验证据。
- `SECTION_FUSION_MAP` + `_section_fusion()`：弧切换点融合词典（按能量走向选型：
  蓄力→爆发=白闪、铺垫→蓄力=zoom 上升感、→尾声=fadeblack 收、未列出=真叠化、
  **进入喘息一律硬切**——瞬间静止是节奏设计）。密度预算：融合至少隔 3s、
  段落白闪独立预算 8s（撞预算降级为叠化而非硬切）。
- 段对象打 `transition_params["section_fusion"]=True` 标记；beat_lock 凭标记豁免
  （密集段内转场仍全量降级保踩点纯度）；豁免后 `chain_last_extra` **按存活转场
  重算**（链尾补偿跟随，避免 r1_fixed_v1 的"补偿无人消耗→时间线拉长 14%"回归）。
- 时长安全不重复实现：渲染端转场安全化钳制统一兜底（0.25s 镜头容 0.15s 微融合，
  0.17s 镜头自动降级）。

## v2：小提琴重拍精确卡点（2026-09-25 用户反馈「不够高级，镜头没精确卡点小提琴重拍」）

**诊断**（cache/stems/9e00915a2a31/anchors.json 的 melody_onsets = 小提琴攻击音+音变点，带强度）：
- 强锚（≥0.85）全曲 38 个、片内 32 个；旧版切点仅覆盖 71%（≤1帧），中位差 217ms
- 融合边界落在能量弧边界上，离最近强锚最远 1.3s（9.0s 边界）
- 相位核查：片内漏覆盖强锚中 2 个（1.585/6.049s）距鼓点 192/290ms = 离格装饰音

**实现**（ai/production_director.py）：
- 锚数据接入：`_strong_melody_anchors`（≥0.85）/`_grid_melody_anchors`（全量）/`_anchor_drums`
- `_pick_anchor_hit()`/`_anchor_on_grid()`：取"最强且在鼓点相位上（±65ms 内有 kick/snare）"的锚
- **融合边界吸附**（弧循环前预计算）：最强强锚 ±0.5s → 任意在相位锚 ±0.12s（帧级校准）；
  flash 让白闪**峰值**对准锚（边界=锚+t/2），zoom/叠化让新镜头**落定**在锚上；
  头/尾位移表保持相邻弧接缝连续
- **强锚补切**：片内漏覆盖的在相位强锚，把最近中间边界移过去（≤0.25s、移后段长 ≥0.18s 才动）
- 离格装饰音不动（R-0001 教训：跟离格事件走会被判"完全不在点上"）

**验收**（purity5fusion，闸门 ✅ ACCEPT，648 帧守恒，切点自检 PASS 0 问题）：

| 指标 | purity4(v1) | purity5(v2) |
|---|---|---|
| 强锚 ≤1帧覆盖 | 23/32 (71%) | **25/32 (78%)** |
| 强锚 ≤1.5帧覆盖 | 78% | **81%** |
| 已覆盖锚的中位差 | 11ms | 11ms |
| 融合边界→锚偏差 | 13-60ms+离锚最远1.3s | **全部 ≤1 帧（16-18ms）** |

- 3 处融合保留并逐帧验证渐变签名（zoom@0.208/dissolve@5.708+8.958）；flash@14.33 因位移后
  空间不足被安全化降级为硬切——但切点本身落在锚点 1.7 帧内
- 未覆盖的 7 个强锚全部有明确理由：离格 ×2（设计豁免）、移动会碎段（<0.18s）×2、
  最近边界超窗 ×1、片外 ×2

## v3：踩点推进+震动感（2026-09-25 用户反馈「踩点的时间段可以推进镜头拉近，有震动感」）

**实现**（ai/production_director.py，punch 撞击运镜的两个分支）：
- 推近峰值 PUNCH_PEAK 0.15 → **0.22**（z 上限 1.15 → 1.22），双鼓点对分支同步
- **震动感**：包络期（2帧冲+5帧弹）画面逐帧交替抖动，幅度 = 输入宽的 0.8%
  （1920 宽 ≈ 15px），方向逐帧交替、相位随 onset 错开（`mod(on,2)`，非真随机、
  可复现），幅度随包络分数同步起落——与 zoom 放大余量恒满足不越界
- 两个开关：`AEKV_PUNCH_PEAK`（幅度）、`AEKV_PUNCH_SHAKE`（震动，0=关）
- 坑：ffmpeg 表达式求值器**不支持 `%` 运算符**，交替方向必须写 `mod(on,2)`

**验收**：
- 单段探针（tmp/shake_probe.py，受控色块源走真实 _extract_clip）：推近线性
  **+22.5%**（期望 22%）、包络期质心偏移 **7.5px**（期望 ~5px 量级）✅
- purity6fusion 交付：闸门 ✅ ACCEPT、648 帧守恒、切点自检 PASS 0 问题、

## v4：撞击运镜改走 AE 专业特效（2026-09-25 用户裁决「剪辑这种拿 AE 有专门特效做观感好点」）

**实现**（ai/ae_render_channel.py）：
- pulse 分支新增 **Position 抖动表达式**：以 Scale 撞击关键帧为锚，最近关键帧后
  7 帧内逐帧随机抖动（36px×二次衰减、posterizeTime 锁 24fps、seedRandom 按帧
  确定性）；comp/layer motionBlur=16 samples 让抖动带**真实运动模糊**——
  ffmpeg zoompan 给不了的质感
- **桥复活的关键**：AE 必须用 `os.startfile` 启动——`subprocess.Popen` 起的 AE
  不执行 Startup 脚本（加载器一行日志不写、ping 无结果，但进程/窗口正常）
- **坑**：ffmpeg 表达式求值器不支持 `%` 运算符（交替方向写 `mod(on,2)`）

**成果**（purity7/8/9 三轮复现）：AE 通道端到端 **12/12 撞击镜头**渲染成功
（桥构建合成 → aerender 56s → 并行规范化），首次在融合系列里真正走通双通道。
