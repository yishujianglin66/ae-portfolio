## 二、发现一：套件级**顺序耦合陷阱**（生产模块被 reload）

### 现象

我为 `unified_pipeline` 写的配置测试**单独跑全绿**，但全量跑 **4 项全红**：

```
AssertionError: assert <PipelineMode.TEXT_TOPIC: 'text_topic'>
                     is <PipelineMode.TEXT_TOPIC: 'text_topic'>
```

两侧打印完全相同却 `is` 不等 —— 这是**两个同名同值的枚举类对象**。

### 根因（二分定位）

`tests/test_formal_spec.py:200` 为验证"绑定幂等"执行
`importlib.reload(pipeline.unified_pipeline)`。`reload` 在**原模块对象上重新
执行代码、换掉全部类对象**，于是：

- 我的测试模块在**收集期**导入并绑定的 `PipelineMode` 是**旧**类；
- 而 `detect_mode()` 方法体引用模块全局，reload 后指向**新**类；
- 两者 `is` 不等 → 与该测试同跑必红，单独跑必绿。

### 处理

把我的断言改为**按 `.value` 比较**（对 reload 免疫、不依赖执行顺序），并在测试
类 docstring 里写清这条陷阱与定位过程。**未改** `test_formal_spec.py` —— 它验证的
是真实现象（绑定区幂等），问题在"其他测试用身份比较"这一侧。

> 给后续补测的提醒：**枚举/类身份比较（`is`）在会被 reload 的模块上不可靠**；
> 写测试时优先比数值语义（`.value`），或在同文件内 import 后再取属性。

## 三、发现二：**重复补测复发**（第二次踩同一个坑）

`unified_pipeline` 的配置钳制层，`tests/test_pipeline_config_validation.py`
（144 行 / 14 项）**已经完整断言**：0/负数→1、`False`→3、浮点→2、数字串/非法串/None、
超大→5、区间内保值、主循环 int 契约，以及质量分的负值/超 100/非法类型/bool 回退。
这就是该文件未覆盖行只动 5 行的原因（在噪声带内 = 约等于没动）。

### 处理（同第二轮做法）

把该文件从 **57 项裁到 16 项**，删掉与既有测试重复的两块（迭代数、质量分钳制），
只留**确属独有**的：`semantic_score_weight` 钳制、`visual_judge_min_score` 钳制、
`visual_judge_backend`/`quantize` 白名单（**含"校验用 lower() 但原样保留大小写"的
既有行为**）、`detect_mode()` 四分支、`StageResult` 时间戳自填、枚举值、`to_dict` 字段面。
并在文件内留下注释说明"为何不在此重复钳制测试"。

### 教训升级（第二次了，必须改方法）

第二轮我总结过"**补测前先 grep 既有断言**"，本轮仍然复发 —— 因为我那次只 grep 了
"哪些测试**引用**这个模块"，没 grep"**同一行为**是否已被断言"。方法修正为两步：

1. grep **模块名/函数名/字段名**，列出所有同域测试文件（本轮 `test_pipeline_config_validation.py`
   的名字**就是**我准备测的那一层 —— 我甚至在同一条组合命令里跑过它并看到它全绿，却没反应过来）；
2. 把候选断言按**行为**逐条与既有断言比对，**只写差集**；
3. 写完先跑"新旧同跑"确认不重复也不冲突，再跑全量取数。

## 四、`davinci_resolve_integration.py` 覆盖了什么（19 项）

- **`ColorGradeArtifact`（跨工具互通的标准调色描述）**：`to_dict` 契约键、
  `from_dict` 对缺字段**取默认而不 KeyError**、`to_json` 保留中文（`ensure_ascii=False`）、
  `created_at` 空则序列化时补、`save` 自建父目录、`save→load` 往返一致、
  缺文件 `load` 抛 FileNotFoundError；
- **`ColorGradeNode`**：默认值 + **默认 dict 不共享**（dataclass 经典陷阱）；
- **可执行探测**（不触发真实 Resolve，`subprocess.run` 打桩）：
  `_find_resolve_exe` 两种目录布局 + 都存时优先扁平布局 + 缺失返回 None；
  `_check_availability` 的 fuscript 邻位探测、"退出码非 0 但横幅含 DaVinci 也算可用"、
  输出无 DaVinci 则不可用。
