## 二、实际选型（与方案的差异）

方案原定"Wan2.2-TI2V-5B GGUF Q4（7-9GB）"。实际落地发现**本机 ComfyUI 已有 Wan 系资产**，调整如下：

| 组件 | 实际使用 | 说明 |
|------|---------|------|
| 主模型 | **Wan2.1-I2V-14B-480P GGUF Q3_K_M**（8.0GB，city96 量化，hf-mirror 下载） | 14B Q3 与方案"Q4 7-9GB"同档；480p 版本选型理由见 §三 |
| 加速 | lightx2v_I2V_14B_480p 蒸馏 LoRA（rank64，本已在盘） | **8 步 cfg=1.0** 出片，替代 20+ 步 cfg=7 |
| Text Encoder | umt5_xxl_fp8_e4m3fn_scaled（本已在盘） | |
| CLIP Vision | clip_vision_h（本已在盘） | I2V 必需 |
| VAE | Wan2_1_VAE_bf16（本已在盘） | |
| 运行时 | ComfyUI 0.34.0 + ComfyUI-GGUF 节点（新装） | |

**净新增下载仅 8.0GB 主模型**，其余资产全部复用本机已有（`D:/ComfyUI/models/`）。

I2V（图生视频）而非 T2V 的理由：AMV 场景里空镜需要**与前后镜头风格衔接**（从成片抽帧作为首帧驱动），且 I2V 比 T2V 更可控。

## 五、过程中发现并修复的两个休眠 bug

`ai/aigc_generator.py`（AIGC 适配器套件）存在两处致命缺陷，导致**包括 ComfyUI 本地通道在内的全部适配器（DALLE/Imagen/Veo/Sora/Kling/即梦）从未发出过任何真实请求**——所有调用都 RecursionError 被上层 `except` 吞掉后返回 False：

1. **`_safe_urlopen` 无条件递归自调用**（重构事故）：
   ```python
   def _safe_urlopen(req, timeout):
       _validate_url(req.full_url)
       return _safe_urlopen(req, timeout=timeout)   # ← 调自己，必然 RecursionError
   ```
   修复：改经 opener 发起（URL 先过 `_validate_url`）。

2. **本地服务白名单缺失**：`_validate_url` 的域名白名单只有外部 API，`127.0.0.1` 不在内且被 loopback 拒绝——即使修了递归，ComfyUI 本地通道仍不可达。修复：新增 `_LOCAL_HOSTS`（127.0.0.1/localhost/::1），允许 `http://127.0.0.1:8188`（仅此端口），外部域名的私网拒绝逻辑不变。

**影响面**：此 bug 解释了 `core/gen_fx_provider.py` 为什么"永远走程序化降级"——注释声称"ComfyUI 一开自动升级质感"，实际通道从未打通。修复后该链路首次可用。

```bash

cd D:/ComfyUI && venv/Scripts/python.exe main.py --port 8188 --lowvram

# 4. 环境变量（离线）
HF_ENDPOINT=https://hf-mirror.com  # 权重走镜像
```

## 七、诚实边界

1. **质量层级**：480p + Q3 量化 + 8 步蒸馏，产物是"可用级空镜"（氛围运动自然），不是"4K 精细级"。作为转场/氛围插入镜头达标，作为主镜头不够。
2. **非劣检验的单次性**：本轮 1 个镜头 1 次 seed 的结果。批量混入（多镜头/多 seed）需更完整的统计，但首次闭环证明"链路真实可跑 + 品质不劣"。
3. **速度**：8 步采样约 8-10 分钟（含模型分载开销）。夜间批处理可行（与方案 E2-1 预判一致）。
4. **`gen_meta.json` 的显存采样字段**：本轮 VRAM 数据来自 ComfyUI 日志（分载明细），脚本内采样逻辑未触发完整路径（生成过快结束），下轮批量生成时补齐。
