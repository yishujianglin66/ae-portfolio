## 一、当前问题诊断（实测）

v23 成片 73 个切点中 14 个未命中拍/onset，拆解为两类：

| 类型 | 数量 | 根因 |
|------|------|------|
| 超短镜头微偏(0.04-0.42s) | 9 | 24fps 帧量化 + onset 精度亚帧级限制 |
| 音乐空档长镜头(正确) | 5 | 200ms 内无拍, 长镜头跨越空档 = 正确行为 |

**但真正的短板不在"切点时间准不准"，而在"切点锚定在什么事件上"**——
当前 v23 用 librosa onset 笼统检测(84个, 含大量 hihat/切分音)，
专业漫剪应锚定 **kick(低频重音)**。

## 二、深度研究：OpenMontage beatgrid 引擎揭示的专业方法论

对《独自升级.mp3》实测（19.4s / 99BPM / 32拍 / 65事件）:

### 2.1 鼓类型分类（band-split 频带分割）
```
kick  <150Hz   低频重音 → 漫剪"撞拍"的真正目标
snare 150-900Hz 军鼓    → 节奏骨架
hihat >5000Hz  镲片     → 高频弱击, 切在上面观感不"撞"
perc  其他      打击     → 过渡
实测: kick=11, snare=11, hihat=33, perc=10
```

### 2.2 网格位置语义（16分音符网格）
```
strong     正拍(10个)   → 主切点
weak       弱拍(36个)   → 次级切点
syncopated 切分音(19个) → 专业技巧(刻意用), 但默认不切
```

### 2.3 关键时刻（SURGE/DROP/hard_stop）
```
SURGE 能量突增(5s/1s/2s/8s/12s) → 视觉爆发点
DROP  能量突降(3s/6s/13s)       → 切点/停帧点
hard_stop 13s(突然停止)          → 定格/黑场
```

### 2.4 rolls/fills 连击段
```
8.80-9.64s   snare fill(5击)
10.73-12.65s hihat 持续连击(9击) → DROP
17.90-19.11s kick 加速滚奏(7击)  → 高潮
→ 连击段应切换"连续视觉"(缩放/抖动/残影), 而非离散快切
```

### 2.5 特殊事件
```
riser(1s/3.09s等) 铺垫上扬 → 运镜蓄力, 不切点
glitch/crash      噪声爆发 → 故障/闪白特效
```

## 三、跟音乐剪辑的专业升级方案（可落地）

### 3.1 切点锚定升级: onset → kick优先 + 网格语义
```
当前:  切点 = 所有 onset ∪ beat          (84+32 混用, 含 hihat/切分)
升级:  主切点 = kick + strong 拍          (撞拍感)
       次级切点 = weak 拍 (需要密度时)
       排除 = hihat/riser/glitch 事件      (不"撞")
       切分音 = 可配概率启用 (syncopation 技巧)
```

### 3.2 连击段视觉切换 (rolls)
```
detect_rolls 输出连击段 → 该段不再"逐击切点",
改用连续视觉: 缩放推进/残影/抖动 (zoompan + tblend)
```

### 3.3 关键时刻语义驱动 (moments)
```
SURGE → 变速加速或拉近 (蓄力后爆发)
DROP  → 硬切或停帧
hard_stop → 定格/黑场/闪白
```

### 3.4 空档与静音
```
SILENCES(0-1s/3-5s/6-7s) → 长镜头或留白, 不硬切
VOID 相位 → 素材呼吸感
```

## 四、接入路径（分两步，都可独立验收）

### Step 1: 把 beatgrid 的鼓类型/网格语义接入现有切点
- `_plan` 里 `_detect_onsets` 的 onset 替换为 beatgrid 输出的 `events`
  (kick/snare + strong/weak/syncopated)
- 切点候选 = kick ∪ strong_beat ∪ (density>1.5 时加 weak)
- 验收: 切点命中率 + 观感"撞拍"增强

### Step 2: 关键时刻 + 连击段接入编排
- moments(SURGE/DROP/hard_stop) → 变速/停帧/闪白
- rolls → 连续视觉(缩放/残影)
- 验收: 高潮段视觉冲击 + 连击段流畅感

## 六、结论

v23 卡点精度已达标(71.2% onset 对齐, 超 v22 的 60.9%)。
"没跟音乐"的深层原因是**锚定粒度**：onset 笼统检测把 hihat/切分音也当切点，
而专业漫剪锚定 **kick(低频重音)+ 强拍**，并用关键时刻/连击段驱动视觉。
OpenMontage beatgrid 引擎已提供全部信号(鼓类型/网格/关键时刻/连击段)，
按 Step 1→Step 2 接入即可实现真正的"音乐驱动剪辑"。
