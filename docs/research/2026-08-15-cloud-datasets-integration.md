# 云端公开数据集 × 项目衔接方案（2026-08-15）

> 背景：AutoDL 实例已挂载 25 个公开数据集（`/root/autodl-pub/`，零下载零配额）。
> 本文把每个数据集映射到抠像链路的可落地环节，按衔接价值分三档。

## 一、核心衔接（直接闭环当前短板）

### COCO2017 + VOCdevkit —— 客观精度评估（最高优先级）
- **环节**：BiRefNet 精修评估 / 检测器评估
- **落地**：`scripts/eval_birefnet_coco.py`（已提交）用 person 类 GT mask 算 IoU/边界F1——**补齐项目长期缺的 EDGE_IoU 客观指标**（此前因无人做人工标注一直 N/A）
- **扩展**：VOC 2012 segmentation（含 person）做第二套评估集交叉验证；检测器（YOLO/Owlv2）也可用 COCO person 类 bbox 算召回率——量化"锚定检测"组件质量

### Vimeo-90k —— 时序一致性标准评估
- **环节**：时域平滑（MED5/13）验证
- **落地**：Vimeo 提供高质量连续帧序列（含 GT），把我们的 J500/帧间 IoU 指标放到标准序列上验证——从"黑岩/FATE 单素材"升级为**基准化评估**（当前所有 J500 结论都基于单支素材，这是最大方法学短板）

## 二、数据衔接（混合微调扩充训练集）

### CelebA（20 万人像）
- **环节**：BiRefNet 微调补充数据
- **落地**：人脸+发丝是抠像边缘精度的高价值样本；与动漫数据混合微调（比例 3:1），提升发丝级边缘——直接对治用户反馈的"边缘小瑕疵"

### ADEChallenge2016 / cityscapes（真实场景分割）
- **环节**：域泛化评估 + 微调负样本
- **落地**：量化"动漫微调后真实场景精度下降多少"（域漂移代价）；若下降超 10%，加少量真实场景数据平衡

## 三、前瞻衔接（未来组件储备）

### GOT10k / LaSOT / MOT20 / mot17（视频目标跟踪）
- **环节**：未来 SAMURAI 类跟踪组件
- **落地**：这些是跟踪标准基准，SAMURAI（Windows 编译受阻的待办）一旦可用，直接用它们做快速运动段（转身段）的跟踪评估与微调

### DIV2K
- **环节**：Topaz 超分模块评估（项目其他链路）
- **落地**：8K 超分质量基准

## 四、不衔接（明确跳过，省扫描时间）

| 数据集 | 原因 |
|---|---|
| ImageNet/ImageNet100/cifar | 分类任务，Backbone 预训练用不到（模型自带） |
| KITTI/nuScenes/DOTA/TT100K/S3DIS/SemanticKITTI/D2SA | 自动驾驶/遥感/3D，与动漫抠像无关 |
| BERT-Pretrain-Model | NLP，仅项目非视觉模块可能用 |

## 五、落地路线图

| 阶段 | 动作 | 前置 |
|---|---|---|
| ① 立即（训练完成后） | COCO person 类 A/B 评估（微调前 vs 后） | 云训练回传 |
| ② 同日 | VOC 第二套评估 + 检测器召回率 | ① |
| ③ 次日 | Vimeo-90k 时序指标基准化（J500 标准序列验证） | ② |
| ④ 二期 | CelebA 混合微调 + 域漂移评估（ADE/cityscapes） | ③ |
| ⑤ 远期 | GOT10k/LaSOT 跟踪组件（SAMURAI 落地后） | 组件就绪 |

> 核心思路：**评估先行，数据其次，前瞻储备**——先把"能用数字说话"的闭环建起来，再谈扩充训练数据。
