# 漫剪内容层深度研究 — 从"卡点"到"讲故事"

> **创建**: 2026-08-13 | **背景**: v23 卡点已达标(85%命中/超v22)，但用户指出：
> 1) 卡点 72% 有上升空间 2) 素材偶有重复 3) **导演没编排故事，镜头表达杂乱无章**
> **结论**: 卡点是"节拍层"(已解决)，真正短板是"故事层"(节奏对但无叙事意图)。
> 业界所有开源工具(OpenMontage/ai-montage-agent 等)都只有节奏骨架，**故事层是空白=机会**。

---

## 一、卡点 72% 的真相（实测数据）

| 指标 | 实测 | 解读 |
|------|------|------|
| 总切点 | 48 | — |
| **命中** | **41 (85%)** | 实际命中率 85%，非 72% |
| 未命中 | 7 | 全是 **弱 onset 半拍切**（onset 偏 91-199ms） |
| 未命中特征 | 时间 0.62/3.04/14.33/15.0/15.29/15.42/17.83s | 都在音乐"空档"或弱 onset 处 |

**瓶颈**：7 个未命中的切点，要么是音乐空档（正确行为，长镜跨越），要么是弱 onset（hihat 半拍）被误切。**要上 90%+ 需要**：空档段明确标为"长镜不切"，弱 onset 排除。但这是"节拍层"的边际优化（85%→90%），观感提升有限。

## 二、素材重复（实测已解决）

v23 decision_log 39 镜全部唯一（重复=0）。之前 26 镜重复的根因(无内容感知选材)已修复。当前无此问题。

## 三、核心短板：导演没有"故事层"（杂乱无章的根因）

### 3.1 现状（实测代码）

| 层 | v23 现状 | 缺什么 |
|----|---------|--------|
| **节拍层** | ✅ music_dynamics 能量分层 + kick 锚定 + 变速 | 已解决 |
| **叙事层** | ❌ _plan 纯按节拍/能量分段，**无主题/无镜头意图** | **核心缺口** |
| **语义层** | ❌ 镜头不表达"内容观点" | 缺 |
| **素材语义** | ⚠️ 只按高光/时长选，**不看画面内容与主题匹配** | 缺 |

**证据**：`ai/multimodal_director.py` 有完整的 `direct_from_text`（LLM 生成分镜：title/mood/pace/structure/情绪递进），**但 v23 主引擎 `_plan` 从未调用它**。项目有故事规划能力，却没用。

### 3.2 "杂乱无章"的机制
- 镜头 A 是高燃打斗，镜头 B 是抒情空镜，镜头 C 又是打斗——**没有情绪弧线串联**
- 素材选段只看"高光/时长分散"，**不匹配该镜头的叙事角色**（铺垫/爆发/收尾）
- 转场/变速跟节拍走，**不跟剧情走**（该留白处没留白）

## 四、业界开源方案研究（结论：无现成故事层）

| 方案 | 节奏骨架 | 故事层 | 结论 |
|------|---------|--------|------|
| **OpenMontage music-to-video** | ✅ beatgrid 极专业 | ❌ 仅"素材贴片+字版"，无叙事 | 只解决节拍，不解决故事 |
| **ai-montage-agent** | ✅ beat_sync_engine | ❌ 高光+节拍 | 同上 |
| **hookcut (rhythm 复刻)** | ✅ 参考片节奏复刻 | ❌ 仅切点时间轴 | 复刻节奏非叙事 |
| **cacity/VideoHub 等** | ⚠️ 基础 | ❌ | 低质 |
| **Qwen2.5-VL 时序理解**（已调研） | — | ⚠️ 能理解"画面在表达什么" | **VLM 是故事层的钥匙** |

**结论**：开源项目普遍聚焦"节拍/节奏"，**"镜头表达叙事意图"是行业空白**——但可用 VLM（Qwen2.5-VL 已调研可跑）补上。这是差异化机会。

## 五、T3 运镜感知的实质价值（实测）

**已生效**：v23 运镜含 `push`/`zoom_back` 等 T3 特征运镜（旧版 _ZOOMPAN_MAP 无 push），说明 `SourceCameraInventory`（光流分类素材运镜）已在渲染中工作。

**实质价值**：
1. **素材运镜感知**：`analyze()` 识别素材本身是推/摇/复杂 → 决定给该素材配什么运镜（避免"素材在推，我又加推"的重叠）
2. **衔接平滑**：`suggest_camera_for_shot(mood, source_camera, prev_camera)` 避免连续同运镜
3. **降级安全**：T3 失败回退旧逻辑，不阻断

**局限**：T3 解决"运镜不重复"，**不解决"为什么这个镜头在这里"**——它仍是节拍层/视觉层的优化。

## 六、落地路线图：补"故事层"（三阶段）

### Stage 1：故事意图接入（本周可做，直接用已有 direct_from_text）
```
用户主题/描述 → multimodal_director.direct_from_text → 分镜计划
  (title/mood/pace/structure: 每段有 shot_type/camera/transition/情绪)
→ 把 structure 喂给 _plan: 每段获得"叙事角色"(铺垫/爆发/收尾)
→ 素材匹配按"叙事角色 + 内容语义"选，而非纯高光
```

### Stage 2：素材-叙事语义匹配（用已有 MaterialIntelligenceEngine）
```
每段有叙事角色(铺垫=需要情绪铺垫画面/爆发=高能画面)
→ 素材帧的 mood/scene_type(已有 t12 分类器) 匹配段落角色
→ 解决"打斗配抒情空镜"的错配
```

### Stage 3：VLM 镜头语义复核（Qwen2.5-VL，已调研可跑）
```
渲染后 → VLM 看关键帧 → 校验"画面是否表达该段叙事意图"
→ 生成"镜头表达描述"写入 decision_log（可追溯的叙事依据）
```

## 八、结论

1. **卡点**：实际 85%，边际优化空间有限（→90% 需处理空档/弱onset，观感提升小）
2. **素材重复**：已解决
3. **核心机会**：**故事层**——v23 有完美的"节奏骨架"但无"叙事血肉"。项目已有 `direct_from_text`（LLM 分镜）+ 素材语义匹配能力，**接入即可让镜头"表达意图"而非"贴节拍"**。这是从"卡点机器"到"会讲故事"的质变，也是区别于所有开源方案的机会。
4. **T3**：已在节拍层/视觉层有效（素材运镜感知+衔接平滑），但解决不了叙事层。
