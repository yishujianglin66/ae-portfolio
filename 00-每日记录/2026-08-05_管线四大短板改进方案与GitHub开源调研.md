## 一、GitHub 开源项目调研

### 1.1 问题一（导演剧本自动化）— 推荐项目

#### ① OpenMontage（⭐ 12,650+，2026 年 GitHub 增速最快项目之一）

- **仓库**：`github.com/calesthio/OpenMontage`
- **核心思路**：将 AI 编程助手（Claude Code / Cursor / Copilot）变成完整视频工作室。用自然语言描述需求，Agent 自动完成"调研→脚本→分镜→素材生成→剪辑→渲染"全流程。
- **架构亮点**：
  - 12 条生产管线（科普动画/纪录片/品牌概念片/产品广告等），每条管线由 YAML 生产清单定义
  - 52 个工具 + 500+ Skill 模组，可组合扩展
  - 读取人类可读的 YAML + Markdown 技能文件，流程完全透明可改
  - 集成 FFmpeg / Remotion / Stable Diffusion / Piper TTS
- **可借鉴点**：
  - **YAML 生产清单模式**：将当前 `smart_director.py` 的硬编码预设改为可配置的 YAML 剧本模板
  - **Skill 模组机制**：每个剪辑技法（匹配剪辑、J-cut、蒙太奇）封装为独立 Skill，按需调用
  - **Agent 编排架构**：当前 `ai_director.py` 的 5-Phase 架构可参考其 Agent 驱动模式升级

#### ② OpenStoryline（AI 故事视频生成器）

- **仓库**：`github.com/journey-apps/OpenStoryline`
- **核心思路**：通过自然语言输入，由 LLM 规划编排，将手动剪辑转化为"意图导演"。自动搜索下载素材，基于主题视觉与情感识别构建故事线。
- **可借鉴点**：
  - **情感识别驱动的叙事构建**：自动识别素材的情绪属性，构建上下文叙述
  - **风格技能系统**：内置风格模板可复用，类似我们的 `TEXT_ANIM_PRESETS` 但更智能
  - **AI 过渡功能**：自动选择匹配前后段落情绪的转场方式

#### ③ Remotion（⭐ 21K+，React 程序化视频引擎）

- **仓库**：`github.com/remotion-dev/remotion`
- **核心思路**：用 React 组件定义视频，每一帧都是函数式的渲染结果。支持模板化生产。
- **可借鉴点**：
  - **模板引擎思想**：将 14 种 `TEXT_ANIM_PRESETS` 升级为参数化模板，支持组合嵌套
  - **数据驱动渲染**：剧本 JSON → 视频，与我们的 `ScriptToJSXTranslator` 架构天然兼容

### 1.2 问题二（字体特效多样化）— 推荐项目

#### ① Generative Manim（⭐ 5K+）

- **仓库**：`github.com/360macky/generative-manim`
- **核心思路**：GPT → Manim 代码，文字描述直接生成动画视频。
- **可借鉴点**：其"文字→动画代码→渲染"链路与我们的"预设→JSX→AE"链路同构，可参考其**动画组合器**设计，让多个动画效果可叠加。

#### ② MG-Gen（Single Image to Motion Graphics）

- **论文**：arxiv 2504.02361
- **核心思路**：单图生成动态图形，包含文字运动和物体运动的联合生成。
- **可借鉴点**：文字动画不只是"入场→展示→出场"，而是**持续运动**（呼吸感、律动感），可引入到我们的 `hold` 阶段。

### 1.3 问题三（自适应调色）— 推荐项目

#### ① AdaIN-style（实时风格迁移）

- **仓库**：`github.com/xunhuang1991/AdaIN-style`
- **核心思路**：自适应实例归一化，将风格图像的统计特征（均值/方差）注入内容图像，实现实时风格迁移。
- **可借鉴点**：逐镜头提取色彩统计特征，用 AdaIN 思想将目标调色风格的均值/方差适配到每个镜头，而非全局统一 LUT。

#### ② SANET（风格感知内容损失）

- **仓库**：`github.com/GlebBrykin/SANET`
- **核心思路**：ECCV18 论文实现，在风格迁移中感知内容特征，避免色彩冲突。
- **可借鉴点**：调色时考虑原片色彩分布，避免"暗场景+高饱和滤镜=灰蒙蒙"的冲突。

#### ③ NVIDIA FastPhotoStyle

- **仓库**：`github.com/NVIDIA/FastPhotoStyle`
- **核心思路**：照片级风格迁移，解决空间不一致和伪像问题。
- **可借鉴点**：风格迁移后的色彩一致性校验机制，可用于我们的逐镜头调色后质检。

### 1.4 问题四（长期学习机制）— 推荐项目

#### ① Vex（终端 AI 视频编辑 Agent）

- **仓库**：`github.com/samuelclinton/Vex`
- **核心思路**：AI 选择操作 → 确定性工具执行 → 项目状态记忆。每次操作的结果被记录，后续决策参考历史。
- **可借鉴点**：**"AI 选择 + 确定性执行 + 状态记忆"三层架构**，与我们的"导演决策 + JSX 执行 + 评测反馈"高度同构。

#### ② ShortGPT（AI 自动化视频创作）

- **仓库**：`github.com/RayVentura/ShortGPT`
- **核心思路**：模块化视频创作管线，集成素材搜集、语音合成、字幕、编辑。
- **可借鉴点**：编辑变量长效保存机制（类似我们的 `ORCHESTRATION_PATTERNS` 但更持久化）。

## 二、四个问题的具体改进方案

### 2.1 问题一：导演系统剧本自动化能力升级

**现状诊断**：

| 模块 | 当前能力 | 短板 |
|------|---------|------|
| `smart_director.py` | 14 种文字预设，按 `pool[ci % len(pool)]` 循环分配 | 无叙事逻辑，无情绪递进 |
| `ai_director.py` | LLM 生成剧本 JSON → JSX 翻译 | 剧本有结构但不落地到混合管线 |
| `multimodal_director.py` | 5 种输入模式，`SHOT_TEMPLATES` 有 5 种镜头模板 | 模板未与 `smart_director` 的预设打通 |

**改造方案：三层剧本架构**

```
Layer 3: 叙事层（ai_director.py 的 LLM 剧本）
    ↓ 输出: 段落结构 + 情绪弧线 + 技法标注
Layer 2: 编排层（smart_director.py 的预设决策）
    ↓ 输出: 每个切点的预设 + 字体 + 特效 + 位置
Layer 1: 执行层（resolve_ae_resolve_pipeline.py 的 JSX 生成）
    ↓ 输出: 可执行的 JSX 代码
```

**关键改造：在 `smart_director.py` 中引入高级剪辑技法**


**现状诊断**：

当前 `smart_director.py` 中所有 14 个预设的 `prop_fn` 都硬编码 `font='MicrosoftYaHei'`，仅通过 `fillColor` 和 `fontSize` 做微小差异。14 种预设的特效组合（Glow/Directional Blur/RGB 分离等）虽然已开发，但在 `build_smart_text_jsx()` 中按 `pool[ci % len(pool)]` 分配，导致分布不均。

```python
# ---- 修改后的预设构建逻辑（伪代码） ----
def build_preset_with_font(preset_key: str, shot_idx: int, 
                           intensity: str, emotion: str = "") -> Dict:
    """根据预设名 + 镜头情绪，从策略引擎获取最优字体+特效配置"""
    
    # 1. 查矩阵获取推荐字体
    matrix_entry = EFFECT_FONT_MATRIX.get(preset_key, {})
    font_key = matrix_entry.get("font", "body_regular")
    
    # 2. 情绪微调：高唤醒度 → 升级字体粗细
    if emotion in ("rage", "triumph", "tension"):
        font_key = "title_bold"  # 强制粗体
    elif emotion in ("grief", "melancholy", "serenity"):
        font_key = "subtitle_light"  # 强制细体
    
    font_config = FONT_REGISTRY[font_key]
    
    # 3. 字号根据强度调整
    size_min, size_max = font_config["size_range"]
    if intensity == "intense":
        font_size = size_max
    elif intensity == "gentle":
        font_size = size_min
    else:
        font_size = (size_min + size_max) // 2
    
    return {
        "font": font_config["font"],
        "faux_bold": font_config["faux_bold"],
        "fontSize": font_size,
        "effects": matrix_entry.get("effects", []),
    }
```

### 2.3 问题三：逐镜头自适应调色算法

**现状诊断**：

当前 `resolve_ae_resolve_pipeline.py` 的 Stage C（`_grade_and_mix` 方法）对全片应用统一的 FFmpeg 滤镜链：
```python
vf_parts.append("hue=s=1.15")
vf_parts.append("eq=saturation=1.15:contrast=1.02:brightness=0.005")
vf_parts.append("colorbalance=rs=-0.02:gs=0.01:bs=0.03:...")
```
虽然第四轮已实现"逐镜头差异化调色"（在 Stage A 前完成，6 种风格循环），但仍是固定循环而非自适应。

**改造方案：基于原片色彩分析的自适应调色**

```python
class AdaptiveColorGrader:
    """逐镜头自适应调色引擎
    
    核心原则：
    1. 分析每个镜头的原始色彩分布（色温/饱和度/亮度/主色调）
    2. 根据原片特征智能选择或调整滤镜参数
    3. 避免色彩冲突（暗场景不用高饱和、冷色原片不叠暖色滤镜）
    """
    
    # 调色风格定义（每种风格有安全边界）
    COLOR_STYLES = {
        "warm_dramatic": {
            "target_temp": "warm",      # 目标色温
            "sat_boost": 1.25,          # 饱和度增益
            "contrast_boost": 1.08,
            "safe_brightness": (40, 200),  # 原片亮度在此范围内才适用
            "safe_saturation": (20, 80),   # 原片饱和度在此范围内才适用
            "conflict_rules": [
                ("原片已高饱和(>70)", "sat_boost 降到 1.1"),
                ("原片极暗(<25)", "contrast_boost 降到 1.02，避免灰雾"),
            ],
        },
        "teal_orange": {
            "target_temp": "neutral_warm",
            "sat_boost": 1.2,
            "contrast_boost": 1.1,
            "safe_brightness": (30, 180),
            "safe_saturation": (15, 75),
            "conflict_rules": [
                ("原片偏冷蓝(U>>V)", "色温偏移量减半，避免色彩断层"),
                ("原片已暖(V>>U)", "减少暖色注入，防止过暖"),
            ],
        },
        "cyber_cool": {
            "target_temp": "cool",
            "sat_boost": 1.15,
            "contrast_boost": 1.12,
            "safe_brightness": (20, 160),
            "safe_saturation": (10, 70),
            "conflict_rules": [
                ("原片已高饱和(>70)", "sat_boost 降到 1.05"),
                ("原片极亮(>200)", "contrast_boost 降到 1.03，避免过曝"),
            ],
        },
        "golden_epic": {
            "target_temp": "warm_gold",
            "sat_boost": 1.3,
            "contrast_boost": 1.05,
            "safe_brightness": (35, 180),
            "safe_saturation": (20, 65),
            "conflict_rules": [
                ("原片偏绿(G>>R,B)", "色相偏移修正，避免黄绿混合"),
            ],
        },
        "desaturated_cinematic": {
            "target_temp": "neutral",
            "sat_boost": 0.85,  # 降饱和！
            "contrast_boost": 1.15,
            "safe_brightness": (30, 200),
            "safe_saturation": (30, 90),
            "conflict_rules": [
                ("原片已低饱和(<25)", "不再降饱和，只调对比度"),
            ],
        },
    }
    
    def analyze_shot_color(self, shot_path: str) -> Dict[str, float]:
        """用 ffmpeg signalstats 分析镜头色彩特征"""
        # 提取: YAVG(亮度), UAVG/VAVG(色度), SATAVG(饱和度)
        # 返回: {brightness, saturation, u_avg, v_avg, is_warm, is_dark, is_high_sat}
        ...
    
    def select_best_style(self, shot_color: Dict, 
                          available_styles: List[str]) -> str:
        """根据镜头色彩特征，从可用风格中选择最匹配的"""
        best_style = None
        best_score = -1
        
        for style_name in available_styles:
            style = self.COLOR_STYLES[style_name]
            score = 100
            
            # 检查亮度是否在安全范围
            b = shot_color["brightness"]
            b_min, b_max = style["safe_brightness"]
            if b < b_min:
                score -= (b_min - b) * 2  # 过暗惩罚
            if b > b_max:
                score -= (b - b_max) * 2  # 过亮惩罚
            
            # 检查饱和度是否在安全范围
            s = shot_color["saturation"]
            s_min, s_max = style["safe_saturation"]
            if s < s_min:
                score -= (s_min - s) * 1.5
            if s > s_max:
                score -= (s - s_max) * 1.5
            
            # 色温匹配
            target = style["target_temp"]
            is_warm = shot_color["is_warm"]
            if target in ("warm", "warm_gold") and not is_warm:
                score -= 10  # 暖色风格 + 冷色原片 = 需要大幅偏移
            if target == "cool" and is_warm:
                score -= 10
            
            if score > best_score:
                best_score = score
                best_style = style_name
        
        return best_style or available_styles[0]
    
    def compute_adaptive_params(self, shot_color: Dict, 
                                 style_name: str) -> Dict[str, float]:
        """根据镜头色彩 + 选定风格，计算自适应滤镜参数"""
        style = self.COLOR_STYLES[style_name]
        params = {
            "sat_multiplier": style["sat_boost"],
            "contrast_multiplier": style["contrast_boost"],
            "brightness_offset": 0.0,
        }
        
        # 冲突修正
        s = shot_color["saturation"]
        b = shot_color["brightness"]
        
        # 规则: 原片已高饱和 → 降低增益
        if s > 70:
            params["sat_multiplier"] = min(params["sat_multiplier"], 1.1)
        
        # 规则: 原片极暗 → 降低对比度增益，微提亮度
        if b < 25:
            params["contrast_multiplier"] = min(params["contrast_multiplier"], 1.03)
            params["brightness_offset"] = 0.02
        
        # 规则: 原片极亮 → 降对比度，微压亮度
        if b > 200:
            params["contrast_multiplier"] = min(params["contrast_multiplier"], 1.05)
            params["brightness_offset"] = -0.01
        
        return params
```

**集成方式**：在 `resolve_ae_resolve_pipeline.py` 的 Stage A 剪辑循环中，对每个镜头段调用 `AdaptiveColorGrader`，替代当前的固定 6 风格循环。

## 四、逐镜头自适应调色算法设计

### 4.1 算法流程

```
对每个镜头段:
  1. ffmpeg signalstats 提取色彩特征
     → {brightness, saturation, u_avg, v_avg, is_warm, is_dark, is_high_sat}
  
  2. 风格选择（从可用风格池中）
     → 按"安全范围匹配度"打分，选最高分风格
  
  3. 参数自适应计算
     → 基础参数 + 冲突修正 → 最终 FFmpeg 滤镜参数
  
  4. 生成逐镜头滤镜命令
     → 每个镜头段独立的 eq/hue/colorbalance 参数
  
  5. 镜头间过渡平滑
     → 相邻镜头的滤镜参数差异过大时，插入过渡帧
```

### 4.2 色彩冲突避免规则

| 原片特征 | 禁止操作 | 替代方案 |
|---------|---------|---------|
| 极暗 (YAVG<25) | 高饱和滤镜(>1.3x) | 降饱和+提对比度(电影感) |
| 极亮 (YAVG>200) | 暖色叠加(会过曝) | 冷色微调+压高光 |
| 高饱和 (SAT>70) | 再加饱和(会断层) | 保持或微降，调对比度 |
| 冷色调 (U>>V) | 强暖色滤镜(色彩冲突) | 同色系微调或中性调色 |
| 暖色调 (V>>U) | 强冷色滤镜(色彩冲突) | 同色系微调或中性调色 |
| 单色调 (UV差<5) | 高饱和(会突兀) | 轻调色+加暗角 |

### 5.3 反馈闭环

```python
class CapabilityFeedbackLoop:
    """每次管线运行后，将效果反馈写入注册表"""
    
    def record_run(self, run_id: str, decisions: Dict, score: float):
        """
        Args:
            run_id: 运行 ID
            decisions: 本次运行的决策记录
                {
                    "fonts_used": {"title_bold": 3, "mono_tech": 2, ...},
                    "effects_used": {"glow": 4, "directional_blur": 1, ...},
                    "color_styles_used": {"teal_orange": 3, ...},
                    "techniques_used": {"match_cut": 1, ...},
                }
            score: 本次运行的综合评分
        """
        registry = self._load_registry()
        
        for category in ["fonts", "effects", "color_styles", "edit_techniques"]:
            used = decisions.get(f"{category}_used", {})
            for cap_name, count in used.items():
                if cap_name in registry[category]:
                    entry = registry[category][cap_name]
                    old_count = entry["usage_count"]
                    old_avg = entry["avg_score"]
                    # 指数移动平均更新
                    new_avg = (old_avg * old_count + score) / (old_count + 1)
                    entry["usage_count"] = old_count + count
                    entry["avg_score"] = round(new_avg, 2)
                    entry["last_used"] = run_id
        
        self._save_registry(registry)
    
    def get_best_capabilities(self, category: str, top_k: int = 3) -> List[str]:
        """获取历史评分最高的能力项"""
        registry = self._load_registry()
        items = registry.get(category, {})
        sorted_items = sorted(items.items(), key=lambda x: x[1]["avg_score"], reverse=True)
        return [name for name, _ in sorted_items[:top_k]]
    
    def should_try_new_combination(self, category: str, 
                                    cap_name: str, 
                                    threshold: int = 5) -> bool:
        """是否应该尝试新组合（使用次数不足的能力优先尝试）"""
        registry = self._load_registry()
        entry = registry.get(category, {}).get(cap_name)
        if entry is None:
            return True  # 未知能力，应该尝试
        return entry["usage_count"] < threshold
```
