# 2026-08-26 · AEP 逆向工程补强

> 会话主题：逆向工程工具链修复与补强
> 涉及模块：`aep_analyzer/`、`reverse_engineer_pipeline.py`、`aep_binary_parser.py`

---

## 1. 任务背景

用户要求对 AEP 逆向工程工具链进行修复补强，目标是让流水线真正可用：
- AEP 二进制扫描 → 知识提取 → 风格匹配 → JSX 预设生成 → 报告输出

## 2. 现状盘点

### 已有资产
- `aep_binary_parser.py`（35KB）：离线二进制解析器，可提取合成/图层/matchName/素材路径
- `aep_analyzer/knowledge_extractor.py`：知识提取器（效果链/关键帧/图层组织/技法标签/调色模式）
- `aep_analyzer/template_learner.py`：模板学习器（跨工程知识合成）
- `aep_analyzer/report.py`：报告生成器
- `10-风格化剪辑知识库/`：12 个逆向知识文档（含 5 种风格组合模式）

### 发现的缺口
1. **无预设生成模块**：知识提取后无法自动生成可执行的 JSX 预设
2. **关键帧曲线提取不足**：贝塞尔控制点、空间切线、属性时间线未提取
3. **无统一流水线**：各模块独立，无一键式 CLI
4. **matchName 噪声**：二进制 parser 把子参数（`ADBE Ramp-0000`）、属性组（`ADBE Group End`）、3D 材质属性（`ADBE Ambient Coefficient`）全当效果

## 3. 实施内容

### 3.1 新增 `aep_analyzer/preset_generator.py`
- 11 个效果参数知识库（Fractal Noise / Glow / Exposure / Tint / Turbulent Displace / Cracked Tiles / Noise / Box Blur / B&W / Photo Filter / Lumetri）
- 5 种风格配方（赛博朋克 / 动漫混剪 / 复古胶片 / 清新文艺 / 音频响应）
- JSX 模板生成器（IIFE 包装，含图层查找 + 效果添加 + 参数设置 + 混合模式）
- 预设 JSON 输出（兼容 `text_animation_presets.json` 格式）
- 风格自动检测（从效果链匹配最接近的风格配方）

### 3.2 增强 `aep_analyzer/knowledge_extractor.py`
- 关键帧贝塞尔控制点详细提取（`bezierIn`/`bezierOut`/`spatialIn`/`spatialOut`）
- 属性时间线构建（每个动画属性按时间排列关键帧序列）
- 曲线类型分类（ease_in_sharp / ease_in_smooth / ease_in_gentle）
- None name 防御（图层名称可能为 None 的情况）

### 3.3 新增 `reverse_engineer_pipeline.py`
- 统一 CLI 流水线：`--aep`（单文件）/ `--aep-dir`（批量）/ `--generate-presets`（仅生成预设）
- 5 步流水线：二进制扫描 → 知识提取 → 风格匹配 → 预设生成 → 输出保存
- **19 条 matchName 噪声过滤规则**：
  - 子参数模式：`.*-\d{4}$`、`.*_\d+$`
  - 属性组：`ADBE Group`、`ADBE Transform Group`、`ADBE Blend Options Group` 等
  - 变换属性：`ADBE Position`、`ADBE Orientation`、`ADBE Scale` 等
  - 相机属性：`ADBE Camera .*`
  - 3D 材质属性：`ADBE Shadow Color`、`ADBE Ambient Coefficient` 等
  - 环境属性：`ADBE Envir .*`
- 二进制 parser 字段名映射修复（`composition_index` vs `comp_index`、`layer_index` vs `layer_id`）
- Markdown 报告生成器

### 3.4 Bug 修复
- `pat.match()` → `pat.search()`：正则匹配从「仅开头」改为「全文搜索」
- 图层 name 为 None 的防御处理
- 字段名不一致修复（binary parser 输出格式与 pipeline 适配层对齐）

## 8. 解析器性能优化 + 批量扫描 9 套 AE 新手工程

### 性能问题
原始 `aep_binary_parser.py` 对大文件极慢：
- 2.1MB 文件：78.5s
- 18.7MB 文件：超时 300s+未完成

### 瓶颈分析（cProfile）
- `_extract_paths_from_text` 占 74.9/76.2s（98%）——PATH_RE 复杂正则在二进制解码的垃圾文本上运行 16,439 次
- `_is_mostly_printable` 占 1.0s——逐字符 Python 循环

### 优化措施
1. **盘符预过滤**：`_extract_paths_from_text` 增加 `_PATH_DRIVE_RE` 正则预检，无盘符路径(`X:\`)或 UNC(`\\`)直接跳过
2. **大文件跳过 supplement scan**：`_global_supplement_scan` 对 >5MB 文件跳过（主循环已覆盖关键数据）

### 优化结果
| 指标 | 优化前 | 优化后 |
|------|---------|--------|
| 2.1MB 文件 | 78.5s | 0.9s |
| 18.7MB 文件 | 超时(300s+) | 5.9s |
| 9 套批量 | 超时未完成 | 38.9s |
