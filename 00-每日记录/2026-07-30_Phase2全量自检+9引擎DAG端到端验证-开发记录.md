## 五、缺陷修复

### 5.1 系统性 3 元组解包 bug（27 处）

**根因**: `base.py` 的 `_run_subprocess()` 返回 4 元组 `(returncode, stdout, stderr, error_code)`，但 11 个文件中 27 处调用使用了 3 元组解包 `code, stdout, stderr = ...`，导致"一调即崩"的 `ValueError: too many values to unpack`。

**影响范围**:

| 文件 | 修复处数 | 解包模式 |
|------|---------|---------|
| blender/engine.py | 7 | `code, stdout, stderr = ` → `code, stdout, stderr, _ = ` |
| silhouette/engine.py | 6 | 同上 |
| topaz/engine.py | 1 | 同上 |
| openmontage/engine.py | 2 | `rc, stdout, stderr = ` → `rc, stdout, stderr, _ = ` |
| moviepy/engine.py | 1 | 同上 |
| sam2/engine.py | 1 | 同上 |
| rife/engine.py | 1 | 同上 |
| layer_render_service.py | 3 | `code, stdout, stderr = ` → `code, stdout, stderr, _ = ` |
| beat_video_service.py | 4 | 同上 |
| textfx_short_video.py | 1 | 同上 |
| **合计** | **27** | |

**附带修复**: `fake_hfr_service.py` docstring 从 `(code, stdout, stderr)` 更正为 `(code, stdout, stderr, error_code)`。

**验证**: 修复后全部 27 处调用点正确使用 4 元组解包，Grep 搜索确认无残留。

### 5.2 AME subprocess 管道阻塞 bug

**根因**: `media_encoder/engine.py` 的 `_ensure_me_running()` 使用 `subprocess.run(capture_output=True)` 启动 GUI 程序（`cmd /c start "" exe`），GUI 程序继承 stdout/stderr 管道导致 `subprocess.run` 无法退出（等待管道关闭），进程永久阻塞。

**修复**: 改用 `subprocess.Popen` + `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 标志 + `DEVNULL` 重定向，实现真正的非阻塞 GUI 启动：

```python
import subprocess as _sp
_sp.Popen(
    [str(self.executable_path)],
    stdout=_sp.DEVNULL,
    stderr=_sp.DEVNULL,
    stdin=_sp.DEVNULL,
    creationflags=_sp.DETACHED_PROCESS | _sp.CREATE_NEW_PROCESS_GROUP,
)
```

### 5.3 AME _ensure_me_running 3元组解包 bug

**根因**: 同 5.1，`code, stdout, _ = ...` 应为 `code, stdout, _, _ = ...`。

**修复**: 更新为 4 元组解包。
