## 4. 关键技术决策与踩坑记录（时间线）

### T1: 渲染卡死 → 对话框自动关闭
- **症状**：所有渲染超时（即使最小640x360也卡死）
- **根因**：AE在渲染期间弹出#32770对话框（H.264编码器确认），阻塞ExtendScript线程
- **修复**：send()的wait循环中每3秒调用`find_and_close_dialogs()`
- **关键代码**：`_render_safe.py` 中 EnumWindows→GetClassNameW=="#32770"→keybd_event(13)

### T2: 爆炸过曝 → 全ADD层同步降低
- **症状**：36帧纯白（t=0.73-1.97s）
- **根因**：多层ADD叠加（flash+glow+sparks+debris+core+shockwave）峰值时叠加到纯白
- **迭代**：v1降flash/glow→仍34帧白; v2降shockwave/maxOpacity→仍32帧; v3降sparks/debris peak 70%→**10帧微白**
- **最终参数**：flash=12, glow=12, sparks_peak=120, debris_peak=100, core=50, shockwave=35, embers_maxOpacity=60

### T3: 3D灯光遮挡 → 2D ADD辉光
- **症状**：addLight后全场景被黑色遮挡
- **根因**：addLight的黑底Solid载体渲染为不透明
- **修复**：KeyGlow([1,0.8,0.5], blur=80) + RimGlow([0.4,0.6,1.0], blur=60)，ADD混合

### T4: spatial_std优化方向确认
- **反直觉发现**：暗BG+缩尘层→spatial从16降到12（更均匀=更差）
- **核心规律**：spatial需要帧内对比度（亮粒子+暗背景），均匀亮度源降低spatial
- **决策**：停止"降BG/缩Glow"方向，保持粒子集中+适度BG

### T5: 摄像机升级
- **爆炸**：衰减振幅震动（t=0.46-2.5s, ±15px→±3px）+ Z轴推镜(-1050→-960)
- **喷泉**：6点弧线轨道 + Z轴roll(-1.5°→1°→-0.5°) + DoF焦点呼吸

### T6: 喷泉active%提升失败→回退
- **尝试**：dust 25→35, velocity 0.12→0.30, main birthrate 0→8
- **结果**：YAVG过亮(205.9), spatial降(38.0), active降(71%)
- **原因**：更多粒子=更均匀亮度=降低对比度
- **决策**：回退到原始参数（spatial=42.9, active=80%→摄像机升级后81%）

## 6. AE Bridge操作SOP

```
完整流程（全自动）：
┌─────────────────────────────────────────────────────┐
│ 1. 检测Bridge: python scripts/_ping.py              │
│    → 返回 "BRIDGE_OK" 则继续                        │
│    → 超时则执行恢复流程 ↓                           │
├─────────────────────────────────────────────────────┤
│ 2. 恢复AE:                                         │
│    Stop-Process -Name "AfterFX" -Force             │
│    Start-Process "AE路径"                           │
│    等待 #32770 对话框 → keybd_event(13) 关闭       │
│    等待 _bridge_started.marker (最长90s)            │
│    再次 ping 确认                                   │
├─────────────────────────────────────────────────────┤
│ 3. 创建Comp: send(JSX代码, wait=60)                │
│    → 通过 ae_command.json 写入                     │
│    → 轮询 ae_result.json 等待结果                   │
│    → wait循环中每3秒 find_and_close_dialogs()       │
├─────────────────────────────────────────────────────┤
│ 4. 渲染: send(render_JSX, wait=300)                │
│    → 模板: "H.264 - 匹配渲染设置 - 15 Mbps"        │
│    → 输出: temp/XDIR.mp4 或 temp/FOUNTAIN.mp4      │
│    → wait循环中持续关闭对话框（关键！）             │
├─────────────────────────────────────────────────────┤
│ 5. 验证: python scripts/_verify_enhanced.py <file>  │
│    → 6指标全部PASS                                  │
├─────────────────────────────────────────────────────┤
│ 6. 复制: shutil.copy2 → output_production/dir5_...  │
└─────────────────────────────────────────────────────┘
```

### Bridge通信协议
- **命令文件**: `.ae-mcp-bridge/ae_command.json`
- **结果文件**: `.ae-mcp-bridge/ae_result.json`
- **格式**: `{"command": {"type": "runScript", "data": {"code": "...JSX..."}}}`
- **结果**: `{"result": {"data": {"result": "..."}}}`
