### 防御编码（最后一项）

**问题**：`core/llm_gateway.py` 的 `_h3_request` 方法内部 `import aiohttp` 在全量运行时失败（`ModuleNotFoundError`）。

**调查过程**：
1. 在 `conftest.py` 加了 `pytest_runtest_teardown` 哨兵，逐测试检查 `builtins.__import__` 是否被篡改

> ⚠️ **本结论已于同日二次会话被否证**：`aiohttp` 导入从未被阻断，该防御已撤除；同时本节调查项 3「撤掉防御后确认 h3 确实失败」不可复现。全文见文末「八、复验修正（2026-08-27 二次会话）」。

**修复**：
```python
# core/llm_gateway.py _h3_request 方法内
try:
    import aiohttp as _aiohttp
    client_timeout = _aiohttp.ClientTimeout(total=timeout or self._config.timeout_seconds)
except Exception:
    client_timeout = None  # 退化，mock session 不使用该参数
```

## 三、新增的永久设施

### 1. `__import__` 泄漏哨兵（`tests/conftest.py`）

```python
import builtins as _bltn
_orig_import = _bltn.__import__  # conftest 加载时快照

def pytest_runtest_teardown(item, nextitem):
    """每个测试用例结束后检查 builtins.__import__ 是否被篡改。"""
    current = _bltn.__import__
    if current is not _orig_import:
        import warnings
        warnings.warn(
            f"[IMPORT-LEAK] {item.nodeid} 结束后 builtins.__import__ 被篡改！"
            f" 原始={_orig_import!r}, 当前={current!r}",
            stacklevel=1,
        )
        _bltn.__import__ = _orig_import
```

**作用**：未来任何测试如果泄漏 `__import__`，会立即在输出中看到 `[IMPORT-LEAK]` 警告并自动恢复。

### 2. sys.modules 快照-恢复模式（范式）

```python
# 注入前保存
_prior_modules = {k: sys.modules[k] for k in INJECTION_KEYS if k in sys.modules}
_prior_attrs = {}
for parent, attr in PARENT_ATTR_PAIRS:
    pm = sys.modules.get(parent)
    if pm and hasattr(pm, attr):
        _prior_attrs[(parent, attr)] = getattr(pm, attr)

# ... 注入 mock 并执行目标代码 ...

# finally 恢复
try:
    ...
finally:
    for k in INJECTION_KEYS:
        sys.modules.pop(k, None)
    sys.modules.update(_prior_modules)
    for (parent, attr), val in _prior_attrs.items():
        pm = sys.modules.get(parent)
        if pm:
            setattr(pm, attr, val)
```

## 五、关键经验

### 1. sys.modules 跨测试污染是最高频陷阱

- 测试文件在模块级注入 mock 包 → 全量运行时污染后续文件
- **必须**用快照-恢复模式密闭化
- 单独运行各文件都正常 = 典型串扰特征

### 2. 合成包陷阱

- `type(sys)("pkg.sub")` 创建的空壳包无 `__init__.py` 执行
- 后续 `from pkg.sub import RealClass` 命中缓存 → ImportError
- 解决：加载后删除合成子包，保留必要父包

### 3. 延迟导入在测试环境的脆弱性

- 函数内 `import xxx` 在测试环境可能因 sys.modules 清理而失败
- 非关键延迟 import 应做 try/except 防御
- 这是良好编码实践，不是 workaround

### 4. collect_ignore 路径解析

- 条目相对 conftest.py 所在目录解析
- 在 `tests/conftest.py` 中写 `"tests/xxx.py"` 前缀 → 整个列表静默失效
- 正确：直接用文件名 `"xxx.py"`

### 5. 不要凭直觉定位根因

- 最初假设 `builtins.__import__` 泄漏 → 哨兵实测排除
- 真正原因是 sys.modules 层面的间接阻断
- **先加诊断工具，再用数据说话**
