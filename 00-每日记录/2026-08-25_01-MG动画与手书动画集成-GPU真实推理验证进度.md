## 4. 关键经验总结

1. **显存测量口径陷阱**：MuseTalk 初版用 `datagen` 批量预编码 100 帧 latent 全部驻留显存，峰值报到 11815 MiB（超物理 8GB，明显异常口径）。改为**逐帧流式生成 + 即时释放**（与官方 `inference.py` 一致）后真实峰值 5655 MiB。教训：批量预编码必须验证显存口径，官方推理循环逐帧流式是有原因的。
2. **网络线路矩阵更新**：`openaipublic.azureedge.net`（OpenAI whisper 官方源）**可达**，是 HF/ModelScope 之外第三条权重线路（已下载 whisper tiny.pt）。
3. **MuseTalk 音频特征固定 384 维**：只能用 whisper tiny 系列（384 维），base(512 维) 会在 `reshape(-1, 384)` 处崩溃。
4. **numpy 2.x 兼容三连**（AnimatedDrawings）：`np.bool8` 已移除 → `np.bool_` shim；`math.*` 不接受单元素数组 → `.item()` 标量化；`np.argwhere` 返回 (n,1) 形状 → `int(arr[0].item())`。
5. **SCAIL-2 无 flash_attn 跑法**：monkey-patch `wan.modules.clip.flash_attention` 为 `attention()` 的 sdpa 分支（注意还原输出 dtype）。
6. **GBK 控制台陷阱**：print 里的 ✅/→ 等符号在 PowerShell 重定向到文件时会触发 `UnicodeEncodeError`，验证脚本避免使用。

### 远程环境踩坑记录

1. **mmcv 编译失败**：系统 CUDA 11.8 vs torch cu124，nvcc 不在 PATH → 最终用 `mmcv-lite`（无 CUDA 算子但可导入）
2. **torch 2.6 weights_only 默认 True**：需全局 patch mmengine + MuseTalk 所有 torch.load 调用
3. **UNet 权重截断**：首次下载仅 1.3GB（应 3.2GB），需重新下载
4. **Google Drive 不可达**：face-parse 79999_iter.pth 改从 hf-mirror ManyOtherFunctions 仓库下载
5. **numpy ABI 不兼容**：xtcocotools 需要 numpy<2（降级到 1.26.4）
6. **PowerShell 转义**：`$` 变量在 SSH 命令中被展开 → 改用上传脚本文件方式

### 结论

MuseTalk 官方完整推理链路（含 dwpose 人脸检测 + face-parse-bisent 分割 + whisper 音频特征 + UNet 唇同步生成 + ffmpeg 合成）已在远程 32GB vGPU 上全链路验证通过。本地 8GB 显存足够跑核心生成链（5655 MiB），但完整推理需远程或解决 mmpose 兼容性。
