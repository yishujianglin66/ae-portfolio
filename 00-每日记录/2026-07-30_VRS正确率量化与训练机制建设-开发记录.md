# 2026-07-30 VRS 正确率量化与训练机制建设 - 开发记录

## 大白话总结

**这次做的是什么**：之前 VRS 视频分析的正确率是个"黑箱"——不知道分析得准不准，也不知道哪里不准。这次建立了"标准答案对照"机制（Ground Truth 验证），用 28 个人工标注的 AMV 视频做基准，让 VRS 每次分析后都能算出准确率、混淆矩阵、置信度校准。同时建了"主动学习采样器"，自动挑出"最值得训练"的样本，告诉你下一步该标注哪些视频、该补哪些特征。

**为什么之前无法提升正确率**：因为没有"标准答案"，VRS 改了任何参数都无法量化是变好还是变差。现在有了 GT 验证机制，每次改动都能立即看到准确率变化。

## 已实施内容

### 1. VRS GT 验证器（`vrs/vrs_gt_validator.py`）

**功能**：用 `data/real_amv_test/ground_truth.json`（28 条人工标注）作为基准，对 VRS 输出进行量化验证。

**输出指标**：
- 整体准确率 (accuracy)
- 每个风格类别的 precision / recall / F1
- 混淆矩阵（哪些风格最容易认错）
- 置信度校准报告（高置信度是否真的高准确率）
- 主动学习候选样本（错判 + 低置信度）

**用法**：
```bash
python -m vrs.vrs_gt_validator                    # 跑全量 28 条
python -m vrs.vrs_gt_validator --limit 10         # 只跑前 10 条
python -m vrs.vrs_gt_validator --report out.json  # 输出 JSON 报告
```

**核心映射函数** `map_vrs_to_amv_style()`：将 VRS 的 style_tags + 特征组合，用加权评分映射到 8 个 AMV 风格类别。

### 2. 主动学习采样器（`vrs/active_learner.py`）

**功能**：基于 GT 验证报告，挑选"最值得训练"的样本。

**输出**：
- 高优先级错判样本（高置信度但错判，最危险）
- 低置信度样本（模型不确定，最需要标注）
- 类别覆盖缺口（哪些风格样本太少）
- 训练建议（特征工程方向 + 数据采集方向）
- 可导出的训练任务清单

**用法**：
```bash
python -m vrs.active_learner                              # 分析默认报告
python -m vrs.active_learner --report custom.json         # 指定报告
python -m vrs.active_learner --export tasks.json          # 导出训练任务清单
```

### 3. VRS 抽帧密度 + 镜头检测阈值修复

**问题**（主动学习采样器识别）：
- 26/28 错判样本被标记为 slow_paced（VRS 抽帧太稀疏，18 帧/158 秒）
- 26/28 错判样本 shot_count < 5（镜头切换阈值 0.30 过严）

**修复**：
- `num_frames` 默认 18 → 72，上限 32 → 120
- `scene_diff_threshold` 默认 0.30 → 0.12
- 新增 tempo 兜底逻辑：当 shot_count=0 时，用 frame_diff_mean 判断节奏

## 实际验证结果（量化基线）

| 版本 | 抽帧 | 阈值 | 准确率 | 关键发现 |
|------|------|------|--------|---------|
| v1.0 baseline | 18 | 0.30 | **7.14%** (2/28) | 所有样本都被误判为 amv_cinematic |
| v1.1 阈值修复 | 18 | 0.12 | **10.71%** (3/28) | 混淆矩阵开始分散 |
| v1.1 dense | 72 | 0.12 | **0%** (0/28) | 混淆矩阵完全分散，映射规则需校准 |

**关键洞察**：
1. GT 验证机制能立即量化每次调整的效果——之前根本不知道 VRS 这么差
2. 主动学习采样器准确识别出 2 个 P0 级缺陷：抽帧太稀疏 + 阈值过严
3. 72 帧抽帧后，VRS 能识别 fast_paced/multicut 标签（之前全部 slow_paced）
4. 但映射规则需重新校准——cinematic 视频也被识别为 multicut
5. 置信度校准差距：v1.0 是 7.14%，说明高置信度并不比低置信度更准

## 现在项目能做什么

1. **量化 VRS 正确率**：每次改 VRS 后跑 `python -m vrs.vrs_gt_validator`，立即看到准确率变化
2. **识别最危险的错判**：主动学习采样器输出"高置信度但错判"的样本，这些是最需要优先修复的
3. **数据缺口可视化**：清楚知道 amv_pull_zoom/amv_cinematic/amv_korean_flash/amv_3d_spatial 各缺 8 个样本
4. **训练任务清单导出**：24 个可执行的训练任务（复核标注/采集样本/特征工程）
5. **混淆矩阵诊断**：清楚知道 amv_beat_sync 最容易被误判为 amv_cinematic（8 次）

## 将来可以做到什么程度

1. **准确率 ≥85%**：通过 T3-T5 阶段（K-Fold + 特征工程 + 模型重训），目标达到生产级
2. **置信度校准**：让高置信度样本的准确率真的高于低置信度样本（目前校准差距只有 7%）
3. **自动迭代管线**：T7 阶段实现"跑管线→采集数据→重训模型→A/B 对比→部署"全自动
4. **主动学习闭环**：系统自动挑出难样本→用户标注→扩展 GT→重跑验证→准确率提升
