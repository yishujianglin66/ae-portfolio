# 2026-08-27 (三) 运镜标签三角验证 + VLM 专家生产路径接入

## 一、光流物理标注器 v7.1（7 轮迭代，`tmp/_flow_labeler.py`）

为解决"75% 准确率只有 4 条弱真值"问题，建独立于模型的物理标注器。每轮踩一个 AMV 域坑：

| 版本 | 坑 |
|---|---|
| v1 全帧中位流 | 动漫重复帧 90%+（测孪生帧假静止） |
| v2 仿射拟合 | zoom 对称流在中位数自抵消 |
| v3 跳重复帧 | 跨切点帧对乱流（zoom_s=481 垃圾） |
| v4 块中位鲁棒 | 物体/特效淹没全帧拟合（expl≈0） |
| v5 段感知 | 慢推在短窗口低于阈值漏判 |
| v6 长基线 | 首尾跨镜头（diff 大流为零） |
| **v7.1 转场域感知** | **AMV"运镜"活在转场段（静帧原画+滑动/视差转场），镜头内真相机运动≈0** |

**领域实证**（"一个舒服的拉镜"）：镜头内 diff=0.0（比特级静止原画），运动全部集中在
转场段（diff 32.8，双极视差流）——所谓"拉镜"实为 2.5D 滑动转场。
最终分布：tilt-orbit 36 / zoom 10 / static 12（合理）。

## 二、三角验证结论（`tmp/运镜标签三角验证报告.md`）

- VLM(28条) vs 光流物理标签：**总一致 43%，置信子集 41%**
- 主混淆：tilt-orbit↔tilt-orbit 11 条一致（主力区）；tilt-orbit↔zoom 4（"拉镜"命名分歧）；
  static↔tilt-orbit 各 4（"转场算不算运镜"系统性分歧）
- **诚实结论**：两套系统测的不是同一个东西（物理=转场运动类型 / VLM=感知相机行为）；
  真实可靠性区间 40-60%，且 AMV 域"zoom vs tilt-orbit"标签本身有歧义
- **标注规范前置**：扩 50-100 条人工标签前必须先定义"转场算不算运镜"
- CNN 2 分类不受歧义影响（动静二分清晰）

## 三、VLM 专家生产路径接入（`ai/camera_decision.py`）

- `SourceCameraInventory` 新增 **L0.5 分层 CNN+VLM**（LoRA 不可用时的升级路径）：
  CNN 秒级筛动静 → 动作类交 VLM 专家（4bit 5.82GB）
- 3 类→fine 词表映射：zoom→zoom_in / tilt-orbit→orbit / static→static
- confidence + coarse + description 透传下游；磁盘缓存复用 L1 键
- 开关：`AEKV_HIER_CAM=0` 关闭；`AEKV_NO_LORA=1` 测试跳 LoRA

**E2E 真机验证（venv, 4bit）**：
- 动作路径：`BV1os411Z7jg` → orbit / tilt-orbit / conf 0.792 / hier_vlm + 自然语言描述 ✅
- 静态纠偏路径：`BV1DdrdB2Ev5` → CNN 误报 motion → VLM 纠回 static / conf 0.693（57.6s）✅
  （分层架构价值实证：VLM 兜住 CNN 误报）

**环境坑**：系统 python 与 py3.12 均无 bitsandbytes；**4bit 只在项目 `.venv`**
（bnb 0.50.1 + torch 2.13）——生产调用必须走 `.venv/Scripts/python.exe`，
否则降级链 bf16→offload→段错误。GPU 残留进程（如 Silhouette.exe）会占满 8GB 致 OOM。
