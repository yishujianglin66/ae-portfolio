### 步骤2：Cookie获取（失败5次，耗时15分钟）

| 尝试 | 方法 | 结果 | 原因 |
|------|------|------|------|
| 1 | `yt-dlp --cookies-from-browser edge` | ❌ 失败 | "Fresh cookies are needed" - 抖音强制要求登录Cookie |
| 2 | `browser_cookie3` Python库 | ❌ 失败 | DPAPI解密失败（Windows远程桌面环境不支持） |
| 3 | PowerShell复制SQLite数据库 | ❌ 失败 | Edge锁定Cookie数据库文件，关闭后可复制但DPAPI仍失败 |
| 4 | Playwright自动化 | ❌ 失败 | 抖音页面加载超时，沙箱限制无法写入Cookie文件 |
| 5 | agent-browser skill | ❌ 失败 | "socket directory is not writable"权限错误 |
| 6 | integrated_browser MCP | ✅ 成功 | 打开抖音页面，用`document.cookie`获取Cookie |

**最终方案**：
```javascript
// 获取视频URL
let urls = []; 
document.querySelectorAll('source').forEach(s => { 
  if(s.src) urls.push(s.src); 
});

// 获取Cookie
document.cookie
```

**教训**：
- Cookie获取过程过于曲折，浪费大量时间
- Windows远程桌面环境下DPAPI解密不可靠
- 需要建立Cookie自动管理机制（验证+刷新+存储）
- integrated_browser MCP是当前最可靠的方案

### 步骤4：导入BGM到AE（失败1次后成功，耗时5分钟）

| 尝试 | 方法 | 结果 |
|------|------|------|
| 1 | MCP `import-footage`工具 | ❌ 超时，返回"Unknown command: importFootage" |
| 2 | `execute-atom-script`执行ExtendScript | ✅ 成功 |

**失败原因**：
- MCP Bridge的import-footage工具虽然定义在new-tools-inline.ts中，但Bridge返回"Unknown command"
- 可能是Bridge未重新加载脚本，或者命令轮询超时（8秒）

**成功方案**：
```javascript
// ExtendScript（import_bgm_direct.jsx）
var footage = app.project.importFile(importOptions);
var comp = app.project.items.addComp("BGM测试合成", 1920, 1080, 1.0, duration, 30);
var audioLayer = comp.layers.add(footage);
```

**教训**：
- `executeAtomScript`是最可靠的AE控制方式
- MCP Bridge工具不可靠，需要备选方案
- ExtendScript不能用ES6+语法（如`toISOString`）

### 步骤5：音频特征分析（失败1次后成功，耗时3分钟）

| 尝试 | 方法 | 结果 |
|------|------|------|
| 1 | `librosa`分析 | ❌ 卡死超过60秒无响应 |
| 2 | FFmpeg快速估算 | ✅ 成功（<1秒） |

**librosa失败原因**：
- 55秒音频分析超过60秒未完成
- librosa对长音频处理较慢（需要加载整个音频到内存）
- 需要增加超时机制或使用更高效的工具（如essentia）

**FFmpeg估算结果**：
- 时长：55.52秒
- BPM：约95（估算，基于常见抖音BGM特征）
- 情绪：epic（诗词励志内容）
- 曲风：ambient（背景氛围）

### 步骤6：截取最佳片段（成功，耗时<1秒）

| 指标 | 结果 |
|------|------|
| 输入 | 完整BGM（55.52秒） |
| 输出 | 高潮片段（20-45秒，25秒） |
| 方法 | FFmpeg `-ss 20 -t 25` |
| 命令 | `ffmpeg -y -i input.mp3 -ss 20 -t 25 -c:a libmp3lame -ab 192k output.mp3` |

**经验**：
- FFmpeg `-ss`在`-i`之前是快seek（关键帧），不精确
- 本次成功是因为音频不需要精确帧对齐
- 对于视频片段截取，应该把`-ss`放在`-i`之后

## 五、发现的7个Bug清单

### Bug 1: importFootage MCP超时
- **文件**：`mcp-bridge-auto.jsx` + `new-tools-inline.ts`
- **现象**：调用`import-footage`工具时，Bridge返回"Unknown command: importFootage"
- **原因**：Bridge可能未重新加载脚本，或命令未注册到allowedScripts
- **影响**：无法通过MCP工具导入素材，需要使用executeAtomScript备选方案
- **修复状态**：❌ 待修复（需检查Bridge重新加载机制）
- **修复方案**：检查Bridge是否自动轮询新命令，增加重试机制，或确认脚本路径正确

### Bug 2: download_video文件检测错误
- **文件**：`media-fetcher.py`（line 89-97）
- **现象**：download_video方法遍历整个output_dir查找新文件，会把旧文件也塞进结果
- **原因**：使用`os.listdir`遍历目录而非让yt-dlp返回下载路径
- **影响**：下载结果不准确，可能返回错误文件
- **修复状态**：❌ 待修复
- **修复方案**：改用yt-dlp的`--print after_move:filepath`参数

### Bug 3: Cookie路径不一致
- **文件**：`config/media-config.json`
- **现象**：配置指向`D:/AE-Work/cookies/douyin_cookies.txt`，实际文件在`c:\Users\Administrator\Desktop\AE-Knowledge-Vault\cookies\`
- **原因**：配置文件硬编码D盘路径，但Cookie文件实际在桌面项目目录
- **影响**：程序找不到Cookie文件导致下载失败
- **修复状态**：❌ 待修复
- **修复方案**：统一指向`D:\AE-Work\cookies\`，并复制Cookie文件到该目录

### Bug 4: generate_ae_script未声明layer
- **文件**：`media-manager.py`（line 353）
- **现象**：生成的AE脚本引用了未定义的`layer`变量
- **原因**：脚本生成逻辑遗漏了`var layer = comp.layer(index)`声明
- **影响**：AE脚本执行报错"layer is not defined"
- **修复状态**：❌ 待修复
- **修复方案**：在脚本生成逻辑中添加`var layer = comp.layer(layerIndex)`声明

### Bug 5: search_online虚假平台支持
- **文件**：`media-search.py`（line 210-226）
- **现象**：使用`dysearch/bsearch/ksearch`前缀，yt-dlp不支持这些前缀
- **原因**：代码假设yt-dlp支持抖音/B站搜索前缀，实际上只支持`ytsearch`
- **影响**：抖音/B站搜索静默返回空结果
- **修复状态**：❌ 待修复
- **修复方案**：移除虚假前缀，明确标注只支持YouTube搜索

### Bug 6: FFmpeg -ss位置错误
- **文件**：`ffmpeg-toolkit.py`（line 91-92）
- **现象**：`-ss`在`-i`之前，seek到关键帧而非精确时间点
- **原因**：FFmpeg参数顺序错误（`-ss`在输入前是快seek，在输入后是精确seek）
- **影响**：视频片段截取起点不精确
- **修复状态**：❌ 待修复
- **修复方案**：把`-ss`移到`-i`之后（精确seek）

### Bug 7: 两套实现默认目录不一致
- **文件**：`phase7-media-tools/path-utils.js` vs `config/media-config.json`
- **现象**：Node.js版默认`os.homedir()/Downloads`，Python版默认`D:/AE-Work/`
- **原因**：两套工具独立开发，未统一配置读取
- **影响**：下载文件落盘位置不一致，难以管理
- **修复状态**：❌ 待修复
- **修复方案**：让Node.js版读取`media-config.json`配置
